# Denim R02 — yarn-authored cloth candidate

R01 is frozen at `f64eb3aaaedec738ae3d73661ea967713ede8e39`. Its surface shader was **not** an explicit yarn model. R02 adds an independent yarn-authoring kernel rather than relabeling a magnified texture.

## What changed

- A binary weave draft generates continuous, stable-ID warp/weft centerlines in millimeters. Default specimen: 238 warp + 112 weft yarns; 26,656 intersections. Pitches are 0.42 / 0.64 mm (about 60 / 40 per inch), a visual candidate informed by CottonWorks' construction ranges, not a measured sample.
- Swept elliptical yarn surfaces, closed cut ends, and 2,100 sparse cut-edge fiber curves. The thickness control changes both yarn cross-sections and crossing separation. The 0.70 mm setting is a nominal envelope, not a caliper measurement. Slub locally varies that envelope.
- Four weave drafts, six finishing candidates, front/back views, continuous rolled edge, folded/hanging carriers, separate geometric topstitch samples. Carrier deformation is art-directed, not cloth physics. Topstitches are not a complete lockstitch construction.
- Indigo warp and natural weft are distinct materials. Wash, crown abrasion, and backstaining are separate controls. These are appearance approximations, NOT Jeanologia machine recipes or chemical kinetics.
- Close inspection uses explicit swept yarns. At smaller pixel footprints, albedo and normal captures of the same generated full swatch are mip-filtered with anisotropic sampling. Transition shading is blended before geometry LOD switches. No imported photograph or generated image replaces the yarn structure.
- Analytic carrier derivatives, instanced shared meshes, a bounded supersample target, event-driven idle rendering, lower mobile capture resolution, and pixel-coverage-aware cut fibers control cost. Ordinary view is roughly 81k rendered triangles including edge fibers/stitches; close yarn view is several million. Actual hardware frame rate remains unverified.

## Internal structural verification

`node test-core.cjs` checks every crossing in all four drafts, continuity, dimensions, thickness changes, and rejected invalid inputs.

`window.__DENIM_WORKBENCH__.auditGPU()` temporarily renders actual depth-tested yarn family IDs and reads the **rendered** family at every crossing center. It is internal QA, not a microscopy UI. Crossing-center checks are not proof of globally collision-free surfaces, yarn packing, or cloth self-collision.

`qa.mjs` tests the actual local `file://` entry, fixed HTTPS entry, material changes in canvas pixels, all weave controls, front/back, roll, thickness, export, close/far LOD, idle stop, GL errors, and a 390×844 mobile viewport. This is not a phone hardware test. Evidence lives in Actions; do not infer visual approval from passing automation.

## Files and recovery

Edit `core.js`, `app.js`, and `template.html`; run `python3 build.py` to assemble the standalone `index.html`. `_bundle/part*.txt` and `unpack.py` preserve the exact submitted authoring source for reproducible bootstrap. No runtime CDN, external texture, model, font, or decoder dependency. Source generation never touches R01 or another workbench.

Export: `kaopu.denim_material_profile@2.0`. Units are explicit millimeters. Existing R01 profiles remain separate; no shared consumer is silently migrated.

## Remaining boundaries
