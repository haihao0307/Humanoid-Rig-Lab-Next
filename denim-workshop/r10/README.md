## 实际实现

1. `distance-lod.js` 以最终输出像素中的纱距驱动中景到近景的连续权重，默认约2.8到7像素；近景细毛羽在约4到9像素范围连续显露。不是按固定世界距离生硬换对象，也不是所有屏幕/相机下使用同一米数。
2. 保留近景实体纱线和原短棉纤维；中远景使用同一 YarnGraph 捕获的颜色、覆盖率、加权法线信息。捕获目标加入4×MSAA，法线按覆盖和相干程度处理，不把过滤后趋近零的向量重新归一化成锐利高光。线性色彩在最终像素积分之后只做一次色调映射。
3. 过渡区同时计算两种表达，在同一帧线性混合。变形布面的局部导数修正斜视区域的过渡权重，复用过渡纹理的alpha通道，不增加另一份全屏蒙版。没有时域历史、随机抽稀、噪声抖动或残影来掩盖闪烁。
4. 中远景破口、边缘、松散纱线与针脚保留可分辨路径，并用像素覆盖曲线表示小直径线，而不是依靠亚像素硬圆管。中远景动态阴影由同一物理布面和破口覆盖生成，避免继续使用极密纱体的闪烁阴影；近景仍使用详细阴影。粗阴影是明确的尺度近似，不是完全一致的离线光传输。
5. 主体表面/外层细纤维从常驻数据中拆出。进入近景预加载区域时，在独立短生命周期Worker中按原种子和父纱线生成，传回紧凑Float32控制点；生成完成再连续显露。离开可分辨范围约0.9秒后释放对应GPU对象，高精度截面模板也按需创建/释放。加载和卸载阈值分离，防止轻微推拉反复抖动。返回近景重建的控制点应字节一致。
6. R09.1 `dynamics.js` 原文件逐字节保留。距离变化只改变显示和资源驻留，不重置、删减或停掉475节点布样求解。风吹、惯性、锚点、针脚和阴影仍读取同一物理位移。

## 按需加载的确切范围

当前是整块布样的“微观纤维层”按需生成、驻留与释放，不是网络下载模型，不是每块局部的虚拟几何分页，也不是已经支持大量整衣的调度系统。边缘/破口/针脚和基础生成函数常驻，较远距离仍保持可交互三维及物理。文件核心不依赖外部运行资源，运行中的Blob Worker源码封装在单体HTML内。

## 资源代价与未验证项

微层离远后释放约数十MiB，只有实测后才能报告具体比例。过渡区双路绘制有额外显存和带宽成本；更好的覆盖捕获增加一次性生成成本，不是所有距离都更省。基础高密度纱体、近景缝线/松散纱线模板等仍有常驻数据，未做到最小内存。保真屏幕目标本身也是很大一项开销，不能只看几十KB的HTML断言整个系统极轻。

软件Chromium不是用户实机的显卡占用或FPS，390×844只是视口模拟。LOD视觉过滤不能让低分辨率屏幕同时保持不可分辨的逐根细丝；目标是保持正确的整体颜色、织纹层次、轮廓与运动，不是在远景强行保留闪烁细节。

继承的布样物理仍没有整衣蒙皮/人物动作正式接入、自碰撞、CCD、受力撕裂、真实针孔与线张力，以及所有可见纤维不穿透的证明。近景用户批准仍以用户实际观察为准。
