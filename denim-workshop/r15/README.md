# Denim R15 — live physics performance, 60 FPS target not certified

用户要求开启物理时全面优化，至少60帧。父版固定R14构建5ebe0c034d3a345067929c6034d53eb615b39d21，源码/回执头9d5437755d69c8a86557b10cbfcf12dbb84812ed。本轮只新增r15及专用CI，旧目录、档案、main、其他工作台与根许可证不改；Draft，不合并、不强推。撕裂仍暂停，人物整衣不接。

## 真实修改

连续整片折叠的计算热点移入本项目可读C实现，编译为内联WASM双精度内核。保留637点、240Hz固定子步、12+16轮投影、厚度、面密度、曲率半径保护、桌面/布面接触、摩擦与夹具。空间哈希的候选与约束执行顺序保留；不是减少节点/迭代/接触检查。固定类型数组、同一子步内融合执行，缓存不变系数，减少临时分配。容量溢出明确报错，不删碰撞。原bend-cloth.js保留作独立参考，原材质模式的Cloth没有换成折叠模型。

渲染端复用Hermite位置/导数的同一组取数，缓存不变uniform，取消60Hz调度前多余的定时休眠；GPU分批大小依据完成时间调整，仍保留fence背压和看门狗。保留原几何、纱线数量、近远细节阈值、分辨率/抗锯齿、阴影与灯光。折叠模式沿用R14已有的显式节能档，不将其称为新增无损优化。传输保留命令/采样序号与过期数据保护，省掉折叠模式中已知为零的旧网格计算。

## 可操作的测量

“运行30秒真实运动检查”持续改变边缘夹具目标，物理、碰撞、质量、时间不断续运行；不是重播缓存动画。“导出本机帧时间报告”保存帧记录、物理更新率、仿真速度、P95帧间隔及当次浏览器/画布/renderer条件；不上传用户设备数据。

完成绘制FPS按完整画面fence被JS观测到完成计数，不把rAF空回调或未完成的分批绘制计入。独立物理状态更新率与仿真秒/墙钟秒分开报告。GPU完成被观察不等于显示器/合成器实测，不能凭一个峰值或按钮写着60就宣称合格。

## 测试与构建

首次hydrate.py核对源包/父版摘要，展开本项目的增量并生成规范可读文件。以后从规范C/JS改代码，compile-kernel.py和build.py构建，不覆盖重跑hydrate。源码包不是闭源实现，CI会在公网验证前提交全部可读代码、WASM和HTML。

compile-kernel.py使用clang/wasm-ld，禁止fast-math，无SIMD硬件要求。输入C和适配器摘要固定；不同编译器可能生成不同WASM，最终采用CI完整数值/网页验证过的二进制。最终BUILD_MANIFEST记录实际公开字节，不能用本地另一编译器摘要冒充。

14项原R14质量门禁在加速模型重新运行。test-performance.cjs三档厚度逐步对照原JS的完整720步，独立检查位置/质量/时间/接触和报告，不仅比较最终图片。本地初测约6.2—6.4倍求解速度，位置差低于1e-9米的预设门槛；这是Node求解计时，不是整页帧率。正式数值以本目录PERFORMANCE_NUMERIC.json为准。

qa-performance.py实际进入file://和固定公网，检查同姿态原材质/折叠画面、镜头不重置物理、边缘释放、持续运动、复位、测量与报告按钮和390×844视口。--content只属开发检查，不冒称file/public。手机视口不等于真机；软件SwiftShader不等于消费显卡性能。

## 未完成与成本

60FPS整页验收尚未通过。本地软件浏览器整体仍远低于60；不能把求解加速倍数换算成FPS提升倍数。缺少在声明硬件、分辨率、刷新率、画质与持续时间上的完整60帧实测。用户机器的实际运行报告可提供下一步定向瓶颈证据，而不是保证它自动达标。

新增WASM线性内存约7MiB，此外还有JS/驱动开销，不把120KB级HTML当作运行内存。仍是固定整片布样，不是通用成衣；保留R14未实测材料/半径参数、不完整CCD、无逐纤维碰撞等限制。视觉与实机验收仍待完成，基线对照容差不是任何角度无损的证明。
