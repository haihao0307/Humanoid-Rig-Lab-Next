# 人物自然转向 R27

日期：2026-09-30  
分支：`feature/human-natural-turn-r27-20260930`

## 结论

旧转向不能通过“降低角速度”或“加一个缓动”解决。旧实现的核心问题是：

1. 转向期间仍然采样直线步行的上身动作；
2. 脚步始终使用固定 0.36 秒、固定最高约 65 mm 的同一种摆动；
3. 骨盆接近支撑脚扭转上限时会把根节点角速度硬置零，等待下一次换脚；
4. 头、胸、腰和骨盆没有转向专用的时序；
5. 原测试明确要求出现支撑等待帧，因此“测试通过”并不代表转向流畅；
6. 没有真实浏览器视频可以证明当前画面自然。

R27 不改写锁定的 `motion/vendor/*`，而是在现有 Motion-Lab 外层加入可随人物比例和持物状态重新计算的转向适配层。

## 生物运动约束

R27 采用以下约束，而不是把身体当成一块刚体旋转：

- 原地转向时，头、肩和骨盆会开始重新定向，头部更快并更早达到峰值，之后才发生脚步置换；
- 行走中的预先计划转向通常呈头→肩→骨盆→脚部置换的由上而下时序；
- 改变行进方向之前存在预期性的重心和身体配置调整；
- 默认使用稳定的跨步转向，不默认采用支撑面更小、稳定性更差的旋转式转向；
- 大角度转向需要更多步，并降低角速度；
- 持物时使用更小的单步角度、更慢的根节点转速和更低的抬脚高度。

当前常数是以这些规律约束后的作者参数，不是针对某位真人的临床或测力平台标定。

## R27 实现

### 1. 稳定跨步策略

按目标角度规划步数：

- 很小角度允许在双脚支撑范围内完成；
- 中等角度使用稳定跨步转向；
- 大角度使用多步转向；
- 首步偏向转向外侧脚，随后左右交替；
- 最后一轮补齐双脚朝向和标准站距；
- 禁止交叉式 spin turn 作为默认行为。

### 2. 去除固定机械脚步

每一步根据实际需要旋转的角度计算：

- 摆动时长；
- 抬脚高度；
- 落脚朝向；
- 落脚位置；
- 是否属于最终纠正步。

水平轨迹和足部朝向采用五次最小跃度曲线，抬脚曲线在起点和终点速度为零。摆脚期间加入很小的足背屈，而不是始终保持整只脚水平。

### 3. 提前换脚，减少硬停顿

旧内核在支撑脚扭转达到上限时直接停止根节点旋转。R27 在扭转达到该硬阈值之前启动下一步，并降低转向角速度，使根节点不再频繁出现“转一下—停住—换脚—再转”的机械节奏。

### 4. 头、胸、腰、骨盆分段转向

转向开始后：

- 头部最快；
- 胸廓随后；
- 腰椎只承担小幅过渡；
- 骨盆由真实落脚和根节点方向共同推进；
- 转向结束后，各轴向段在约 0.34 秒内回到中性相对关系，避免结束瞬间弹回。

### 5. 支撑侧重心转移

摆脚时骨盆向支撑脚移动不超过约 9 mm，并有不超过约 4 mm 的轻微下沉。持物时横向幅度更小，以保护双手物体接触。该层是运动学代理，不是完整重心、ZMP 或地面反作用力求解。

### 6. 上身动作去直线步行化

原系统在原地转向时仍会把直线步行的摆臂采样混进上身。R27 在没有持物和手部约束时大幅衰减该摆臂，只保留少量自然反摆。持物时由原有手掌接触目标继续拥有手臂控制权。

## 自动验收矩阵

`tools/test-turn-command-continuity.mjs` 已改为检查完整 R27，而不是只检查角速度：

- 左右 15°、30°、45°、90°、135°、180°；
- 空手与持物两种速度配置；
- 支撑脚落地期间位置必须锁定；
- 最终朝向误差小于既有阈值；
- 步数不能无限增长；
- 未完成转向期间连续硬停顿必须小于 0.24 秒；
- 头部不能在转向初期落后于胸廓；
- 胸廓不能退化成与骨盆完全整块旋转；
- 根节点角加速度必须有界。

该测试仍属于 Node 级运动学检查，不能替代视觉验收。

## 真实浏览器验收

`tools/natural_turn_visual_qa.py` 只运行转向：

- 左右 15°；
- 左右 45°；
- 左右 90°；
- 左右 180°；
- 正面、侧面和背面；
- 每个场景保留中途帧、结束帧和视频。

重点观察：

1. 头部是否轻微先行但不过度拧颈；
2. 胸和骨盆是否有连续层次；
3. 是否还出现明显硬停顿；
4. 首步是否稳定，没有脚交叉；
5. 摆脚是否有合适的抬脚与足背屈；
6. 支撑脚是否滑动；
7. 90°、180° 是否用合理步数完成；
8. 转向结束是否平稳回到站姿；
9. 左右方向是否对称；
10. 肩、胯、膝和踝是否出现新的表面问题。

只有同时满足以下条件才允许合入人物生产分支：

1. Node 转向矩阵全部通过；
2. 生成入口与源码一致；
3. Chrome/WebGL2 真实浏览器运行成功；
4. 视频中没有明显硬停顿、支撑脚滑动或整块旋转；
5. 左右 90° 和 180° 均通过人工视觉检查；
6. 新人物接入后重新运行，不把旧 R2 结果直接视为新人物结果。
