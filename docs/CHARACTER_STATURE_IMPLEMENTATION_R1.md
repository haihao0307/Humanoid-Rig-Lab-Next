# 人物母体第一阶段：个人体型与三种身高

## 当前实施范围

本阶段接通研究方案中的 P0 与 P1：版本化体型参数、个人骨架、受限整体身高变化、曲面与毛发尺寸、接触和动作适配，以及完整人物的暂存替换。新增“较矮／参考／较高”三份身高预设，也可在允许范围内输入身高。

这是整体等比例身材，`statureScale` 范围为 0.94 至 1.06。范围属于本项目的首批创作约束，没有人口统计或医学标定含义；尚未接通腿身比、肩宽、胖瘦或新的脸型身份。现有皮肤、毛发、面部微控和表情继续保留。

本轮只装配与审查文件，不运行页面、Worker、人体生成、动作或 GPU。代码接通不等于站姿、落脚、身材观感或性能已经验收。新体型配方继续标为 Candidate，`runtimeVerified=false`、`visualAcceptance=false`、`productionReady=false`。

## 使用入口

用户自行启动当前项目后，进入 **人物设置 → 体型与身高**。先选择较矮、参考或较高，也可输入厘米数，再按“应用身高”。只有站立、收脚完成、没有任务或持物时允许改变身体尺寸；更换过程中继续显示旧人物。

**人物设置 → 角色与任务定义** 同时提供三份身高预设。调整当前人物身高会保留其皮肤、毛发、面部、任务配置与能力定义；选择完整角色预设则使用该预设的其他字段。角色导出与人物 DNA 导出包含体型，导入可以重建相同定义。

角色配方升级为 `jarvis/character_preset@5`，兼容旧 `@3` 和 `@4`。旧配方没有 `shape` 时采用参考身高；`statureM` 为派生读数，不是第二个可以独立写入的身高来源。若它与 `shape.statureScale` 不一致，导入明确报错。

```json
{
  "schema": "jarvis/human_shape@1",
  "revision": "r2-uniform-stature-r1",
  "statureScale": 1.06
}
```

上面是 `character.shape` 字段示例，不是独立完整 NPC 文件。角色 API 和 Worker 都拒绝未知形体字段、错误版本、null、非有限数与范围外比例。随机派生保留已选体型，不在未声明的情况下重新抽取身高。

## 数据与生成关系

`body/CharacterShape.js` 验证体型并从只读 `R2_RIG` 深拷贝个人参考。节点位置、末端位置、拟合半径和参考地面按同一比例变化。原数据及来源残差仍作为来源证据，不把缩放结果称为新测量。每个 Human 持有 `resolvedRig`、`bodyMetrics`、`canonicalSourceBind` 和个人 `sourceBind`。

个人尺寸包括骨段长度、站姿间距、髋高、脚底高度和手掌接触偏移。几何键包含完整来源 SHA、装配生成器版本、体型方法版本和完整比例值，避免不同身高共用旧的固定来源键。角色身份、实例状态和几何可复用身份继续分开。

曲面与权重先在未缩放的参考空间生成。`compactSourceRig` 明确提供该参考坐标；Worker 在共享拓扑、绑定、支撑点筛选完成后，通过 `applyCompactStature` 同步变换曲面解码尺寸和支撑点。权重索引、八项整数权重与法线方向保留，骨架的姿态变换则从个人中立骨架计算。

此做法只对当前整体正比例缩放成立。局部肩宽、腿身比或胖瘦变化不能直接复用这一结论，后续必须重新设计曲面求值、误差评估、个人骨架和绑定关系。

## 表面、脸部与毛发

GPU 中先恢复未缩放参考坐标，用于肤色、眼睛、稳定皮肤细节和面部控制，再把位置送入个人尺度和 DQS。皮肤拉伸估算的参考面积乘比例平方，避免身高本身被当成皮肤拉伸。

面部微控仍以真实毫米表达。上传前把位移换算到参考空间，显示时再恢复个人尺寸；0.5 mm 的局部操作不会因为身高增加而自动变大。面部覆盖采样在参考坐标求权重，距离读数按个人尺度表达。脸型身份参数的独立体系仍是后续工作。

毛发继续保存参考函数与临时参考坐标缓冲。发丝、底层覆盖、发宽和 LOD 距离依据个人比例显示，发际线遮罩与程序纹理仍在原有参考坐标计算。独立毛发请求、身体请求和渲染器都核对同一份体型，防止旧毛发结果被交给新身高人物。

## 动作、接触与场景

`MotionLabPose`、`NaturalLocomotion`、`ReferenceMotion`、`StandardsMotion` 读取个人骨架与尺寸。动作过程中保持当前个人骨长，不向双四元数调色板引入骨骼缩放。骨长误差与手脚目标误差原有上限没有为新身高放宽。

坐卧、下蹲接触、敬礼、搬运和推动同时更新预检与执行的尺寸来源。下蹲候选使用按 Human 分离的 WeakMap 缓存，避免更换身高后沿用上一人的手臂可达范围。预测报告只保存可序列化参数，实时 Human 通过私有关联传递，不进入导出的状态。

人体净空、抓握跨度、携物包络和出生位置检查使用个人几何配置。场景物体尺寸、地面和世界接触目标保持场景坐标。替换时若当前位置无法容纳新人物，保留旧人物并要求先移动到空旷处。

力量配置、肌量、体重及来源动作核中的速度和步幅参数没有因为身高自动增加。动作核心仍为来源锁定的 Motion-Lab，传入个人骨架不代表所有步幅、动作范围和体型组合都已验证。后续需分别研究身体能力参数和动作风格。

## 人物替换与并发

`CharacterAssembly.js` 准备新 Human、个人曲面、绑定、毛发、身体状态与 Agent。仅在当前人物定义、世界版本、站立条件和资源状态仍符合要求时，由 `commitCharacterRuntime` 同步更新内部变量与公开 HumanLab 引用，再释放旧资源。

暂存 Agent 使用原位置与朝向，跳过普通重置的世界物理同步和约束清理；新人物未提交前不重置共享场景。提交同时兼容渲染器中的人物数组，替换当前人物并保留其他实例。失败资源的清理不清空活动人物的绘制缓存。

构建期间活动视图显示编辑状态，新任务与场景编辑被阻止。其他外观修改若使人物定义变化，旧请求不得覆盖新定义。细节与毛发的异步结果同时检查发起时的表皮实例，避免跨人物提交。

换身高保留世界、人物的平面位置和朝向以及模拟时间，恢复为新身高的站姿。它不是动作存档恢复，也不表示生长模拟。暂存期间新旧 GPU 资源并存，会增加短时内存，实际峰值尚未测量。

人物替换后重新绑定关节观察、骨架契约和任务完成反馈；父页面刷新能力、物理配置与身体证据，废弃基于旧体型的待确认推演。此事件不会触发场景自动存档恢复。

## 精度与证据

原始采样误差与长度阈值继续保留在参考空间；新报告另列乘身高比例后的派生长度误差。有限采样误差不是完整曲面误差证明，显示变换的浮点舍入也没有被包含在全局证书中。本阶段没有把原容差原封不动地标到放大后的人物上。

`tools/check-character-shape.mjs` 仅解析源码与字面配方，检查页面和 Worker 参数域一致、版本迁移、个人参考、绑定后缩放、动作预检传参、面部与毛发坐标和导出状态。总检查还保留曲面系数、Motion-Lab 文件哈希、原有动作和资源所有权约束。

2026-09-12 本次文件检查快照：`build-pure.mjs` 装配成功，`check-pure.mjs` 全部通过，体型专项 80 项通过；`audit-files.py` 已更新 207 个文件的校验记录，并完成 7 个 Python 文件的语法解析。入口与源码一致，未声明标识符为 0。结果见项目根目录 `FILE_AUDIT.json` 与 `SHA256SUMS.txt`；这是共享工作区当次文件快照，不是运行或视觉验收。

运行验收仍需覆盖三个身高的站立、走停、转向、坐起、敬礼和持物，检查肩腋、腕部、脚底、发际线与面部偏移。另需验证取消、旧请求返回、资源分配失败及重复切换。当前文件审查无法给出这些结果。

## 后续优先级

1. 在允许的验证范围内审查并完善本次身高链路；实际动作和视觉由后续运行证据决定接受状态。
2. 增加独立腿身比和肩宽的函数变形，重新处理关节和曲面约束，不把整体缩放方案扩写为任意局部缩放。
3. 加入躯干与肢体丰满度、脸型身份，保留现有表情状态分层。
4. 将性格偏好接入已有日常候选排序及受限表达通道。
5. 与并行的多人板块继续对齐个人几何键、状态隔离、资源复用与预算。多人实例管理由该板块实施，本轮负责形体链路及人物替换兼容。

## 研究依据

- Loper 等，2015，[SMPL 作者资料](https://smpl.is.tuebingen.mpg.de/)：形体变化、关节位置和姿态应共同组织。这里借鉴分层，不引入其模型或训练数据。
- Kavan 等，2008，[双四元数蒙皮说明](https://users.cs.utah.edu/~ladislav/dq/index.html)：缩放和剪切需额外处理。本阶段在个人中立形体中建立尺寸，姿态阶段保留刚体 DQS。
- [人物母体研究报告](CHARACTER_MOTHER_SYSTEM_RESEARCH_R1.md)：P0/P1 实施顺序、资产约束、各板块接口与后续边界。
