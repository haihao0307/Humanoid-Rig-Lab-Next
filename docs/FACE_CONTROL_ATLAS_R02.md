## 坐标与证据边界

参考坐标使用米、Y 向上、Z 向前，参考值来自仓库 R2 人脸框架。已存在的 21 个参考标志点可作为低频结构拟合的锚点；眼部中心和耳部局部锚点在 R2 标志点层并未完整定义，因此本原型中的相应中心是候选推断值，必须在真实导入网格上校准。

当前覆盖核是有界椭球核的研究性候选，不等同于真实解剖分割。导入 GLB 的坐标轴、原点、比例、变换层级若与 R2 参考系不同，覆盖率会失真；界面已明确提示先校准坐标。浏览器页面源码已从 GitHub 原始文件回读核对；尚未在目标浏览器完成完整视觉 QA，也尚未有用户导出的生产人物 GLB 在本轮完成导入测试。

## 关键设计结论

1. 面部语义区不是一对一骨骼。眼球适合独立旋转控制；眼睑需要曲线/区域变形并受眼球接触约束；下颌可使用局部关节表现；脸颊、额部、鼻翼、唇部应使用局部形变目标或 GPU 区域场。
2. 稳定身份结构、人工中性残差、临时表情继续遵循现有 `FaceControls.js` 分层，不创建第二套脸型身份数据。
3. 应将新区域映射作为 Performance Deform 层的语义索引，读取现有头部最终姿势矩阵；不能改写 Core Rig 的父子关系或骨长。
4. 当前自动采样不是自动识别。下一步必须以真实人物导出网格实测坐标校准、区域覆盖与冲突，再决定是否将 FaceRegionMap 纳入生产 schema。

## 下一步验收门槛

- 使用当前人物系统生成并导出的头部/全身 GLB 实测，不用示意头替代。
- 确认 GLB 的单位、原点、朝向和头部参考坐标，必要时先做刚体/尺度配准。
- 在正面、侧面、3/4 视角检查区域覆盖；分别核对眼睑、鼻翼、唇缘、下颌边界。
- 输出每个顶点的多区域权重，检查归一化、重叠冲突、无覆盖、区域边缘连续性。
- 与现有 GPU 形变核保持一致，并测量静止、表情、连续动作时的帧率与内存。
- 所有正式绑定修改先以候选版本保存，保留回滚，不覆盖原始 GLB 或旧 FaceRecipe。
