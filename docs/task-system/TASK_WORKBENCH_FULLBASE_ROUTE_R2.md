## 2. 仍然存在的三个实际问题

### 2.1 任务接收者存在双重语义

人口面板同时存在“人物勾选”和“任务对象：已选人物/全体人物”；主语义任务窗口又主要绑定当前人物。用户看到的人物选择、当前人物和最终任务接收者并非始终是同一个概念，容易发生勾选一人但任务仍发给全体，或主窗口只控制当前人物的情况。

### 2.2 动态交通原先只有停车检查

旧交通逻辑主要检查下一个路线点是否被其他人物占用，然后停车并定期检查。连续扫掠在路段中间检测到人物时，底层仍可能进入 blocked/fault；场景物体移动后切断旧路线，也可能让人物停留或直接失败。

本轮已经取消自动停车等待，将其替换为路线段预测、确定性侧移、局部绕行、物体变化后的重新规划和狭窄情况下的主动后撤。

### 2.3 同一目标、工作位和狭窄通道没有预约

多个人物仍可能前往同一目标点。工作位、接近位、机动集结位和通道先后顺序没有统一所有权，容易形成重叠或双向堵塞。

## 3. 高效三阶段路线

### 阶段一：统一任务接收者

- 人物勾选集合成为多人任务的唯一接收者来源。
- “当前人物”只决定编辑与观察对象，不再暗中代表任务范围。
- 全体任务通过“全选”明确形成，不再保留容易误解的第二套范围状态。
- 主任务窗口逐步接入同一人物选择快照；派单结果逐人返回，不因一人拒绝而回滚其他已接收者。
- 保留现有 `NPCPopulation` 队列与 `Agent`，不另建平行调度内核。

验收：只勾选一人时只有该人收到任务；多选时每个人保持自己的队列、暂停与失败状态。

### 阶段二：预测、偏移与局部绕行

- 预测未来短时间内自身沿路线和附近 NPC 的运动位置。
- 同一对 NPC 使用稳定、对称的左右侧规则，不使用随机方向。
- 生成局部进入点和越过点，连续扫掠通过后写入当前路线。
- 原目标保持不变；越过冲突区后并回原路线。
- 场景物体移动并切断路线时，立即根据当前几何重算路线。
- 侧向空间不足时，按稳定优先级让一方主动后撤到安全点，而不是原地停车。
- 不采用每帧完整 A*；只在路线失效或恢复导航阻断时重算。
- 只有当前地图和局部净空都确认无解时才明确失败，不无限等待。

验收：两人迎面和四人交叉不会因一次碰撞预测突然终止；移动物体切断旧路线时能够重新绕行；交通状态中不再存在自动停车等待计时器。

### 阶段三：站位预约与死锁恢复

- 目标生成 `approach`、`interact`、`staging`、`exit` 候选位。
- 同一工作位只允许一个人物持有交互预约，其他人物分配不同接近位、机动集结路线或可执行的备用任务，不固定站在原地排队。
- 狭窄通道使用短时通行令牌；让行者主动退入侧袋、回撤点或循环路线。
- 无进展时依次执行确定让行者、侧移、后退、释放非必要预约、重新规划或切换备用任务。

验收：多人前往同一区域不会重叠在一个点；狭窄通道双向进入不会永久死锁；未取得工作位的人物不会无限静止。
