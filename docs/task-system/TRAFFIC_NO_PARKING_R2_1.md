# 多人交通 R2.1：取消停车等待，改为预测绕行

- 完整源码基线：`upload/human-workbench-20260915@2c10eda`
- 工作分支：`feature/human-task-workbench-adjustment-v2-fullbase`
- 决策：碰撞避让不再进入原地停车等待状态
- 适用范围：NPC 行走、接近、搬运途中和共享场景临时障碍

## 1. 本轮直接取消的行为

旧逻辑在下一个路线点被其他 NPC 占用时执行：

1. 停车并收脚。
2. 每隔一段时间重新检查。
3. 阻挡移开后继续原路线。
4. 等待超过 30 秒后把任务判为错误。

这一机制不再作为交通主流程。原因是它无法区分短时会车、长期占位和移动后的场景物体，容易让人物长时间停在原地，也无法形成大型 NPC 环境所需的连续流动。

用户任务中明确写出的“等待 10 秒”“休息”等行为仍然保留；取消的是由碰撞系统自动产生的停车等待。

## 2. 新交通顺序

每次人物准备进入下一路线段时按以下顺序处理：

1. 预测未来 1.8 秒内自身沿路线的位置。
2. 预测附近 NPC 按当前速度和朝向的短期位置。
3. 检查两者安全包络是否会相交。
4. 根据 NPC 实例 ID 对生成稳定的左/右侧偏移，不使用随机选择。
5. 生成进入点和越过点，并用连续扫掠检查三段净空。
6. 局部绕行完成后重新并回原任务路线。
7. 如果场景物体已经移动并切断旧路线，立即调用当前网格路径重新规划。
8. 如果侧向净空不足，由稳定优先级确定一方主动后撤到安全点，而不是原地停车。
9. 如果局部偏移、后撤和当前地图重规划均无可用净空，明确返回不可恢复错误，不无限等待。

## 3. 防止机械摆动

- 同一对 NPC 使用对称、确定性的侧向规则。
- 绕行点写入当前 Agent 的路线，不直接修改骨骼、脚锚或 Pose。
- 绕行期间不重复生成另一组偏移点。
- 规划有短冷却时间，避免每帧重跑路径和左右切换。
- MotionController 检测到路线段或落脚路径受阻时，先尝试恢复路线；只有恢复失败才上报任务错误。

## 4. 当前实现位置

主要修改：

- `body/NaturalLocomotion.js`
  - `predictTrafficConflict()`：路线段短期预测。
  - `trafficPairSide()`：确定性左右规则。
  - `installLocalDetour()`：局部进入点、越过点和并线。
  - `replanStaticRoute()`：物体移动后的路线重算。
  - `installDeterministicRetreat()`：狭窄情况下主动后撤。
  - `recoverNavigationBlock()`：把 MotionController 的导航阻断转为路线恢复。

对应测试：

- `tools/test-npc-traffic-wait.mjs`

文件名暂时保留以兼容原检查入口，但内容已经改为验证：无停车等待字段、确定性绕行、持续产生位移、物体阻路后重规划以及脚锚误差。

## 5. 尚未混入本轮的内容

同一工作位、同一交互目标和狭窄通道双向预约属于下一阶段。当前版本先解决“途中相遇与临时物体阻路”，不把站位预约、职业协作和多人同步搬运同时塞进本轮。
