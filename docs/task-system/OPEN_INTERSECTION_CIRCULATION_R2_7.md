# 多人任务 R2.7：开放交叉区域共享通行与主动循环

- 完整源码基线：`upload/human-workbench-20260915@2c10eda`
- 工作分支：`feature/human-task-workbench-adjustment-v2-fullbase`
- 前置能力：独立派单、预测避让、目标站位、狭窄通道方向权、共享资源主动机动
- 约束：不恢复原地停车等待，不另建人物任务队列，不越过 MotionController 直接写骨骼

## 本轮发现的真实问题

R2.6 最终网页中的六人物测试证明，保持人体包络不相交并不等于任务能够完成。四人交叉场景中最小人物间距仍高于安全阈值，但有一名人物在 100 秒模拟时间内没有完成原任务，并产生了大量底层受阻恢复。

这属于进度活锁：每个局部规避动作单独看都安全，但多个人物不断重写彼此的下一段路线，整体剩余路程不再单调缩短。单纯延长测试时间或继续增加随机侧移只会掩盖问题。

## 处理方式

开放交叉区域改为一个共享交通资源：

1. 预测到三人及以上汇入同一开放区域时，建立交叉区域租约。
2. 按稳定进入顺序选择一个通行者。
3. 通行者沿原任务方向穿越区域。
4. 其他人物分配到不同半径的外侧循环路线，持续移动，不原地停车。
5. 通行者越过区域后释放通行权，下一人物接续。
6. 通行者在限定时间内没有穿过时，主动轮换通行权；最多 16 次后明确报告无解。
7. 人物任务终点、个人队列、步态、脚锚和身体控制权仍归原有系统。

## 为什么不继续使用成对优先级

成对优先级只能回答 A 与 B 谁先走，无法在 A、B、C、D 同时交汇时形成全局一致顺序。实际测试中，成对局部规则会让一个人物不断收到互相矛盾的避让目标。共享交叉区域租约把四个成对问题收敛为一个有序资源问题。

## 验收条件

源码和最终网页测试必须同时满足：

- 六位真实 NPC 全部生成完成后再开始测试。
- 四人交叉任务全部到达原终点。
- 任意时刻只有一个交叉区域通行者。
- 非通行者产生真实外侧位移，不包含停车计时器。
- 最小人物间距保持在身体安全阈值以上。
- 每人的最长静止时间低于 15 秒。
- 路径长度相对直线路径有界。
- 底层 MotionController 不反复进入高频阻断恢复。
- 狭窄通道、共享资源和网格导航回归继续通过。

## 当前边界

该机制针对三人及以上开放交叉汇入。两人普通会车继续使用预测侧移；狭窄通道继续使用方向权与通道外循环；同一物体或工位继续使用资源机动。该阶段不宣称八人物长期性能、视觉自然度或生产就绪。
