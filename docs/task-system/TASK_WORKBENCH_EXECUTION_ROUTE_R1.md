# 人物任务工作台高效执行路线 R1

- 分支：`feature/human-task-workbench-adjustment-v1`
- 基线：`ca3e659eb684435c3598170356016fec68db4c2f`
- 目标：只围绕独立派单、多人交通、阻塞恢复三个关键问题推进
- 原则：每个阶段都能独立测试，不同时重写任务、步态和人体求解

## 阶段一：人物独立派单

解决“不能逐个人物勾选和设定任务”。

实现内容：

1. NPC 实例注册表。
2. 单选、多选、全选、反选和按职业筛选。
3. 每个 NPC 独立的待办队列、当前任务、历史和导航状态。
4. `追加任务` 与 `替换任务` 两种派发方式。
5. 临时阻塞只进入 `blocked`，不进入失败历史。
6. 后续将选择状态接到人物列表和三维场景点选。

阶段验收：

- 只勾选一人时，任务不会进入其他人物队列。
- 多选派单时，每人获得独立任务 ID，但保留共同任务组 ID。
- 每个人物可以独立暂停、恢复、完成、失败和取消。
- 替换某些人物的任务时，不改变未选中人物的队列。

当前进度：调度内核和文件级测试已经建立；下一步接现有人物实例与任务面板。

## 阶段二：动态交通

解决“多人沿静态路线相撞或互相挡住”。

实现内容：

1. 保留现有静态 A*，只在任务开始、路线失效或长期无进展时重算。
2. 建立动态空间哈希，记录附近 NPC 的位置、半径、速度和短时预测位置。
3. 以低成本局部避让调整下一段速度或临时航点。
4. 设定重规划冷却，避免左右摇摆和反复改路。
5. 把动态阻挡从致命异常改为等待、让行或重规划。

阶段验收：

- 两人迎面相遇后均能继续完成任务。
- 四人交叉通过时不出现长期重叠或任务突然终止。
- 动态障碍移开后，等待中的人物能够自动恢复。
- 不采用每帧为每人重跑完整 A* 的高开销方案。

## 阶段三：站位预约与死锁恢复

解决“多人争抢同一工作位、门口或狭窄通道”。

实现内容：

1. 为目标生成 `approach`、`interact`、`wait`、`exit` 四类候选站位。
2. 多人前往同一目标时分配不同站位，没有空位者有序等待。
3. 狭窄通道使用短时通行令牌，形成稳定先后顺序。
4. 无进展监视器依次执行：等待、选出让行者、侧移或后退、重新规划。
5. 只有静态不可达、目标消失、命令无效、明确超时或用户取消才终止任务。

阶段验收：

- 八人前往同一区域时不会重叠在同一点。
- 狭窄通道双向进入时不会形成永久死锁。
- 工作位占用时进入等待队列，不立即失败。
- 失败记录能够区分临时阻塞和不可恢复错误。

## 暂缓内容

以下内容不混入当前三阶段，以免路线膨胀：

- 两人或多人同步搬运。
- 完整职业技能系统。
- 大规模远景 NPC LOD。
- Worker 化和超过 16 个完整人物的容量优化。
- 人体几何、关节求解、步态和面部修改。

三阶段稳定以后，再从同一任务与交通接口扩展合作行为。这样不会重新建立一套与现有人体、Pose 和 Animation 相冲突的系统。
