# 多人交通 R2.2：独立终点站位与四向交叉验证

- 完整源码基线：`upload/human-workbench-20260915@2c10eda`
- 工作分支：`feature/human-task-workbench-adjustment-v2-fullbase`
- 继承决策：自动交通不采用原地停车等待

## 本轮目标

1. 多个人物前往同一区域时，不再把同一个中心点作为所有人的最终站位。
2. 四个人物同时穿过交叉区域时，使用预测偏移、局部绕行和移动让行，不新增停车队列。
3. 临时路线点必须通过 MotionController 实际采用的同一 `world.free()` 净空检查，避免规划层判断可用、动作层随后拒绝。

## 实现

`body/NaturalLocomotion.js` 新增人口级短期站位登记：

- 同一语义目标使用稳定目标键。
- 只有多人共享同一目标时才分配不同终点站位；不同人物各自拥有唯一坐标目标时，保留各自原始坐标，不因目标当前被一个正在离开的动态人物短暂占用而永久改写任务终点。
- 第一个共享目标人物在净空允许时保留标准终点。
- 后续共享目标人物在目标周围选择独立站位。
- 站位间距同时考虑两个人物的平面半径与附加净空。
- 任务改变、动作结束或人物移除后释放登记。
- 没有可达独立站位时明确报告几何无解，不进入无限等待。

四向交叉的移动让行点在提交给 MotionController 前，使用其自身 `MotionLabWorld.free(point, .23)` 规则复核。这样静态物体、其他人物和平面身体半径使用同一判定口径。

对于仍在远处、但当前被另一名移动人物占用的原路线点，系统不再把该远点直接提交给 MotionController。它会沿原路线生成一个短距离、可持续更新的安全推进点，人物先向该点前进，再随着空间变化滚动更新，直至原目标重新具备净空。滚动推进不会改变任务目标，也不形成停车等待计时器。

当两个动态安全包络已经在数值边界上发生轻微重叠时，连续扫掠允许严格增加双方距离的分离运动，继续禁止保持重叠或进一步靠近。这样人物能够主动退出碰撞边界，而不会因为所有方向都被判定为零位移而形成假死锁。

如果既有侧向绕行和侧后方让行都无法处理三人以上的局部拥堵，系统会对当前人物周围进行确定性的径向候选采样。候选必须同时改善最近邻净空、通过静态与动态连续扫掠、拥有可达的原任务终点，并按净空、任务进度和方向一致性评分。选中后直接替换剩余临时绕行链，再接回原先分配的终点站位，避免在陈旧绕行线上继续叠加新的绕行。

终点附近若触发侧向绕行，临时偏移只作为过渡点；路线末端始终重新追加已预约的标准终点，不允许绕行点取代任务终点。

## 文件级验收

- `tools/test-npc-target-reservations.mjs`
  - 8 个 NPC 获得 8 个不同终点。
  - 站位保持身体净空。
  - 释放后的标准站位可以重新使用。
  - 不存在停车等待字段。

- `tools/test-npc-four-way-crossing.mjs`
  - 4 个 NPC 从四个方向穿越同一中心区域。
  - 每个人保持原任务目标。
  - 连续扫掠不得产生身体重叠。
  - 至少触发一次预测绕行、移动让行、径向脱困或阻断恢复。

## 边界

这一轮只处理行走终点与途中交叉。搬运、推动等精确接触动作仍使用现有预检生成的操作站位，避免交通层擅自偏移双手接触目标。同一工作台的交互位所有权和狭窄通道令牌属于后续独立阶段。

当前仍是源码和 Node 文件级验证。生成后的 `index.html`、真实浏览器多人运行、视觉自然度和性能尚未因此自动获得验收。
