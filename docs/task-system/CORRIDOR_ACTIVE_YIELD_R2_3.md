# 多人交通 R2.3：狭窄通道方向权与主动撤离

- 完整源码基线：`upload/human-workbench-20260915@2c10eda`
- 工作分支：`feature/human-task-workbench-adjustment-v2-fullbase`
- 前置门槛：R2.2 的接收者选择、预测绕行、静态重规划、同目标独立站位、四向交叉和网格批处理检查通过
- 约束：交通系统不得重新引入原地停车等待

## 目标

解决单人宽度或接近单人宽度的通道中，两名 NPC 从相反方向进入后互相堵塞的问题。

这里不能假设两个人可以同时穿过，也不能把非优先人物停在通道入口。系统需要确定一方的通行方向权，另一方主动退到通道外侧的安全口袋或循环点，并保留原任务终点。

## 运行顺序

1. 对即将进入的路线段检查左右静态净空。
2. 只有左右都不足以容纳双向会车时，才标记为狭窄通道。
3. 使用通道两侧障碍物标识、主轴和量化位置生成稳定通道键。
4. 已经深入通道的人优先；尚未进入时使用稳定 NPC ID 决定方向权，避免更新顺序改变结果。
5. 获得方向权的人继续移动并短时刷新所有权。
6. 未获得方向权的人主动走向通道外的侧后方安全点，再通过循环路线重新接近；不得在原地保持等待状态。
7. 所有权在人物离开、任务改变、人物移除或租约过期后释放。
8. 如果不存在安全撤离点和替代路线，明确报告几何无解，不伪装成仍在执行。

## 不变量

- 通道权只影响导航路线，不直接写入骨骼、脚锚或 Pose。
- 原任务终点保持不变。
- 显式任务中的“等待”“休息”不受影响。
- 行走、携物行走和精确交互分别保留各自身体净空半径。
- 通道权不替代同目标站位预约，也不替代物体操作所有权。
- 高频位置变化不生成项目 revision。

## 第一轮验收

1. 两人从狭窄通道两端相向进入，只有一个方向获得通行权。
2. 非优先人物产生实际后撤或侧移动作，不出现原地停车计时器。
3. 优先人物通过后，另一人物继续到达原目标。
4. 同向跟随不被误判为双向冲突。
5. 开阔交叉区域不会误触发通道权。
6. 通道所有者被删除或任务取消后，权利能够释放。
7. 交通状态和测试中不存在 `waitS`、停车队列或超时等待失败。
