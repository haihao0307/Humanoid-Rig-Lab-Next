## 接口与兼容性

| 接口 | 输入 | 输出与副作用 |
| --- | --- | --- |
| `trafficResolveOpenIntersection` | locomotion、预测冲突、半径/忽略物体上下文 | 租约或 null；只把当前有效的步行人物加入共享交通资源 |
| `trafficMaintainOpenIntersection` | locomotion、净空上下文、原路线当前目标 | 临时运动目标或 null；必要时通过现有路线规划恢复原目标，失败明确报错 |
| `NaturalLocomotion.releaseIntersection` | 当前人物 | 释放交叉租约并清理临时交通状态；不改队列、站位预约或姿态 |
| `trafficPruneIntersections` | NPCPopulation、交通运行状态、共享时间 | 清除暂停、失败、移除、完成、编辑中或任务已变化的成员，更新通行者 |
| `trafficPopulationNow` | NPCPopulation | 返回共享 `elapsedS`；无人口时钟的独立测试回退到在场人物最大时间，交叉与通道共用 |
| `corridorOwnerManeuverTarget` | 通道租约、净空上下文 | 返回经过静态及动态扫掠检查的短程后撤目标或 null；保持方向权，不改原任务终点 |
| `handoffBlockedCorridor` | 当前冲突、净空上下文、通道描述及租约 | 本侧无法撤离时，验证对方撤离路线后交换方向权；失败回滚对方路线/交通状态及租约，每个租约最多协商一次 |

生产入口将协调器装配在 NaturalLocomotion 之前。独立动作测试允许省略协调器，交通调用有存在性检查；全仓文件门禁保证生产入口不能静默漏装。

交叉与通道租约采用 `NPCPopulation.elapsedS`，避免暂停后个人时钟差异影响共享通行期限。最小动作测试环境没有人口时钟时采用在场人物时钟最大值。一个人物不能同时加入不同交叉租约或狭窄通道；三人以上才新建交叉租约。暂停人物从交叉租约退出；通道所有者暂停、失败或编辑时，在共享步进清理方向权，且不能被重新选为通行者。暂停人物仍由人口碰撞接口作为实体障碍处理；恢复后按当前交通重新申请。目标站位若在入组后才预约，成员目标同步到该预约点。

循环目标不使用成对绕行的 `traffic.active` 标记，避免被 `clearTrafficIfPassed` 错误清空。让出通行权后没有可用外侧路径会明确失败，不再借用所有者路径。路线恢复后重新读取路线当前点，防止继续使用旧目标。

交叉阻断需持续 1.5 秒才计为一次主动轮换，每个新所有者重置该区间，保留 10 秒租期及 16 次轮换上限。相同固定步中的逐人调用不再耗尽重试次数。换人导致安全通行轴变化时，外侧成员可以通过扫掠检查的小步逐渐退出新轴的禁入角度。

机动搜索覆盖侧后方向，并在受限净空下尝试 8/12 厘米短步。旧搜索缺少这些方向且最短为 16 厘米，会在人物靠近静态菜筐时漏掉实际可行的路径。所有新候选仍通过原有完整静态/动态扫掠检查，不降低碰撞间距。

通道撤离循环保持在出口同一侧，避免反复穿过出口挡住通行者；所有者前方无短程净空时后撤，并保持这个目标直到接近或路径失效，避免每帧前后切换。`dispatch` 的 64 项限制只拦截追加；替换仍先检查输入和持物状态，再取消旧任务，非法替换不清空原队列。

通道初次选择的让行者没有可行的撤离循环时，尝试由对方撤离并交换方向权；只在对方路线验证成功时提交交换。两边都没有撤离空间仍明确失败，不制造第二个所有者、不无限互换方向。复杂受限出口测试使用生产 GridNavigation，原简化直线/门点寻路替身不足以覆盖绕过到达人物后重新进入通道的路线。

动作板块无需增加骨骼接口：继续消费 walk 目标和既有净空约束。NaturalLocomotion 仅修改交通状态、预测目标、预约释放和路线恢复；姿态接管、连续相位、转身过滤、脚锚及高度逻辑与基线逐段比对一致。TaskAgent、步态曲线、骨骼求解、人体外貌、面部源码未修改。后续动作改动应保留 `resetFromPose`、`move`、`update` 中的交叉预约释放调用。

## 第二步：导航几何一致性与阻断恢复

在相同生产代码上增加只读恢复记录，复跑得到相同 7614/11809 步、115/53 次恢复。全部恢复原因都是身体连续碰撞检测，并非落脚故障。交叉中 npc-2 位于根菜筐边缘，临时目标指向西侧，但身体尚朝向西南；每次恢复立即重发 walk，下一步又沿当前朝向碰到菜筐。通道中的 npc-2 同样贴近右墙，身体转向尚未完成。

- `recoverNavigationBlock` 保存经过净空验证的恢复目标；`continueTrafficRecovery()` 每步验证任务归属、原终点、通行所有者及目标/线段有效性，选择安全的临时 walk 目标。候选同时检查目标线段与开始平移时的朝向，利用现有步行控制器的大角度转向减速行为，待朝向和前方扫掠都可用后恢复原有路线。任务/终点/通行权改变或目标失效即丢弃恢复目标。它不拥有队列、不改任务终点，不写骨骼、脚锚或姿态。
- `GridNavigation` 原来以 7.5 cm 间隔采样路径，会漏掉穿过箱角扩张圆的一小段；新增用例证明旧路线在运行扫掠约 82% 处受阻。网格边和路线简化现使用连续线段/圆角箱体检查，保留空间桶和查询缓存、半径与忽略物体接口。
- `source/runtime.template.js` 中 `pointToObjectClearance` 的箱体局部变换修正旋转符号，与实体四元数及 MotionLabWorld 扫掠一致。调用参数和返回距离单位不变；非零 yaw 箱体附近的路线/站位结果会变化，这是对原错误几何的修正。
- 新增 `test-grid-navigation-sweep.mjs`：66 条路线逐段对照运行扫掠，包含正负旋转箱体、圆形和倾斜障碍，以及忽略交互物体。原 123 个缓存/取消/几何失效用例继续通过。
- `test-npc-traffic-wait.mjs` 加入真实 MotionController 的箱边恢复回归：相同缩小用例在旧代码恢复 56 次，新代码 1 次并到达原目标；脚锚误差约 1.7e-16 m，动作内核无姿态拒绝。沿障碍切线及浏览器现场的紧凑人物/已有摆脚状态也各恢复 1 次后完成。还检查替换任务、相同索引但终点变化和通行权变化不能继续旧恢复目标。
- 浏览器报告新增错误类型总数和有界现场样本。它记录真实恢复次数，不合并或隐藏连续阻断。CI 新增导航连续性用例，并补齐 GridNavigation 路径触发条件。
- 当原任务终点紧邻通道出口时，`corridorPassed` 保留方向权直到到达后的既有释放流程，而不是刚出通道就允许外侧人物重新进入。CPU 通道用例新增到达附近仍持有方向权的断言；远离出口的任务仍按原通道边界释放。
- `replanStationaryRoute` 在预计路线穿过静止人物时，把 NPCPopulation 中暂停、失败或已无任务且停止的人物投影为本次导航查询的圆形障碍，重新规划到原终点。快照只用于 GridNavigation，不写入场景物体或物理世界；运动中的人物继续走预测协调。新路线仍经原有扫掠约束，已绕开的路线不重复重规划。新增入口被到达人物占据的完整路线用例，同时检查场景对象不被改动、原终点保留、暂停障碍和运动人物排除。

本轮共享 NaturalLocomotion 仅改变导航恢复、`move` 中的恢复调用、`corridorPassed` 的出口预约释放条件和 `prepareTrafficTarget` 的静止人物重规划衔接；其余 32 个既有方法与第一轮提交一致。新增方法只处理路线与临时目标。转身过滤器、连续相位、姿态接管、脚锚及高度逻辑未修改；TaskAgent 和动作内核未修改。恢复期间继续使用 walk 接口，保留正在进行的摆脚调度。动作板块今后如改变步行开始平移的 0.6 rad 朝向窗口或净空协议，应共同复跑箱边、切线和摆脚现场回归。
