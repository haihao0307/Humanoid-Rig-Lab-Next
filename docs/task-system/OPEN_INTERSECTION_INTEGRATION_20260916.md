## 接口与兼容性

| 接口 | 输入 | 输出与副作用 |
| --- | --- | --- |
| `trafficResolveOpenIntersection` | locomotion、预测冲突、半径/忽略物体上下文 | 租约或 null；只把当前有效的步行人物加入共享交通资源 |
| `trafficMaintainOpenIntersection` | locomotion、净空上下文、原路线当前目标 | 临时运动目标或 null；必要时通过现有路线规划恢复原目标，失败明确报错 |
| `NaturalLocomotion.releaseIntersection` | 当前人物 | 释放交叉租约并清理临时交通状态；不改队列、站位预约或姿态 |
| `trafficPruneIntersections` | NPCPopulation、交通运行状态、共享时间 | 清除暂停、失败、移除、完成、编辑中或任务已变化的成员，更新通行者 |
| `trafficPopulationNow` | NPCPopulation | 返回共享 `elapsedS`；无人口时钟的独立测试回退到在场人物最大时间，交叉与通道共用 |
| `corridorOwnerManeuverTarget` | 通道租约、净空上下文 | 返回经过静态及动态扫掠检查的短程后撤目标或 null；保持方向权，不改原任务终点 |

生产入口将协调器装配在 NaturalLocomotion 之前。独立动作测试允许省略协调器，交通调用有存在性检查；全仓文件门禁保证生产入口不能静默漏装。

交叉与通道租约采用 `NPCPopulation.elapsedS`，避免暂停后个人时钟差异影响共享通行期限。最小动作测试环境没有人口时钟时采用在场人物时钟最大值。一个人物不能同时加入不同交叉租约或狭窄通道；三人以上才新建交叉租约。暂停人物从交叉租约退出；通道所有者暂停、失败或编辑时，在共享步进清理方向权，且不能被重新选为通行者。暂停人物仍由人口碰撞接口作为实体障碍处理；恢复后按当前交通重新申请。目标站位若在入组后才预约，成员目标同步到该预约点。

循环目标不使用成对绕行的 `traffic.active` 标记，避免被 `clearTrafficIfPassed` 错误清空。让出通行权后没有可用外侧路径会明确失败，不再借用所有者路径。路线恢复后重新读取路线当前点，防止继续使用旧目标。

交叉阻断需持续 1.5 秒才计为一次主动轮换，每个新所有者重置该区间，保留 10 秒租期及 16 次轮换上限。相同固定步中的逐人调用不再耗尽重试次数。换人导致安全通行轴变化时，外侧成员可以通过扫掠检查的小步逐渐退出新轴的禁入角度。

机动搜索覆盖侧后方向，并在受限净空下尝试 8/12 厘米短步。旧搜索缺少这些方向且最短为 16 厘米，会在人物靠近静态菜筐时漏掉实际可行的路径。所有新候选仍通过原有完整静态/动态扫掠检查，不降低碰撞间距。

通道撤离循环保持在出口同一侧，避免反复穿过出口挡住通行者；所有者前方无短程净空时后撤，并保持这个目标直到接近或路径失效，避免每帧前后切换。`dispatch` 的 64 项限制只拦截追加；替换仍先检查输入和持物状态，再取消旧任务，非法替换不清空原队列。

动作板块无需增加骨骼接口：继续消费 walk 目标和既有净空约束。NaturalLocomotion 仅修改交通状态、预测目标、预约释放和路线恢复；姿态接管、连续相位、转身过滤、脚锚及高度逻辑与基线逐段比对一致。TaskAgent、步态曲线、骨骼求解、人体外貌、面部源码未修改。后续动作改动应保留 `resetFromPose`、`move`、`update` 中的交叉预约释放调用。

## 检查与边界

联网资料核查参考 [ORCA 原始项目](https://gamma-web.iacs.umd.edu/ORCA/) 与 [局部协调处理死锁论文](https://arxiv.org/abs/2107.00246)。它们支持区分局部避碰和整体通行进度；本项目未实现或验证这些论文算法，不继承其安全性证明。

已执行：源码装配、生成入口一致性、全仓语法/依赖/文件审计、65 项交叉通行及衔接源码契约，以及共享文件边界比对。`Task integration checks` 区分文件检查和 CPU 运行回归两个作业。文件审计中的 `applicationExecuted:false` 仅描述该文件检查工具；下面的运行结果独立记录。

首次 Linux CI 暴露了原构建器的跨平台差异：gzip 头的 OS 字节在 Windows 为 10、Unix 为 3，导致相同文本的生成入口无法逐字节匹配。本次在 `build-pure.mjs` 中将该元数据固定为 255（unknown），保留压缩往返检查；文件 CI 固定 Node 24.14.0，与本地生成环境一致。未改运行时解压协议或人物逻辑。
