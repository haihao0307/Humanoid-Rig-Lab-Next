# NPC 持续任务与默认视图 R2

“NPC 生成与多人控制”现在可以编写多行步骤，包括现有动作指令和“等待 15 秒”“休息 2 分钟”等等待步骤。每份任务最多 64 步、16000 字，一轮最多 256 个基础动作；同一人的步骤按顺序执行，各个人物独立计时。

结束条件支持手动停止、指定分钟数（最长 24 小时）或指定轮数，并可设置每轮间隔。暂停保存当前步骤、剩余等待和运行时间；继续从当前位置恢复。达到时长后，当前动作先安全结束再停止调度。发生动作或共享物理错误时终止该任务并显示原因。刷新页面后不会自动恢复；草稿保存在浏览器，人口配方包含任务设置，导入后须手动开始。

操作示例：选择全体人物，填入“打招呼 / 等待 15 秒 / 挥手 / 等待 20 秒”（每项另起一行），结束条件选择“持续到手动停止”，点击“开始持续任务”。人物卡显示当前步骤、完成轮数和运行时间。单次命令可在“单次指令与追加”中输入。

普通人物视图、双人视图及正面/侧面/背面观察使用透视投影，启动默认开启阴影。阴影实际使用取决于浏览器 WebGL 支持。

原先默认场景的 `WATER_A` 水壶与 `TREE_D` 树木碰撞范围重叠，导致共享物理步进失败，连与该物体无关的行走也被中断。水壶初始 x 从 11.3 米移到 10.95 米，保留碰撞检测及原有容差。

实际测试还发现站姿进入打招呼时，被挥手片段较窄的膝关节范围误拒绝。过渡范围现在包含已提交的起始姿态角度，过渡结束恢复原录制片段约束，缓存范围保持不变；不会从待验证候选姿态反推允许范围。回归检查：`node tools/test-motion-transition-range.mjs`。

任务调度测试使用 `node tools/test-npc-persistent.mjs`，覆盖多步骤顺序、双人独立执行、暂停/恢复/停止、按轮数/时长结束、输入校验及导入后不自动启动。
