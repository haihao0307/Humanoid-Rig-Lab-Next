# R28 连续关节与原轮廓

本轮从 2026-10-26 14:28:09 UTC 开始，17:28:09 UTC 硬停止，不因跨本地日期、候选和检查而重置。身体范围；共享 R15 与独立头部项目不修改。不抢鼠标，以实际三维网页交付，没有新增图片文件。

## 这轮改变了什么

R27 主要改变输入存储与计算速度。R28 把实际显示从“只有十组固定原貌，其余动作退回简化场”向连续原轮廓推进。

- 原有十组固定状态继续使用原来求交与皮肤路径，HTML 只改版本和工作页链接。
- 六种 Anny 原体型下的四肢动作，以及驱动 B 明确关闭原姿态修正的原状态，已接入连续来源函数。默认姿态修正没有被关闭。
- 不用动作快照插值。运行时求标量函数、动态平面和裁剪函数的交点；屏幕使用 POINTS，没有人物顶点/索引缓冲或人物三角面绘制。
- 原 native、目标映射与颈口轮廓/平顺/调和阶段的取整顺序已经接回。射线核对使用整数裁剪判断和有理数首交排序，不扩大几何容差。
- 旋转时先显示交互预览，停止操作后，最多三个后台计算单元更新完整画面。旧相机或旧动作结果不能覆盖新状态；失败保留预览与人物，可重试。
- 原目录 1916 项、身体 965 项、34 组配对、左右独立值、两套驱动和完整人物档案保留。头部及未知档案字段继续往返保存。

在三维工作页点击“屈肘”，或连续调整前臂、腕踝等参数，可以查看新路线。独立候选页提供六种原体型与 B 的明确关闭修正状态、三轴动作、组合示例、全身/半身/正侧背面观察和完整人物读档。

## 表达与来源边界

主要实现：`BodyRoundedFunctionsR28`、`BodyMovingDomainR28`、`BodyPoseFunctionsR28`、`BodyPosePrecisionR28`，以及 R28 工作页路由。

不可变共享数据保存精确有理标量系数、来源分区、裁剪条件、骨架函数系数和法线响应系数；实例保存当前完整参数、动作与头颈输入。函数不生成显示用人物网格，不把结果交回原网格显示。

原顶点/面表只在隔离的离线编译和对照中读取，没有作为新显示输入发出。运行时仍明确保留原分区信息、绑定校准和颈口支撑关系；原数值驱动的校准样本也继续保留。**这不代表自主母体完成，更不代表来源消失。**

标量函数在来源参数域的边界上恢复原操作数，再按原顺序运算；动态显示的权威输入是函数系数与变量。缓存只保存不可变标量函数的精确参数求值，不缓存动作快照，不缓存人物面连接。缓存的键值载荷上限为 64 MiB，字符串和 Map 的引擎开销另计。

稳定状态只有一个可见身体显示。为避免载入失败时丢失旧画面，切换期间最多暂存两个显示；完成后释放旧显示与其后台计算资源。完整场景显存与全系统紧凑化仍未完成。

## 法线仍有差异

最初的局部形变法线传递，在相同检查中的最大法线差约 56°。来源面积响应多项式将该差异降低至约 1.29°，最大剩余差异主要集中在颈口；仍未通过原法线复刻。

离线审计确认：原模型用于身体法线的混合身体/头部支撑为 336 个面，实际显示几何为 584 个。实际显示细分还包含依赖端点法线的切平面修正、条件分支和逐级法线重算。用实际显示支撑重算法线可逐分量匹配原显示；只用原模型支撑仍有差异。

当前法线响应尚未复刻这套显示支撑、分支和原 Float32 累计顺序。这是已缩小的实施边界，不能宣称解释了全部法线和材质差异，也不能通过猜测加厚或改肌肉体积来掩盖。审计见 `normal-support-audit.json`；较早失败候选和结果继续保留。

原皮肤固定状态路径仍沿用 R27/R26，首次/重绘及原生局部像素差异没有在本轮被解决。新连续函数页用灰色结构光；原皮肤设置保存在完整人物档案中，不假装已在灰模生效。
