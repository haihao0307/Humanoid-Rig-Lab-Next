# 承重高度与摆脚踝部配合

## 原因与修改

原行走高度固定采用腿长的 94%，导致承重腿到达身体下方后仍持续屈膝。NaturalLocomotion 现在根据个人股骨/胫骨长度、脚锚与髋部的水平距离计算承重高度，再经过已有高度响应；保留双腿（包括摆动腿）的可达上限和固定骨长约束。12 度的目标屈膝是工程上的 IK 余量，不是医学正常值，也不是全身动力学。

离地脚增加前段轻微下垂、后段回收的踝部姿态。幅度随实际速度和步距缩放，并受可用离地高度约束；接触时回零，继承的倾斜脚掌仍优先使用原姿态。MotionLabPose 消费该姿态，完整骨架和皮肤跟随同一个提交器，未添加渲染侧假动作。

研究依据：[Usherwood 等关于 heel–sole–toe 与承重腿摆动机制的研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC3427509/) 描述了落地、较伸展的中段承重和末段蹬离之间的区别。本轮只处理几何承重高度与离地踝部配合，没有实现论文中的能量/力矩模型，也没有把空中摆脚称作真实蹬地。

## 共享接口

- 任务输入仍为目标、路线和交通约束；步速、路径、落脚端点和接触时序不变。未改预约、避让、阻断恢复、任务队列或调度。
- 脚状态增加可选 `swingPitch`（弧度）。旧状态缺省为零，接触脚为零；有 `adoptedOrientation` 时保持原接管路径。该字段随既有内核状态快照恢复。
- `report().height.walkingTargetM` 现在返回当前承重目标，新增 `legacyWalkingTargetM` 保留旧标量，`method` 为 `support-reach/v1`。外部正常调用无需配合；读取诊断者不能再假设目标为常量。
- 不修改 CharacterShape 的体型定义、外貌、面部、人物选择、锁定 vendor 或生成入口；index.html 由构建生成。

## 分层验证

**CPU 运行：**8 种体型、16 次行走、16 次转向、8 次中途停止，共 17,362 帧通过。3,456 个稳态承重腿样本的平均屈膝为 15.793 度；同条件旧 HEAD eaf618a 为 35.294 度。峰值仍为 40.484 度，说明开始换步等阶段仍有明显屈膝，不能据平均值宣称解决全部姿态问题。

高度单帧变化最大 1.572 mm（120 Hz）；脚锚误差约 1.8e-16 m，固定骨长误差约 3.9e-16 m。摆脚角度范围约 -6.72 至 +5.74 度，完整姿态实际脚部角度有变化，接触脚姿态保持不动。摆动腿最大屈膝仍约 51.83 度，未把双腿统一拉直。

相位连续、左右转向、步速/摆臂配合、动作失败回滚、起身脚掌接管、轻量平衡、蒙皮连接与 2,078 组完整/精简接触预检一致性均通过。上述数值是测试场景结果，不是生理标定或性能容量证明。

**浏览器与视觉：**真实 WebGL 每 150 ms 采样行走和转向，78 张截图无页面/人物错误。已逐格查看正侧联系表、关键放大图和停止姿态，与上轮同时间采样对照；采样最低皮肤点约高于地面 0.685 mm。承重中段姿态较高，摆脚出现踝部变化；仍有平脚落地、换步偏屈膝、胸部偏直的观感，整体自然度未通过。镜头跟随人物，临时隔离其他人物渲染，非实时帧率录像，未操作桌面鼠标。

七类动作和六人分发回归结果见交付 PR。证据保存在本轮外部可视化目录 `support-height-final` 与 `support-height-runtime`。浏览器采样构建为 20c6aee1d718922f2d189a2821035ff77752f09584da5c5ee39f5de0a29a210c；之后只整理源码注释/缩进并补充测试中的实际脚姿态断言，最终入口重新装配并执行文件审计，不把这些非行为调整声称为又一次浏览器运行。

## 下一阶段

真正的脚跟落地—足底承重—前脚掌蹬离，需要将接触支点由踝点扩展为脚跟/前脚掌局部点，并让摆脚调度、IK 和支撑反馈共同维护世界接触约束。当前脚锚锁定踝点，直接旋转接触脚会造成脚趾穿地或滑动，因此本轮接触脚保持原契约。后续须同时验证支点连续、皮肤净空、重心转移、停止与转向接管，再扩大多人容量测试。

此前坐姿悬臀、起身展臂/侧倾和群体空间占用仍未解决；本轮没有测量大量 NPC 的实时容量。
