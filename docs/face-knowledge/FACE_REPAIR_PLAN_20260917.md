2026-09-18 用户最新决定：**“鼻子已经可以了，嘴唇变厚一倍，就可以先收尾提交GitHub了。”** 因此本轮仅继续完成唇部加厚和必要的皮肤连接适配；眼、鼻、口内、牙/舌、胡须不再扩改。保留已完成修复，未整合的实验不进入生产。下列九阶段是长期路线，不能覆盖用户此次明确的阶段收尾范围。

遵循用户先处理皮肤的优先级，顺序为：**外貌数据 → 固定检查条件 → 皮肤主要观感 → 鼻口连接 → 眼眶与眼睑 → 表情与口腔 → 其他细节 → NPC 批量验证 → 整体验收**。第一轮皮肤集中处理正常观看距离的光泽与色彩；五官形状保持可比较。后续结构完成后再回到皮肤做最终校准。

所有模块保持项目自行编写的生成函数；不引入第三方头部、扫描、模型、贴图或现成材质。只负责外貌面部范围，保留动作、任务系统和已有表情控制协议。生产工作遵守装配入口，不直接修改生成的 `index.html`。

## 1. 外貌数据与共用结构

已实现 `FaceAppearance.js` 参数配方、种子采样、导入导出和生成器版本检查。17 个身份参数与临时表情分开。4 个整体比例通过同一连续映射作用于面皮、眼、牙、耳与毛发，另 13 个局部参数继续使用原有控制场。默认值不改变中性头，旧版本配方可迁移。

验收边界：同版本同参数能复现；表情不写回身份；更换外貌不能改变任务、角色编号、身体或已有发型。不同版本不能无提示地声称复原原样。数值边界与两个 NPC 图例不能证明任意组合均符合解剖。

## 3. 皮肤主要观感：先解决塑料感

**学习重点：**复核 `SOURCES.md` 已记录的艺术家皮肤制作拆解与反射/扩散资料，关注区域粗糙度、油膜、色素和光照各自负责什么。记录实际阅读范围；需要新方法时先查原始资料，再决定实现，不把“加随机噪声”当作默认答案。

**修改所有者：**`SkinSurface.js`、`TissueShaders.js`；只有隔离结果指向扩散时才调整 `SkinTransport.js`。诊断照明属于 `CompactWorkbench.js` / `source/runtime.template.js` 的渲染职责。

执行顺序：

1. 冻结几何和当前微表面，分别关闭油膜、宽镜面、色素变化与扩散，定位哪一项主导当前塑料感；必要时加入只显示镜面的调试视图。
2. 先校准光源与反射的对应关系，再调整宽/窄高光的强度和粗糙度。不能靠统一加大粗糙度、减暗曝光或强模糊获得“改善”。
3. 调整额头、鼻部、面颊、下巴的连续区域权重，让光泽差异有位置依据，区域之间没有硬边。参数均为自主设定，不冒充人体实测。
4. 处理肤色：减弱云状中频色块，分离总体肤色、局部色调和细小色素变化，避免整个面部统一橙褐或大面积脏斑。
5. 只有主观感改善后才重新接入浅微表面，检查它在特写时增加细节、退远后自然过滤。保留扩散的材质/深度边界，不用它遮盖几何接缝。

**必须看到的结果：**相同镜头和曝光下，正常距离的额头/鼻/颊反光不再像一层统一涂层；肤色减少云斑且保持细微变化；侧光不出现砂纸、橘皮或蜡融感。中性肤色与一个深肤色设置都检查，不能只为单一肤色调通。接触处不得出现新的模糊光圈。

**返工规则：**如果只在极近距离看见噪声变化，第一阶段不通过；回到分量隔离和光源校准。若某项缺陷在灰模中仍存在，将它交给明确的结构阶段，不继续用材质补偿。皮肤阶段通过仅代表材料观感改善，不代表整脸真实。

## 4. 鼻口连接与唇体：重做关键空间截面

**学习重点：**按正、侧、仰视研究鼻翼回折、鼻底/鼻小柱关系，唇红外翻、唇内缘、口角与口周支撑。先将观察写成可检查的截面和连接关系，再实现函数；不凭一张正面参考改变全部比例。

**修改所有者：**`FaceAnatomy.js`、`PerioralSurface.js`；只有确认源头部接口是问题来源时才进入 `surface-kernel.mjs` / `mesher.mjs`，范围限定头部及已存在的接口责任。

- 先处理鼻子外表面：联合定义鼻尖、鼻翼、鼻小柱和鼻底的空间截面。对需要回折的局部使用能表达多方向形状的参数曲面，避免只用正面高度网格加深孔洞。
- 保留鼻腔壁的真实连接，明确外皮到内壁的过渡。不能把“有内壁”当作“有鼻翼厚度”。
- 再处理口周：让人中、上唇支撑、口角、下唇与下巴之间的体积连续；重构唇体沿口宽变化的截面，降低等粗胶条感。
- 单独检查唇缝的实际间隙、腔体遮挡和接触阴影，各改各自职责，不能直接抹掉黑线。
- 首先完成中性状态，每完成鼻或口一个局部立即检查相邻区域和整脸，避免局部正确、整体失衡。

**必须看到的结果：**灰模正、斜、侧、仰视都能读出鼻翼包覆；鼻孔不再像薄片上打孔；唇体与周围皮肤有连贯体积，口角没有尖刺、细钩，唇缝不靠一条均匀黑线成立。既有颏底白折和口角叉线不能回归。

## 5. 眼眶与眼睑：解决闭眼盖片

**学习重点：**明确眶部支撑、眼球接触、睑缘、眼皮厚度和闭合运动的分工。此前接触包络可能顶起中央睑面是待验证解释，先做有控制的对照，不直接当成唯一根因。

**修改所有者：**`EyeAnatomy.js`，必要的相邻眶部支撑由面皮所有者负责。

- 联合调整眼球位置、上下睑截面和外侧支撑，避免只压低中央盖片后造成穿球。
- 让接触约束保护眼球，同时保持外部皮肤体积和眶缘过渡；表情过程中控制整条睑面，不只移动自由边。
- 重整内外眼角、泪湖与睑缘的连接；眼材质暂时固定，先完成灰模。
- 检查睁眼、约半闭、全闭，增加少量视线转动；双眼、正侧面均覆盖。

**必须看到的结果：**闭眼表面连入眼眶，不再出现独立圆盖或突出亮弧；半闭不鼓包、跳变或穿眼球；开眼的上下睑层次自然，眼角没有独立粉色片。

## 6. 表情与口腔：让修好的结构能动

**修改所有者：**`FaceAnatomy.js`、`PerioralSurface.js` 与 `EyeAnatomy.js` 的几何响应。保留已有表情通道名称和调用关系；需要跨模块改接口时先形成明确变更说明。

- 调整牙弓和各牙冠的形状、排列及牙龈遮挡；先看正常说话露齿范围，避免只为大张口画面调形。
- 校准内唇、黏膜、舌与腔体层次，保持湿润内缘与外部皮肤的区别。
- 检查轻张口、适度张口、微笑、抿唇、眨眼，以及适量组合；让口角、脸颊和下巴随开口形成连贯变化。
- 把阶段 2、3 的结构检查加入表情后的回归，防止中性修好了、运动又破坏。

**必须看到的结果：**正常说话幅度下牙齿不再像矩形积木，嘴角不拉出细钩，牙齿不穿唇；连续变化不跳形。单表情通过后，组合表情仍不出现新的明显断裂。

## 7. 次级细节与最终皮肤校准

- 定位耳褶、脸侧、鼻侧和颏颈细缝的真实生成层，再修共享边、采样或法线；不全局加密、全局磨平。
- 眉毛与睫毛按生长区组织方向、密度和聚散，检查像素覆盖与距离过滤；数量更多不能作为验收条件。
- 校准角膜、虹膜、眼白和湿润睑缘，减弱过于规则的虹膜辐射和硬外圈。
- 在新几何上重新校准阶段 1 的皮肤区域，确保材质随表情稳定、没有漂移或接口色差；最后补受控的不对称与微细节。

**必须看到的结果：**细节在特写下有结构、正常距离不抢眼，换距离不明显闪烁；没有为局部细节牺牲原有整脸形态。

## 8. NPC 批量验证

使用固定种子批次与有界参数边界样本；先分别核对脸型、肤色，再组合检查。至少覆盖头部宽窄长短、眼距、鼻口比例，检查毛发与眼牙耳随动、非活动 NPC 与当前编辑角色的一致性、保存再载入和表情后的身份保持。发现碰撞时增加局部针对性样本，不将随机图数量当作覆盖率。

目前仅完成 256 份数据采样和有限的实际 NPC 外貌画面，未完成全部外貌与动作组合的视觉验收。精细眼型、耳型和老化范围尚未建立。

## 9. 整体验收与集成

采用分层检查，不把所有组合做无意义的全排列：中性三视角检查轮廓与连接；固定相机换三种灯位检查体积和材质；近景与正常距离检查尺度；关键表情及少量组合检查接触；中性和深肤色检查光学范围。发现问题再增加针对性的镜头或组合。

每个生产阶段交付：实际可交互工作台、必要的源码改动、同条件前后对照、仍失败项和知识记录。只运行改动所需的构建、连续性、接触或材料测试；最终补整体验证。在真实目标 GPU 上测帧时间与资源开销，再判断扩散方案是否适用，后台软件光栅结果不代表游戏性能。

满足对应视觉条件才接受阶段改动。失败则返回该阶段的结构或材料假设，不通过叠加无关修饰继续推进；不以测试数、代码量或新版本号宣称改善。最终整脸通过当前要求后，再核对远端并整合到统一入口，不把本地候选当成已经发布。
