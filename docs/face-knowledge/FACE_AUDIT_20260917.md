## 为什么前面改了多次却不明显

1. **主要失败已经被观察过，却没有成为交付阻断项。** 之前的记录也承认闭眼凸盖、薄切口鼻孔、规则口缝和耳部面片。之后仍按局部小项继续推进，未让这些问题逐个闭环，这是工作顺序和验收的问题。
2. **皮肤改动集中在低幅度细节及传输，轮廓和组织大形保持不变。** 本次去镜面、灰模与源码哈希对照共同支持这一点。不能要求微米级起伏修复毫米级形状，也不能把用户要求先处理皮肤作为未解决整体问题的借口。
3. **“函数具备 / 连续 / 不穿插”被赋予过多视觉意义。** 例如 `nasalUnderturn:true`、`philtrum:true` 仅表示有对应实现；对眼睑的包络约束也只解决接触的一部分问题。
4. **多镜头不等于独立换光验收。** `source/runtime.template.js:209–210` 当前工作室灯光方向根据相机方向计算。转相机也会转灯，无法单靠这些截图证明固定世界光下的全部体积表现。下轮需补固定世界光转观察方向、固定镜头转主光两组独立检查。

## 后续修复的可执行门槛

先把诊断固定下来：相同身份、姿态、距离、曝光，记录真实材质状态；一个主要变量做一组 A/B。结构修复按鼻口连接与眼眶/眼睑两个区域逐块完成，再汇合整脸。皮肤专项仍保留，但只有对光泽、色素或起伏的隔离观察支持时才调整对应函数。

每一块完成要同时满足：正常观看距离有明确可辨的改善；灰模前/斜/侧不靠高光遮缺陷；闭眼、适度张嘴不出现盖片、细钩或组织断裂；换光后改善仍成立。回归测试继续保护连续性、材料边界和程序化资产约束，但测试数量不用于宣称 3A。

诊断入口：`node tools/capture-face-diagnosis.cjs <仓库外输出目录> [逗号分隔的镜头名称]`。`diffuse-only` 临时移除皮肤 GGX 返回值，`albedo-only` 临时输出原始底色并关闭扩散；仅存在于可丢弃浏览器中，不写回生产着色器。该工具用于问题隔离，不是最终渲染功能。
