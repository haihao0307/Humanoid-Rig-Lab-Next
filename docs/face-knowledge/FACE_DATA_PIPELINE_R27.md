# R27 面部数据、变化逻辑与参考图片路线

2026-10-04。用户要求先完成整个面部的数据准备和可复用变化规则，之后另发一张图片，将可见面部特征记录为数据并尽量调整到当前模型上。本轮交付可交互三维原型及数据闭环；**目标图片尚未收到，未完成真实参考脸复刻**。

本轮所有检查使用独立后台 Chrome，不操作用户鼠标。使用现有 R008 来源生成函数，自创身份变化场和拟合规则，没有引入外部头、模型、贴图、训练权重或预制形变资产。人体反推骨架/肌群接口保持不变；身份造型不声称恢复内部骨骼。

## 当前覆盖与初始基准

工作台入口：`http://127.0.0.1:8879/?view=face-data&version=face-data-r27`。默认固定正面、中性姿态、直视、22° FOV，距离 0.95 m；画面右为人物左。左侧控制身份，右侧显示模型毫米/角度、投影比例、参考比例和误差。照片标点视图在同一右侧面板。原有 57 局部分区、147 可编辑 XYZ 位移和 46 表情区域仍可切换。

新增 52 项身份参数、82 个语义标志点、27 个测量项目。当前精细档现场生成 131,691 个头脸表面样本参与身份映射；该数量随采样精度改变，全部缓存只在运行内存中。数据覆盖的是现有人物的外表面、语义测量和有限变化空间，**不等于全部人脸的所有自由度或真实内部数据**。

当前中性基准与规则描述已保存到 [R008_FACE_BASELINE_R27.json](R008_FACE_BASELINE_R27.json)，包含 52 项定义、82 点坐标与证据、27 项测量、镜头和对应源码哈希。文件不包含顶点/三角数组、图片或已烘焙形变。修改来源或采样后要重新绑定和复核，不能把这些校准点搬到其他人物。

基准中眼中心间距 68.0 mm、构造眼裂宽 23.6 mm；中段测量眼裂高约 4.85 mm（两段轮廓样点），构造中央最大开口 5.6 mm。这两种高度定义不同，不能混写。鼻翼点距约 38.0 mm，口角点距约 52.0 mm。眉、鼻、唇、发际线的语义 XY 是根据当前人物校准的种子，再绑定真实曲面，不是自动检测或临床测量；发际线置信度较低。

## 参数与变化逻辑

| 层 | 参数 | 作用与边界 |
| --- | --- | --- |
| 整体 5 项 | 全头宽/高/深，眼线以上/以下长度 | 颈根平滑衰减，头脸、耳与毛发表面共同变化；单图拟合不求解深度 |
| 轮廓 9 项 | 额宽/前凸，太阳穴宽，颧宽，下颌宽/高度，下巴宽/长度/前凸 | 直接改变外表面，不重拟合或伪造内部颅骨 |
| 鼻 8 项 | 鼻宽/长、鼻梁宽/前凸、鼻尖宽/高/前凸、鼻底高度 | 宽度/长度与局部位置独立；实际尺寸以测量反馈为准 |
| 口 6 项及左右口角 2 项 | 口宽/高度、上下唇厚、唇前凸、人中长、左右口角高度 | 不提供牙列、张口内部和完整下颌运动 |
| 左右眼 12 项 | 外移、高度、深度、宽度、开合高度、眼角倾斜，各侧独立 | 眼球、眼睑和周围皮肤同步映射；眼区是有范围的整体形态近似，眼球可能随仿射场形成轻微椭球，不等于球形眼球/角膜的独立解剖求解 |
| 左右眉 6 项 | 眉高度、眉峰高度、眉区长度 | 移动承载毛发的表面，未改变密度、颜色或重新生成眉型资产 |
| 左右颊 4 项 | 面颊前凸和颧颊高度 | 体表形状近似，不测定脂肪/肌肉内部比例 |

每项定义中的 `matrix`、`translation`、`centre`、`radii`、单位、范围及是否允许正面拟合是持久规则。没有对某张参考图临时烘焙形变。百分比是该形变场的请求尺度，不保证测量值等幅变化；毫米是当前模型的构造空间请求，照片没有标尺时不生成真实毫米目标。

身份映射是原空间中的线性参数叠加：

`F(p)=p+Σ θ_i · w_i(p) · [A_i(p-c_i)+t_i]`。

局部场使用带平顶和光滑边缘的椭球支持；全头场在颈部衰减，上下脸使用眼线附近的连续过渡。局部 XYZ 和表情先在原中性空间评估，身份映射随后作用于其结果；法线使用 `cofactor(J)·n` 归一化。因此表情重置保留身份，身份恢复保留独立局部分区配方。

每次应用检查所有参与样本的身份雅可比行列式和最大坐标伸长：要求 `det(J)>0.42`、列向量最大长度 `<1.9`。不满足则同时缩小有效参数，并公开请求/有效数值与 `safeScale`。这只是采样保护，**不是连续空间无自交、眼球生理结构或任意极端组合的美术认证**。

全头正常值和映射后的面部输出缓存用于避免重复中性重置导致反复评估整个头部；表情改变时只评估受改变的面部样本，必要时重新做完整限幅。本机演示身份下微笑 + 重置共约 0.2 秒，尚不能宣称复杂身份与表情均达到 60 FPS。

## 五官数据与标志点

82 点包括：17 个下脸轮廓、10 眉点、12 眼缘、2 眼中心、8 个颧/颌/太阳穴/耳外缘点、9 鼻点、20 唇点、3 发际线和眉间中心。

表面点使用当前生成三角面的重心绑定；轮廓使用当前表面横截面外缘样本；眼缘使用当前眼部构造。每个点带 `confidence`、`evidence`、`status`，无法绑定则是 `NotObserved`。82 点都可绑定仅说明存在对应表面/构造数据，不代表语义种子全部准确。当前轮廓点是固定截面上的绑定点；大幅变形后不自动重新求解新的正面最外轮廓，真实参考拟合时须复核轮廓对应。

27 个测量包括眼中心距、颧/太阳穴/下颌/下巴宽、发际线到下巴、三庭、左右眼裂宽高、左右眉眼距与眉区长度、眼角倾斜、内眼角距、鼻翼宽、鼻长、口宽、上下唇中段厚、人中和下唇到下巴距离。长度的定义是标志点空间直线/垂直距离，不是沿皮肤弧长。三庭五眼只作为目标比较量，不强制相等或标准脸。

## 参考图片协议与下一步执行

`face-reference.json` 当前为等待图片的空会话，预览服务只开放此明确数据文件。下一步收到用户图片后：

1. 读取图片，确认正面程度、表情、遮挡与左右方向；记录像素宽高。只记录看得见的标志点，不给遮挡区捏造精确点。
2. 以人物自身左/右命名；正面画面右为 `Left`。各点记录归一化图片 XY、可信度及可见性；深度和绝对尺寸保持未知。眉唇轮廓和发际线要对照模型种子复核。
3. 写入 `face-reference.json` 的 `reference`，或通过网站图片标点/JSON 导入。网站“读取已记录的参考数据”读该文件；输入图片只存在浏览器临时 URL，坐标单独保存，不将照片变成模型资产。
4. 固定正面和中性状态拟合，查看当前/目标比例与点位误差；导出完整面部数据、身份配方和拟合记录。眼眉鼻唇轮廓逐项视觉复查，不能只看总误差。
5. 需要时再用 57 区局部 XYZ 配方补细节，保持身份/局部/表情三层分离。照片看不见的侧面深度仍需额外参考或明确的造型假设。

坐标契约示例（仅说明格式，不是目标数据）：

```json
{
  "schema": "human/face-reference@1",
  "kind": "image-observation",
  "image": {"width": 1000, "height": 1200, "name": "user-reference"},
  "landmarks": {
    "pupilRight": {"xy": [0.4, 0.4], "confidence": 0.9, "visible": true},
    "pupilLeft": {"xy": [0.6, 0.4], "confidence": 0.9, "visible": true}
  },
  "notes": "其余点按实际照片填写；未观测点省略"
}
```

必须有左右眼中心，至少 10 个可见比较点才拟合；只给两个眼点会明确拒绝。输入校验点名、坐标、可信度及图片宽高。参考照片经过眼中心平移、旋转和尺度归一化，消除拍摄缩放和图面旋转；没有消除头部偏航、俯仰、不同镜头透视、表情和遮挡，不能将明显侧面照片无条件当成正面数据。

`FaceReferenceFit.mjs` 使用带范围和正则的迭代最小二乘。按区域点数平衡并按模型/参考可信度加权，42 个正面可求解参数参与，10 个深度项不求解。拟合可能得到不同但投影相近的参数；没有标尺时不声称恢复原始真实尺寸。误差单位是眼中心距离归一化的二维位置，不是百分比身份相似度。

下一步可调用 `HumanFace.identity.setReference(data)`、`await HumanFace.identity.fit()`；`HumanFace.identity.report` 和 `HumanGame.subject.identity.report` 提供当前实际数据，`HumanFace.identity.export()` 提供身份配方。网站提供特征演示、基准对比、身份恢复、配方读写、完整数据导出、图上标点及目标数据清除。

## 函数所有者

- `FaceIdentityModel.mjs`：52 项描述、纯 CPU 映射、导出的共享描述生成 GLSL、身份配方验证。
- `FaceIdentityBinding.mjs`：完整当前头脸采样、CPU 外表面与法线映射、眼部 GPU 共用映射、保护/缓存、真实标志点与报告。
- `FaceLandmarks.mjs`：82 项本人物语义种子、曲面/眼构造绑定、参考协议、置信度与照片坐标归一化。
- `FaceMeasurements.mjs`：27 项尺寸定义、固定比较投影、模型与图片的比例/误差。
- `FaceReferenceFit.mjs`：有范围和正则的可见点拟合，明确保留深度未知。
- `FaceIdentityWorkbench.mjs`：52 项交互、实际标志点显示、参考图标点、配方与报告读写、闭环演示。
- `FacialBinding.mjs`：身份映射之前的局部与表情层；每次改变后通知身份层，重置不丢失身份。
- `ProceduralEyes.mjs`：眼睑仍绑定未做身份变换的源表面，GPU 随后应用同一身份映射，避免双重位移；正面直视取消原自然会聚角。
- `SubjectRuntime.mjs` / `FacialWorkbench.mjs` / `app.mjs` / `shorts-app.mjs`：构建和模式接入，继续保留加载进度与固定正面。

## 实际检查、失败修正与证据

`tools/test-face-identity.mjs` 验证 52/82 定义、全部场的解析梯度、左右对称、非头部不动、配方范围/来源、照片平移/旋转/缩放归一化、缺失眼中心拒绝以及有限参数拟合；示例误差 0.03216 → 0.00180。

`tools/review-face-data.cjs` 使用真实后台 Chrome/WebGL2，证据 `New-Human-Production/R008/qa/face-data-r27/review.json` 保存本轮源码 SHA256、基准/演示/拟合/压力检查。PNG 是内部 QA，不代替可交互工作台交付。

- 52 参数、82/82 可绑定点、27 测量和固定正面模式均实际显示；无页面/控制台错误。
- 特征演示最大实际头脸位移 6.9183 mm，安全比例 1，最小身份雅可比 0.69435；非头部最大位移 0，原接缝组间最大差小于 0.001 mm。
- 眼中心距约 68.0 → 70.8 mm；鼻翼宽约 38.0 → 41.7 mm；口宽约 52.0 → 58.4 mm；下颌宽约 112.5 → 107.9 mm。这些是演示构造数据，不是用户参考脸。
- **现场合成目标** 82 点拟合误差 0.027608 → 0.0017067，约下降 93.8%，未拟合深度，实际安全比例 1。此测试验证数据闭环，不能代替真实照片泛化/身份复刻验收。
- 拟合预测与实际应用表面点的最大位置差约 0.0000530 mm；CPU 与 GPU 在 134 点的最大位置差 0.0000667 mm，最大法线向量差约 9.31e-7。这验证计算实现一致，不是现实人体精度声明。
- 全 52 项取上限的压力组合按 0.512 限幅，最小身份雅可比约 0.5315、最大坐标伸长约 1.7029；极端组合的外观未作为成品验收。
- 身份在微笑及表情重置后保留；闭眼、侧面和返回正面内部截图已检查；恢复身份基准后全部位置数组与检查基准逐值一致。
- 图片输入、参考坐标记录、未知点移除、空参考文件状态及数据导出通过。前两次 QA 因测试没有等待图片解码/参考读取异步完成而提前断言，已在真实完成条件后检查；没有以这些失败声称 UI 已通过。
- 原人物毛发存在折叠/明暗细线，整体头部比例变化后的截图仍可见；接缝数值一致并不证明全部毛发外观完美，未将其作为参考发型恢复。
- 源文件装配与 `node tools/check-pure.mjs` 门禁通过；注册了本轮模块、协议及测试。未修改或提交其他聊天的身体/服装成果，未发布公网。
