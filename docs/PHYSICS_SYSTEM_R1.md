# 工作台物理系统 R1

版本：2026-09-12。状态：Candidate。首版为工作台接入物品刚体动力学，使质量、重力、摩擦、碰撞和人物可用力量参与物品运动。人体姿态仍由现有动作与 IK 系统驱动，人体在物理世界中提供运动驱动的碰撞代理。

## 先行调研与来源

调研先于代码修改，参考上游官方文档与源码：

- [cannon-es World API](https://pmndrs.github.io/cannon-es/docs/classes/World.html#step)：单参数 `World.step(dt)` 可由外部固定时钟推进；工作台已有动作时钟，因此继续由该时钟统一调度。
- [cannon-es v0.20.0 World.ts](https://github.com/pmndrs/cannon-es/blob/v0.20.0/src/world/World.ts)：接触求解、重力、摩擦方程与睡眠机制的实现来源。
- [Rapier 刚体说明](https://rapier.rs/docs/user_guides/javascript/rigid_bodies/)：用于比较动态、固定和运动驱动刚体的职责。运动驱动的人体代理不能代表受到外力后自然失衡的完整人体。

选用固定版本 `cannon-es 0.20.0` 的本地 JavaScript 发布文件，保留 MIT 许可，通过 `world/physics/source-lock.json` 记录发布包完整性和逐文件 SHA-256。构建只读取与装配代码，不执行物理库；页面运行时无需下载物理引擎。没有加入模型、扫描网格、图片贴图或预烘焙动作资源。

## 世界中的变化

| 对象或过程 | R1 的职责 |
| --- | --- |
| 可移动物品 | 由质量、姿态、线速度、角速度、重力、阻尼和碰撞接触推进 |
| 固定设施与地面 | 提供静态碰撞边界，接触材质参与摩擦与反弹 |
| 人体 | 现有动作系统决定姿态，物理代理把当前姿态带入碰撞求解 |
| 搬运与推物 | 双掌提出物品目标，受力和力矩上限约束的控制器推动刚体，动作层不直接写持物的位置与旋转 |
| 松手 | 解除操纵后，物体继续受重力、碰撞和摩擦影响；任务需检查物品的真实位置与稳定状态 |
| 出错 | 人物、物品刚体状态、操纵目标、力量状态和任务状态共同恢复到上一安全检查点，并暂停 |

物体的形状由已有盒体、球体、圆柱等生成参数提供近似碰撞体。复杂道具的可见细节不等于逐三角形碰撞细节。规划阶段的几何避障继续参与路线选择；运行中的物品接触交给刚体求解。

## 时钟、力量与任务完成

物理推进绑定固定动作步长 `1/120 s`。多 NPC 共享一个世界时，由群体时钟在各人物控制更新后统一推进一次刚体世界，物理时间不会随人物数量加倍。物理层在单个动作步内最多细分 8 个微步；估计所需步数超过上限时拒绝本步并走安全恢复。这是有限的防穿透措施，尚未实现连续碰撞检测（CCD）。

所有人物暂停时，共享时钟停止。单个人物在持物时暂停，会局部冻结其手中物体：保存原速度和角速度，临时作为固定位置的运动驱动刚体；继续时恢复原来的动力状态。其他人物与自由物品继续推进。这个冻结属于编辑器的时间暂停语义，不代表肌肉以零代价托举；冻结期间物品不能通过「已支撑、已稳定」完成验收。

双掌约束的目标位置不再直接覆盖物品坐标。刚体操纵器根据位置与姿态误差、当前速度和目标变化施力，同时受现有肌群模型提供的力与力矩上限约束。可用力量扣除姿态与身体自重负担，并考虑地面牵引能力。疲劳继续按身体时间累积；无法满足力量或接触条件时触发任务失败与安全恢复。当前后端只允许一个人物占用物品操纵器，其他 NPC 需要等待该人物放置完成。

抓取前检查物品可操作状态。松手阶段需要物品得到支撑；随后等待物品稳定，并检查完整物品范围或指定目标关系。单纯到达动作时间不能认定搬运完成。等待设有上限，避免物品持续滚动时无限占用任务。

整串任务预推演仍是带力量预算的运动学预测，返回 `kinematicForecast=true`、`fullDynamicsValidated=false`。它不预先运行刚体模拟，也不能保证碰撞后一定按预测完成。

## 场景数据与使用

场景编辑器新增「离地高度」「表面摩擦」「回弹系数」字段，与原有质量字段共同组成物品物理参数。场景视图旁的「世界物理」按钮打开重力与地面摩擦设置，并提供手动刷新物品状态的入口。代码将参数应用接入现有任务空闲保护；本次没有运行页面验证这些交互。

| 参数 | 默认值 | 输入范围 |
| --- | --- | --- |
| 世界重力 | 9.81 m/s² | 0.1–30 m/s² |
| 地面摩擦 | 0.65 | 0–2 |
| 物品表面摩擦 | 0.4 | 0–2 |
| 物品回弹 | 0.08 | 0–0.9 |
| 编辑器离地高度 | 按物品当前姿态计算 | 0–10 m |

「刷新状态」读取当前物品的速度、接触支撑与稳定标记，不主动推进模拟。场景保存保留物品完整四元数 `q`、线速度 `v`、角速度 `angularVelocity` 和 `physicsSettings`，旧场景缺少的参数由规范化函数补齐。质量及物品尺寸继续沿用场景输入边界。默认线性阻尼为 0.015，角阻尼为 0.04，目前为引擎适配层的固定参数。

接触面的有效摩擦按引擎材质规则取两面的系数乘积；默认物品与地面的有效值为 `0.4 × 0.65 = 0.26`。[上游接触材质实现](https://github.com/pmndrs/cannon-es/blob/v0.20.0/src/world/Narrowphase.ts)规定了这个组合规则。力量预估中的推物阻力使用同样的乘积，人物脚底牵引预算仍使用世界地面摩擦参数。

保存的是可序列化的场景状态，不包含引擎内部对象引用；导入场景也不恢复正在执行的抓取动作或任务队列。物理诊断提供刚体状态、接触记录、操纵误差、所施力与微步计数。

| 文件 | 职责 |
| --- | --- |
| `world/PhysicsContract.js` | 单位、输入规范化、旋转后的物体范围 |
| `world/PhysicsWorld.js` | 本地刚体世界、接触、有限施力操纵、状态捕获与恢复 |
| `world/PhysicsControls.js` | 世界参数设置与物品状态查询面板 |
| `world/physics/source-lock.json` | 固定引擎版本、来源完整性和文件哈希 |
| `tools/bundle-physics.mjs` | 只处理文本的引擎装配 |
| `control/TaskAgent.js` | 固定步接线、抓放阶段、完成检查与安全恢复 |
| `control/NPCPopulation.js` | 多人共用一次物理推进、物品占用与整组恢复 |
| `body/StrengthBridge.js` | 由当前肌力状态提供物品操纵上限 |
| `tools/check-physics.mjs` | 只读源码、语法树、锁文件和打包依赖的合同检查 |

## 验收边界

按本目录 `AGENTS.md`，本次仅允许文件内容验证：`node tools/build-pure.mjs` 装配入口，`node tools/check-pure.mjs` 解析源代码与文件合同。检查不会打开网页、运行人物动作、运行物理模拟或使用 GPU，也不操作用户鼠标。

文件检查可以发现源码遗漏、状态保存丢失、错误的推进接线或来源哈希变化；无法证明实际碰撞、抓放稳定性、长时间运行或视觉效果。记录保持 `applicationExecuted=false`、`runtimeVerified=false`、`forceDynamicsValidated=false`、`visualAcceptance=false`、`productionReady=false`。本文不把候选实现描述为已通过运行验收。

R1 尚未实现全身受力平衡、跌倒和 ragdoll、逐关节肌肉动力学、软组织变形、衣物与头发物理、流体、器具内物料或破坏。刚体与肌力参数也未经过实验校准。运动驱动的人体可把能量带入物理世界，因此当前模型不能作为人体接触力、伤害或真实搬运能力的测量依据。

人体代理使用分布在躯干和四肢的球体，不包含手掌的细分碰撞。正在搬运或推动的物体排除操作者自身代理，以免运动驱动的代理绕过手力上限；仍保留它与其他人物代理的碰撞。人物之间的避让继续由导航处理，尚未加入人物之间的受力推挤。
