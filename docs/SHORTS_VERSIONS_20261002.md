# 短裤双版本开发记录

原版 A 是用户认可外形的 R24 静态版本；保留原文件的 SHA256 和固定网址，不重新生成或覆盖。新版 B 单独使用当前 R008 人物的实际生成几何量体，目标为腰线降低 55 mm、38 mm 亚麻腰头布套与独立有限弹力带。

**当前状态：开发源码，穿着与布料动作尚未通过。不能作为完成版或生产版发布。**

已验证：原版 / 新版 / 原版离线切换；新纸样面积与质量；19 条真实接缝；四个缝合阶段的终态。终态是折叠后的缝合几何，不是穿在人物上的服装，也不是已通过的物理缝制过程。

根因审查确认了两处初始化错误：裤脚纸样约 863 mm，却被旧目标压到约 544 mm 的腿围；主片腰向与横向混用，使侧腰落到错误侧。`ShortsBoundaryTargets.mjs` 已独立生成逐边等长、包围实际腿部截面的裤脚外环。`ShortsExteriorFrames.mjs` 是独立裁片外部支持面初态；它不代表已闭合的裤子，也不代表穿着或物理动作验收。旧失败记录与原制造路径保留。

GitHub 开发分支仅保存生成源码、关系、参数接口、检查脚本和状态说明。没有提交历史 HTML 构建、烘焙布料顶点、截图、预制模型或贴图。原版固定文件通过 `ShortsVersions.mjs` 中的 URL 与 SHA256 识别；构建双版本时获取或传入原文件并核对字节。

在仓库根目录安装运行时代码并构建内部候选：

```sh
cd New-Human-Production/R008
npm run runtime
npm run entry
npm run standalone
node tools/build-shorts-comparison.mjs
```

最后一条命令需要联网获取固定原版。也可以传入原版本地 HTML、候选 HTML 和输出 HTML 三个路径；生成后单体双版本文件不依赖核心网络资源。候选仍会显示未通过状态并禁用布料动作，不会自动发布。

源纸样检查：`node tools/probe-shorts-draft.mjs`。仓库根目录的 `node tools/probe-shorts-boundary-targets.cjs` 检查裤脚目标；`node New-Human-Production/R008/tools/probe-shorts-exterior.mjs` 检查独立裁片初态。这些几何检查不能替代完整穿着、身体 / 自碰撞、弹力带和人物动作验收。

后续必须完成连通裤身的连续低应变外部放置，再关闭最后腰头，执行真实站立、走路、跑步、跳跃和停止后的布料检查。通过独立验收后才晋级并更新公开测试网站。
