# 坐起准备、连续步态相位与转身指令 R24

日期：2026-09-15。开发分支：`feature/human-motion-workbench-adjustment-v1`。本轮承接 R23 的支撑脚继承与方向力量反馈，继续处理三个基础自然度问题：坐姿到起身来源不连续、步态上体相位在换脚时重定位、原地转身的角速度命令和落脚朝向不协调。

本轮没有修改 `motion/vendor/` 中锁定的 Human-Motion-Lab R2.2 文件，也没有修改肩胸表面、蒙皮权重和重建参数。新增控制均位于工作台适配层，因此原始来源哈希和 `motion/source-lock.json` 保持不变。

## 1. 显式坐姿起身准备阶段

现有 `standToSit` 的末帧与 `sitToStand` 的首帧不是同一个支撑构型。直接短时混合会同时改变手臂、腿、骨盆和躯干，不能解释为真实的起身准备。

现在在任何 `sitToStand` 之前加入内部状态 `standPrepare`：

1. 读取当前已经提交的完整坐姿骨架；
2. 保存左右脚世界锚点；
3. 用 0.72 秒把身体引导到 `sitToStand` 首帧对应的准备构型；
4. 混合期间每一帧重新执行固定骨长双腿 IK；
5. 保留脚锚和接触误差，不允许通过滑脚消化姿势差；
6. 准备结束后重新计算来源片段的根运动原点，使正式起身片段从当前根位置连续开始。

该过渡属于工程适配，不宣称为实测动作。它保存为 `support-transfer/v1`，与原始采集片段分开报告。

专项回归中的原始坐姿与起身首帧最大关节位置差为约 `0.6353 m`。经过 87 个固定步样本后：

- 最大单步关节位移约 `0.01840 m`；
- 最大脚锚误差约 `8.36e-17 m`；
- 最大骨长误差约 `3.34e-11 m`；
- 准备结束与正式 `sitToStand` 根节点接缝误差为 `0 m`。

这证明接缝已经成为可检查的支撑转换，但不等于坐起画面已经完成视觉验收。

## 2. 连续展开的步态相位

旧 R2.2 内核按当前摆动脚直接重定位动作相位。适配层现在增加 `ContinuousMotionPhase`：

- 相位使用单调展开坐标，不在左右脚交换时跳回固定相位；
- 每次新的摆脚事件只校准“录制相位到运行时相位”的偏移，不移动已经提交的运行时相位；
- 双支撑期间只要身体仍在移动，相位继续前进；
- 停止后再次启动时重新校准，避免沿用上一段行走的旧偏移；
- 仍由原 `FullBodyMotion` 采样录制数据，适配层不生成另一套动作来源。

专项测试覆盖两段行走、中间完全停稳、再次启动、19 次左右脚交换和 127 个移动双支撑样本：

- 首次启动及全部后续固定步的最大相位增量约 `0.01139 cycle`；
- 换脚时最大相位增量约 `0.00972 cycle`；
- 第二段行走重新启动的首个摆脚增量约 `0.00413 cycle`；
- 相位没有反向或离散重置。

## 3. 支撑感知的转身命令

没有改写锁定的 R2.2 转身求解器。外层新增 `TurnCommandFilter`，每个固定步只向内核提交一个受限角增量：

- 最大外层角速度 `1.0 rad/s`；
- 最大加速 `3.8 rad/s²`；
- 最大减速 `5.2 rad/s²`；
- 根据最终朝向剩余量提前制动；
- 根据当前支撑脚剩余扭转余量降低目标速度；
- 摆脚开始后，在碰撞扫掠和端点检查通过的前提下，将落脚位置和朝向前置到预计转身方向，避免每次只落到触发摆脚时的微小角度。

90°、-90°和 180°专项回归合计 1713 个固定步：

- 最大外层角速度 `1.0 rad/s`；
- 最大外层角加/减速度 `5.2 rad/s²`；
- 最大已提交根角速度约 `1.0 rad/s`；
- 最大已提交根角加速度约 `8.79 rad/s²`；
- 单次命令领先量约 `0.00833 rad`；
- 摆脚前置目标最多执行 14 次；
- 仍有 42 个支撑换脚等待帧。

最后一项必须保留：R2.2 内部仍具有支撑脚扭转闸，因此本轮降低了多余停顿和落脚次数，但没有消除真实换脚所需的等待，也没有把运动学转身描述为完整动力学平衡。

## 4. 受控腿姿势混合的扭转连续性

R23 在混合期间重新投影双腿后，膝盖代理可能因为重新从绑定姿势构造小腿朝向而在第一帧跳动。本轮改为：

- 使用混合前的股骨和胫骨世界朝向作为首选扭转；
- 只施加使骨轴对准新 IK 方向所需的最小旋转；
- 膝盖代理保持其相对胫骨的已混合局部变换；
- 脚部后代继续随脚部刚性变换。

现有蒙皮附着回归仍通过，最大附着误差约 `5.30e-8 m`，双四元数数值一致性约 `8.88e-16 m`。

## 6. 仍未解决

1. `standPrepare` 是受约束的工程过渡，不是与当前坐姿完全匹配的新动作采集。
2. 转身的脚底受力、重心、惯性和跌倒恢复仍未进入动力学闭环。
3. 连续步态相位改善了上体时间连续性，但尚未建立独立的脚跟—全掌—前掌滚动事件。
4. 手指抓握仍是箱体净空配方，不是真实逐指接触求解。
5. 肩腋 A45/T90 折叠属于表面、绑定权重和姿势补形问题，本轮没有触碰共享绑定文件。
6. 本轮只运行文件和 Node 级运动学测试，没有运行浏览器人物画面或 GPU；`visualAcceptance=false`、`productionReady=false`。

## 7. 下一步

下一轮应建立轻量的身体负载与平衡反馈层：读取物体实际外力、骨盆与躯干状态、左右脚支撑位置，输出有限的骨盆偏移、躯干倾斜、站距、步长和必要换脚请求。该层应位于动作目标和最终 IK 之间，不得修改绑定骨长，也不能由表皮层反向控制骨架。
