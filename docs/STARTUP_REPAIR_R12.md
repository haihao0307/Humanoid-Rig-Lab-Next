# 启动等待修复 R12

2026-09-12。用户截图显示等待 211 秒、页面加载完成、WebGL 可用，但渲染帧和绘制调用均为 0，阶段为连接重建人体与训练场。这说明初始化未完成；截图无法独立判断当时具体耗时在哪个计算函数。

文件审查确认：首帧等待完整重建；五个生成组的参数头声明共 6,208 个曲面分区。Worker 的详细进度只写入尚未创建的性能面板，没有进入启动诊断。随后权重扩散、分块绑定和支撑点计算仍在页面主线程执行。

本轮修改：

- 将原有绑定公式移入 `reconstruction/binding.mjs`，保持原有向量数学、三次 smooth、8 权重编码、扩散上限和精度阈值。Worker 使用页面传入的同源静态骨架计算权重及支撑点，通过 transferable buffers 交付分块属性。页面仅检查骨架顺序、属性尺寸并上传，不再重复执行这些计算。
- 共用边界已存在的分割点不一定处于边长的一半。原误差计算仍与 0.5 处插值比较，会把非中点位置差计为曲面误差，可能导致额外细分。现在位置及法线误差均使用实际、有方向的边参数。没有放宽几何误差、边长或法线阈值。
- 将参数文件、曲面分区、连接、法线、权重和上传阶段接入启动诊断；长分区按实际工作量节流报告，显示最后进度距今时间。
- 单个参数读取限 15 秒，Worker 请求连续 45 秒无进度或总计超过 120 秒会失败并结束计算；取消和正常结束均清理计时器。它们是故障等待上限，不能证明计算在特定硬件上能按时完成。GPU 上传的实际耗时仍未测量。

参考：[MDN Web Workers](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)、[MDN transferable objects](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Transferable_objects)。Worker 可将密集计算与页面线程分开；它不保证计算本身更快，也没有采用持久化显示网格缓存。

`tools/check-startup.mjs` 检查执行位置、共享源码、数学约定、缓冲传递、分割参数和超时清理。原有 R10/R11、来源哈希及启动器字节检查继续执行。当前只完成源文件装配与审查，没有执行重建、绑定、Worker、浏览器或 GPU；优化后的耗时及显示效果待运行验收。最终检查统计见 `FILE_AUDIT.json`。
