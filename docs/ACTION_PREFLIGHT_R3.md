# 动作系统 R3.1：整串预推演与流程修正

日期：2026-09-11。状态：源码已装配；只验证文件内容，未运行网页、人物、导航或 GPU。

## 本轮流程修正

1. **关节动作与等待时的体力状态**：原生执行、独立关节动作和姿势保持都经 `Agent.advanceStrength` 更新体力。关节运动按基本活动计入消耗；动作结束后保持姿势时继续推进恢复，暂停时不推进。显式等待改为读取身体实际累积时间，避免页面倒计时已经结束、身体只更新了少量时间。读取等待计时需要匹配任务预约与代次，并检查未完成动作、持物和错误状态；它不会自行推进人物或解除用户暂停。体力仍是估算模型，预判的理想休息恢复与实时残余激活过程不等同于精确生理预测。
2. **坐躺前的转身**：仅在抓取、抬起、放下和起身收手等接触阶段锁定脚步。`floorAlign` 允许迈步调整，身体旋转受当前支撑脚扭转范围约束；双脚位置、朝向和速度收稳后，才进入坐下或躺下阶段。
3. **搬运与推动的候选落点**：对每个容纳完整物体的候选落点，依次检查接近路线、人物终点、运输包络及持续力量。一处失败后继续下一处，全部失败才汇总原因。执行器使用选中方案的落点、朝向、接近路线和人物终点；抬起后从实时位置重新验证运输路线，保留选中的终点。

这些是源码层面的修正，没有运行复现或动作效果验收。

## 提交时的行为

语言、语音、确认执行、动作示例和营地活动最终都进入 `enqueueSemantic`。该入口先等待整串预推演，通过后才替换旧任务或加入队列。可选的候选方案推理开关不会关闭这一步。手动预览也会得到整串检查结果。

`control/PlanForecast.js` 在私有世界、人物状态和力量状态副本上依次检查节点。每一步把人物位置、朝向、姿势、地面坐点、物体位置及朝向、疲劳传给下一步。条件在前序预测结果上求值，保留原始条件树。预测不会创建另一套人物、执行实时姿势、生成网格或发送场景修改事件。

发现阻碍时，提交方收到第几步、动作类型、节点 ID 和原因；整份新任务不进入执行队列。检查范围包括地面导航、坐躺空间与起身站位、目标落点、可搬运尺寸、持续力量、搬运包络、直线推动时人物与物体的经过区域。最后另查声明的目标集合是否全部满足。

追加任务以前序任务的预测终态为起点，并核对场景结构。真正开始该任务时，再用实时状态检查整串指令；原生动作批次也在身体接收处重新检查。执行中仍使用原有的接触、关节范围和完成证据。

## 衔接调整

- 相邻原生动作按顺序作为一个批次传给身体，逐步报告完成。显式等待、观察、条件和独立关节目标保持各自的调度边界；有源集合条件的物体操作继续逐件核对。
- 身体更新帧结束后直接检查完成和失败。180 毫秒心跳用于状态显示，动作调度不再等待该心跳。
- 相邻步行可在路径交接处开始下一段；朝向接近时保留移动速度。到站阈值由 1 毫米调整到 6 毫米，减少末段微量挪动。
- 转入手势、坐躺或抓取时依据脚部支撑、朝向和速度判断；删除抓取前和放置前额外的固定 0.35 秒等待。
- 每步的超时按预测时长预留，并在完成反馈后重新计时。用户暂停期间不消耗该计时；持物时停止会截断原生批次，继续后只完成当前安全放置。

## 规则对应

| 提交内容或状态 | 文件中规定的处理 |
| --- | --- |
| 第一段可达，后面的目标被堵住 | 返回后面受阻的步骤，整串不开始 |
| 搬完物体后再走原来的通道 | 在物体预测新位置上重新寻路 |
| 前一步改变“是否在区域内” | 在改变后的预测状态上选择条件分支 |
| 营地旧训练场范围之外坐下或躺下 | 使用当前场地的碰撞边界 |
| 推动物体需要绕过障碍 | 提前拒绝；当前推动技能是直推 |
| 搬运长方体 | 人物加前置物体的保守包络用于预测和实际寻路 |
| 原生动作后使用未知关节角度的相对微调 | 提前要求绝对角度，避免拿提交时的旧角度当作未来角度 |
| 关节动作结束后保持姿势并等待 | 继续更新体力；等待时长取身体计时 |
| 页面更新很慢 | 身体尚未推进足够时间时，等待步骤继续保留 |
| 坐下前需要转过较大角度 | 允许双脚轮流调整，收稳后再下降 |
| 第一个落点能容纳物体，但人物或运输路线被挡 | 继续检查其他候选落点，保留用户指定的位置关系 |
| 排队期间场景结构改变 | 原有排队预测失效，报告原因 |
| 暂停时间很长 | 暂停不导致步骤计时超限 |
| 持物时停止多动作批次 | 保留抓握并取消当前放置之后的步骤 |

这张表是源码约定，不是运行测试报告。

## 文件验证与限制

执行 `node tools/build-pure.mjs` 和 `node tools/check-pure.mjs`。后者还调用 `tools/check-actions.mjs`，只解析语法树和文件文本，核对强制检查的位置、共享几何规则、分支状态传递、批次与停止边界、反馈和暂停计时。本轮增加跨模块检查：关节动作与保持分支的体力更新、身体计时与预约保护、脚步锁定和坐躺前收稳、候选落点失败后的继续搜索，以及预测终点到执行器的传递。它不调用应用的推演、导航或人物函数。

这仍是几何与能力模型下的预估：完整动力学、所有姿态的全身自碰撞、双掌 IK 收敛、动态环境变化，以及主观动作流畅度尚未验证。关节目标保留运动学预检标记。`runtimeVerified=false`、`visualAcceptance=false`、`productionReady=false`。

## 修改前调研

- [MoveIt Pilz：Sequence of multiple segments](https://moveit.picknik.ai/main/doc/how_to_guides/pilz_industrial_motion_planner/pilz_industrial_motion_planner.html)：参考先规划整个动作序列、任一段不可行时不启动整串执行的组织方式。
- [MoveIt Pro：Stitch trajectories](https://docs.picknik.ai/how_to/robotics_applications/stitch_trajectories/)：参考连续轨迹在交接处处理速度和加速度的原则。
- [Combined Task and Motion Planning as Classical AI Planning](https://arxiv.org/abs/1706.06927)：参考把任务顺序与几何可行性一起检查的方法。
- [MuJoCo：State and control](https://mujoco.readthedocs.io/en/stable/programming/simulation.html#state-and-control)：本轮参考时间、运动状态和有状态执行器共同推进的组织方式。
- [MoveIt Task Constructor：Connecting Stages](https://moveit.picknik.ai/main/doc/concepts/moveit_task_constructor/connecting_stages.html)：本轮参考候选起点与终点需要由可行运动路径连接的原则。
