# 行走足部支撑过渡与验证边界

本文的数值与截图记录截至 `62541d2`。后续骨盆全身重定向、最新构建证据及实际身体高度读取约定见 [自由行走的骨盆与全身重定向](MOTION_FULL_BODY_RETARGET_20260916.md)。

空手行走现在采用脚跟、全脚掌、前脚掌的运动学支撑过渡。落脚前轻微抬趾，身体越过支撑脚后逐渐抬跟，摆动期连续衔接脚部角度。起步前段保留第一支撑脚的平底接触，第一摆脚相位达到 45% 后允许后脚逐渐抬跟，避免一直锁平到落地而压低身体；停止后足部回平才算停稳。该实现改善了原先整步平脚的表现，但不是力驱动蹬地，也不构成整体动作自然度验收。

后续修复让骨盆随实际支撑脚踝有限上升。此前足跟滚动抬高了踝部，身体却仍受平脚参考高度限制，抬踝被额外屈膝吸收。现在生产姿态按实际支撑点及双腿可达范围计算支撑高度补偿，固定脚锚与骨长不变。补偿目标保留 12° 工程屈膝余量，按身高缩放限制在 35 mm 内，以 80 ms 响应和 0.15 m/s 补偿速度收敛；安全可达上限优先。它是运动学协调，不是对人体重心、肌肉或反力的精确模拟。

自由行走还加入随支撑脚切换的小幅横向身体转移。目标取身体与支撑点横向距离的 20%，用摆脚两端归零的包络和实际速度缩放，按身高限制在 18 mm 内；60 ms 响应与 0.08 m/s 速度上限限制突然换边。身体偏移先纳入双腿可达范围，再生成生产骨架。该转移是运动学近似，未提供真实动态平衡或抗扰动保证。

## 共享接口与兼容性

- 输入仍是任务系统提供的目标、路线、速度和交通约束。没有新增人物队列，也没有修改预约、避让、阻断恢复或任务调度。
- `NaturalLocomotion.engine.state.feet[side].position` 保留内核平面落脚参考；新增 `rocker` 给出 `pitch/kind/pivot/world/ankle`。`MotionLabPose` 从支撑枢轴推导实际踝部位置，再解固定骨长 IK，并独立检查世界支撑点。消费者不可把平面落脚参考当作滚动时的实际踝部位置。
- `report().footSupport` 输出支撑模式及左右脚状态。`TaskAgent.stats.maxFootPositionErrorM` 在滚动支撑时测量已提交脚部的支撑点误差，平脚时仍测踝锚误差；原门限不变。任务板块若展示该值，应将其理解为接触误差。
- `LightBalanceFeedback` 改用脚跟或前脚掌的支撑中心，并缩小滚动时的纵向支撑范围。它仍是有界几何代理，不能解释为真实压力中心或地面反力。
- 携物继续使用已有平脚步态和原落脚距离；私有携物预检显式传入 `{flatSupport:true}`。空手增加前向落脚提前量，目标仍经过内核世界碰撞检查。模式仅在停稳后切换，持物状态中途改变不会瞬间压平脚底。任务板块无需更改接口；后续携物滚动步态需要同步验证手部接触可达性。
- 起身继承的完整脚底姿态保持优先，第一次摆脚释放后才接入新支撑。回滚快照包含动态支撑状态。显式接触姿态覆盖滚动状态。
- `pelvisSupportLiftM` 保存身体支撑高度补偿并随内核状态回滚。内核 `root` 与平脚调度参考继续保留；`MotionLabPose` 在无显式身体/脚锚覆盖的受控步态中叠加补偿后重新解实际骨架。携物、继承接触和显式接触动作不叠加该补偿；停稳交接等待补偿归零。
- 高度诊断 `method` 为 `rolling-support-reach/v2`；`currentM` 仍指内核参考高度，新增 `supportLiftM`、`bodyRootM` 和 `supportResponseS`。任务目标和水平路线无须改动；展示实际身体高度时应读取 `bodyRootM`，实际交互接触仍以已提交骨架为准。
- 新增 `pelvisSupportXM` 为身体局部横向偏移，随执行快照回滚；`report().weightTransfer` 给出偏移、上限和 `stance-contact-transfer/v1` 方法。导航 `root`/路线没有横移，实际骨架会偏移；任务板块进行精细身体占用检查时应读取提交骨架，不能将路线中心当作所有部位的位置。携物、继承接触、显式脚锚/身体位置不叠加该偏移，动作交接等待偏移归零。群体近距离通行与侧向身体包络需要后续联合验证。

## 后续方向与未通过项

1. 起步屈膝峰值及横向身体转移已改善，但躯干、肩肘与步态仍需协调；当前最大承重屈膝约 32°，不代表所有换步均自然。不要把角度回归等同于完整自然步态。
2. 用实际足底皮肤轮廓校准脚跟/前脚掌代理，再复核不同体型、低速、急停、转弯和携物的接触；不要用骨架误差替代皮肤接触验收。
3. 继续改善坐下/起身的臀部支撑、前倾和手臂过渡。本轮没有解决这些已有视觉问题。
4. 针对多人路线交汇、频繁走停和并行动作测量帧耗时、更新预算及碰撞阻断恢复。6 人挥手仅是功能回归，不能证明大量 NPC 自然并行行为或性能达标。

研究依据：[Usherwood 等关于 heel–sole–toe 与行走机制的论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC3427509/)。这里只采用支撑阶段的概念；代码角度、时间和枢轴尺寸是工程调参，不是论文的生物力学校准结果。

横向配合参考：[Wang 与 Srinivasan 关于身体状态与下一步横向落脚关系的实验研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC4190959/)。本实现只加入有限身体偏移，未复现论文的步位预测模型或人体稳定性结论。
