# RF07 · ECS / 流式加载运行时：大世界方向存档，当前范围不扩大

原排名第7。原名保留“大世界运行时”，但当前用户范围仍仅人物与服装。此档案不授权地图、建筑、飞机、动物、植被或完整世界开发；未来也先做人物/服装小实验。

## 1. 痛点与为什么排在后面

当每个人物、每件衣服和每个面板各开循环、各载资源、各做物理，后台和静止对象也可能消耗预算。重复加载与过时任务会放大等待和内存成本。

ECS将实体身份、组件数据和处理系统分离，流式加载则管理资源何时准备、保留和释放。这可以帮助调度，但不会自动解决慢shader、重物理或错误生命周期。没有多对象瓶颈证据就做全局重构，可能只增加复杂度。

## 2. 老师与边界

Flecs展示组件查询、系统、流水线顺序与读写同步点；其查询文档也明确讨论缓存与管理开销的取舍。[S16][S17] OpenUSD的payload提供按需场景内容组织的参考，但不是浏览器中的实时预算调度器。[S01]

我们优先学习数据/依赖/生命周期设计。是否采用Flecs或自有TypeScript数据调度器，要由小型对照证明，不因采用C/C++库就假定更快。这里不默认增加任何新运行依赖。

## 3. 接入人物体系的设计

实体持有稳定entityId与assetRevision，组件只引用必要状态，例如HumanIdentity、RigBindingRef、PoseRef、GarmentBinding、MaterialRef、InteractionRelevance、ResourceResidency、DirtyGeneration和TimingStats。

主体系的绑定数据与finalPose仍有唯一权威。ECS不是另一套BodyDNA数据库，也不能让SkinSystem和PhysicsSystem各自覆盖最终姿势。系统顺序必须显式：接收输入 → 动作/行为目标 → 既有约束/物理 → 最终姿势发布 → 蒙皮/服装更新 → 显示提交。实际项目顺序先核对源码，不从本文伪代码直接替换。

UI刷新与三维刷新分离；不可见面板降低/停止绘制，但正式状态和任务取消仍须处理。异步结果携带assetRevision、proportionRevision、generation；过期结果不可更新新对象。

## 4. 连续需求，不等于无条件降质

建议计算workDemand=f(屏幕足迹、交互相关性、动作/接触状态、误差预算、资源可用性)。相机距离仅为一项；被持握、受力或即将进入接触的对象，即使不在画面内也可能需要保留物理工作。

调度可以让需求与权重连续变化，但网络块、任务、内存分配和物理子步仍离散。需通过稳定的任务合并、取消和资源滞留策略抑制抖动，不使用固定距离档位整件换模。保持既有真结构，不以突然纯色或粗模替代被认可的近景材质。

当前不新增动作缓存。可以讨论资源去重、已加载纹理复用和生命周期，但不能把它们偷换成预烘焙动作替代真实物理。

## 5. 资源身份与卸载安全

拟议ResourceHandle包含contentHash、sourceRevision、visibility、dependencyRefs、refCount和generation。同一内容可复用，私人解密资源只能留在有权限的作用域，不能为跨窗口共享而公开缓存。

卸载前确认无活动抓取/接触依赖、无待应用事务、无引用者；释放GPU/CPU/Worker资源并记录取消。需要重新加载时从完整权威状态恢复，不能仅把模型重新放在原地冒充物理状态延续。

冻结/简化某对象的模拟必须是已定义的运行策略；镜头离开不代表可以丢失速度、接触或任务状态。未实现可靠恢复时宁可报告成本限制，也不能无声重置。

## 6. 首轮最小实验RF07-P0

第一轮只做只读性能归因：针对已有一个人物与一件衣服，记录动作采样、约束、物理、蒙皮、GPU绘制、UI和资源加载各自成本，区分冷启动与热运行。可增加一个后台观察页验证重复工作，但不复制一个完整人物引擎当“共享成功”。

只有诊断发现调度/重复资源是实际瓶颈，下一阶段才建立独立小型数据调度候选。逐项改：唯一时钟/按需绘制、重复请求合并、引用生命周期、过期结果拒绝。不能同时重写人物、材质和物理后宣称收益来自ECS。

后续再扩到两个或少量人物，保留同一资产、设备、画质与动作进行基线对照，不用几十万个空实体的微基准代替完整人物系统。

## 7. 验收与收益定义

同机交错比较P50/P95帧耗、交互处理等待、分阶段CPU/GPU耗时、内存峰值、冷启动字节、重复实例/纹理/Worker数量与连续切换后的资源计数。GPU软件后端、桌面/手机视口和实体设备结果分开。

必须测试后台/前台切换、窗口关闭、快速选择人物/衣服、加载取消、重复返回、上下文丢失及私有资源不越界。保持原几何与同条件输出，物理轨迹差异必须落入预先定义的误差边界，而不是允许任意视觉接近。

收益成立至少需要减少真实重复工作或稳定降低一个已定位阶段成本，同时不把成本转移成不可接受的加载延迟、峰值内存或输入迟滞。没有收益则不迁移。

## 8. 约束与停止条件

普通人难点是明确资源所有权、依赖和系统顺序，以及在异步浏览器中保证取消/恢复不冲突。缓存查询会占内存，频繁增删组件也可能造成管理开销；换成ECS不是零成本。[S17]

如果瓶颈仍在单个高成本shader或求解器，先回对应专项。必须导入完整大世界才能演示、必须降低材质质量才能提速、出现状态失步/重复写入/资源泄漏，均停止本轮晋级。
