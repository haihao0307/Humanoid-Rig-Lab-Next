版本 RF-HANDOFF-20261018-R1。范围：人物、服装、裁缝/裁片、布料/皮革、鞋履，以及它们的局部交互。当前任务：把剩余高价值框架的逻辑、原因、接入方法、风险和后续任务保存到 GitHub。

2026-10-18 的历史讨论先对七个方向排序，随后用户选择第一名“现实世界契约与验证实验室”。目前已推进到 REALITY-HC-S3。用户现在要求保存其他方向，方便在其他窗口调用，而不是继续本窗口的 S3.1 开发。

历史检索恢复的原顺序如下。逐字原回答及完整原始链接清单没有恢复；下面的工程设计、试验拆分和本轮查证的来源均标记为本轮整编。不得把新增细节倒写成用户以前已经批准的实现。

|---|---|---|---|---|

## 2. 六项不是一件事

以同一件人物穿着的牛仔裤为例：RF01记录毫米尺度、裁片身份和未知物性；RF02保存款式、面料、磨损和版本组合；RF03根据带标定的证据求局部尺寸；RF04处理同一织物随观察足迹变化的视觉表达；RF05定义手能够抓住哪一片、何时算拿起或放下；RF06计算约束和接触；RF07管理这些计算何时运行、哪些资源需要驻留。

关键区别：S3中出现“材料厚度”不等于RF02已完成；增加MaterialX不会自动生成针织结构；低残差不等于真人参数唯一；播放拿取动画不等于真的拿住；采用XPBD不等于永不穿模；ECS也不等于自动加速。

## 3. 共同闭环

建议所有未来实验遵循：观察源与基线冻结 → 提出一个可被推翻的假设 → 明确允许改动 → 实验 → 与未改基线比较 → 报告失败和未知 → 用户验收 → 经单独授权再进入生产。

这里的“系统理解”采用可操作定义：能区分对象的结构、参数含义、适用条件和失败边界，并在可重复测试中预测或检查关系。不是给对象写一段自然语言就证明它理解现实。

## 5. 不应混淆的完成状态

本文档包的完成条件只是“文件已存入GitHub、名次与范围齐全、入口可检索、内部链接和登记可核对”。它不代表六个框架已经跑通，不代表新的网页交付，不代表全部内容已经进main。

RF01的历史网页回执只证明对应固定构建的测试。未来窗口必须重新读实时分支，再决定续做、复用、迁移或保留；不能凭本文件永久称某个R编号为最新版。

## 6. 推荐的先后关系（设计，不是新的开工指令）

先利用RF01现有只读证据并补好S3.1导出语义/共同协议映射。RF02可先做无损资产清单，RF04可做保持原外观的受控尺度实验。RF03必须先准备足够可辨识的证据。RF06先整理求解器接口与保护基线。RF05使用现有动作和物理能力做一个小交互，不以框架名替代这些能力。RF07等待有多对象调度瓶颈证据后再试验，不先把工作台改成大型游戏引擎。

没有采用不代表不重要；延后往往是因为先决条件尚不满足，或者迁移成本大于当前可证明收益。
