# RF05 · 世界语义 / Affordance：从物件身份到可验证行为

原排名第5。当前仅保存设计；不在本轮新增行为引擎，不扩展到建筑、飞机或整个世界。这里的Affordance指“某个人物在某种状态下，借助对象的具体结构能完成什么”，不是给物件贴一个动词标签。

## 1. 为什么对人物项目重要

人物的长期目标是执行行为，而不是只播放动画。衣服可以被穿、抓、放下，但每种操作依赖不同条件：袖口能否通过手、抓点属于哪片材料、衣服是否被夹住、手是否已经占用。鞋也不能仅凭外部包围盒判定可穿。

本框架的价值假设是把行为成功条件显式化：系统知道缺了什么、为什么拒绝、下一步需要哪一个结构/物理事实，而不是动画播完就报成功。

## 2. 老师与适用边界

BDDL展示用对象、初始状态和目标谓词描述任务，并由仿真后端实现和检查谓词；目标描述本身不决定具体动作过程。历史bddl-100仓库现为归档，当前相关研究入口转到BEHAVIOR-1K。[S11][S12]

我们学习“目标由状态定义、谓词需落到实际检查”这一方法，不迁入整套机器人环境，不下载它的资产来替换人物，不假设其动作或数据许可自动适用于本项目。

## 3. 建议的分层关系

ObjectIdentity保存“它是什么”；SemanticPart保存“哪些部分承担作用”；AffordanceSpec保存“谁在什么条件下能操作”；SkillPlan保存“执行次序和失败恢复”；MotionGoal保存身体目标；既有运动/物理层返回最终状态；PredicateEvaluator根据真实观测判断完成。

语义锚点需绑定partId、rest/material reference、局部框架、sourceRevision和变形映射。不能把一个屏幕坐标或旧世界坐标永久当衣服抓点。更新人物比例、裁片拓扑或衣服版本时，相关锚点应失效重验。

能力是agent × object × state的关系。例如graspable不仅取决于衣服标签，还取决于人物手部可达域、手部占用、目标形态、碰撞与已有抓取约束能力。wearable同样需要版型、人体比例和接触条件；它不是通用“可穿=true”。

## 4. 第一条行为链应有多小

RF05-P0先选“现有手部能力读取一个已有布片抓点，并解释当前是否可抓”。第一阶段只检查条件，不产生新动作：锚点存在且版本一致、手部有可用通道、目标在可达候选范围、对应物理接口存在。缺少接触证据返回UNKNOWN，而不是猜TRUE。

第二阶段在明确授权后做“拿起并放回一个已有布片”的候选：预检查 → 请求资源占用 → 既有动作接近 → 真实抓取约束建立 → 提起 → 放回实际支撑面 → 释放约束 → 检查稳定 → 完成。不得创建新人体替代当前人，也不得用父子挂接伪装物理抓取。

原台没有真实抓取能力时，该行为停在缺能力报告；先派单补底层，不用动画填空。完整穿外套、系鞋带、复杂职业任务放在后续。

## 5. 拟议协议

AffordanceSpec至少包含affordanceId、objectId、objectRevision、partRefs、agentCapabilityRequirements、preconditions、resourceClaims、goalPredicates、failurePredicates、recoveryPolicy和evidenceRefs。

PredicateObservation至少包含predicateId、arguments、truth（TRUE/FALSE/UNKNOWN）、method、timestamp、sourceRevisions、tolerance与reason。它与RF01的PASS/FAIL/WARNING/UNKNOWN/NOT_APPLICABLE不是一组词，必须显式映射：目标FALSE只说明当前未满足，不自动意味着产品有缺陷；UNKNOWN表示缺证据。

任务状态可采用IDLE、CHECKING、RUNNING、BLOCKED、SUCCEEDED、FAILED、CANCELLED；这些是拟议流程状态，也不能冒充验收认证。任务成功必须绑定最后一份实际观察，超时不能写为SUCCEEDED。

## 6. 真实检查与反例

“拿起”至少有抓取约束建立与物件实际运动证据；“放下”需要支撑与释放后的状态证据。具体接触误差和稳定观察窗口在实验开始前登记，不能事后修改阈值配合录像。

必须包含：目标过远、抓点已失效、另一只手/另一人物已占用、物体仍受夹具限制、动作被取消、接触丢失、页面关闭/恢复、源版本改变。禁止用“屏幕上看起来接近”代替接触，也不能把动画完成事件当成功谓词。

收益应对比旧流程中的假成功次数、失败解释完整度、同一个技能迁移到另一个兼容对象所需修改、用户纠错次数。不能只统计能播多少个动作。

## 7. 对主体系的保护

行为层只给MotionIntent/MotionGoal和接触目标，不直接改骨骼绑定或Skin。最终finalPose仍由现有运动与物理顺序产生。行为失败需要释放占用和约束，不能留下幽灵抓手。

RF01负责语义定义/证据和缺陷；RF02提供对象与组件身份；RF03可帮助估计部分锚点但未知需保留；RF06提供已验证的接触反馈；RF07以后调度行为评估但不修改完成条件。

## 8. 成本和停止条件

普通人难以快速完成的核心是把自然语言词义落到可计算几何、角色能力和后端检查，以及维护失败恢复。仅有分类本体或语言模型，不足以提供这些能力。长任务还有并发占用、异步状态、动作可达性和误差累计成本。

当系统必须伪造碰撞、强行穿模、直接改比例或忽略失败才能“完成任务”时停止。保留语义检查和BLOCKED理由，把缺的能力送回源工作台。先做好一个可解释的小行为，比登记几十个空技能更有价值。
