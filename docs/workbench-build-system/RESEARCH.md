# V1.1 复刻优先的研究方法

返回[总入口](../../WORKBENCH_BUILD_SYSTEM.md)。本册按2026-10-10用户最新方向修订，不再要求完整理论分析先于网页复刻。

## 先选效果，再选能抵达效果的路径

真实画面和实际操作先于功能列表。选定符合用户目标的顶尖样本后，迅速查清作者、来源、许可、运行入口、必要代码/资产/参数和可用环境。近期项目的学习经验优先，外部老师不因论文年代较早自动被排除。检索不使用中国网站来源。

同一个目标可以有多位老师：一个提供完整视觉目标，一个提供可读内核，一个补特定工艺或行为。不能因容易移植就把质量较低的实现偷偷换成视觉目标。

## 两条实现路线并行考虑

可直接使用：先按许可及本任务授权保留有价值的代码、资产、配置与渲染条件，跑起原例并放入自己的网页。不要为了“纯原创”重新写一个更差版本。依赖检查、隔离试跑和版权说明是最低必要工作，不是完整解析项目。

不能直接使用：自行查论文、源代码、节点图、公式、示例输入输出和配置关系，寻找可替代技术老师；将有依据的原理转成最小实现，持续对照原目标。只有演示时可研究可观测行为，不能声称取得了隐藏源码；公开信息不足就保持缺项并补查，不编造精确内部方法。

两条路线都以网页实际效果为参照。代码直接复用阶段不等于知识已掌握；研究重实现也不必声称数学等价或逐像素一致。移植、桥接、预计算加实时展示的实际边界必须明说，不能把视频播放当可交互实现。

## 先冻结，再拆解

复刻基线只读。固定对象、输入、镜头、灯光与版本，逐项关闭或替换几何、颜色、法线、粗糙度、细节、光学或运动层，观察哪种差异来自哪一项。不能同时改变多个条件再事后编解释。

把“看懂了”变成可检查的知识：效果位置、产生它的源码/数据、参数入口、依赖、合法变化、失败例和验证命令。说明老师资产贡献与算法贡献，不能只复制shader却把高质量扫描提供的细节归功于算法。

## 持续学习由实际差距驱动

首轮搜集只求足以动手，不求资料齐全；每次比较发现缺口，再围绕缺口继续搜索。新老师先在隔离实验里证明有用，再引入候选，并复查原能力没有消失。

连续失败时由执行端复核：目标是否可观测、资料是否足够、语义/单位/坐标是否一致、表示是否支持所需细节、环境是否可运行、测试是否只看代理指标。更换技术路线不等于擅自更换用户对象或降低质量目标。

## 来源记录保持诚实而轻量

每项只需清楚记录URL、作者/项目、访问日期、版本、已取得的内容、许可、实际运行结果和对应能力。区分仅看演示/摘要、已读全文、已读源码、实际运行；区分直接复用、适配、独立实现与仅作标杆。

不公开分发许可不明的资料，不把商业资产改名为自己的原创资产。用户已有明确资产限制的母体保持限制；允许资产实验的工作台单独记录范围。知识可用和文件可再分发不是同一个问题。

原始复刻、拆解实验、自主变体三者分开；每项已学能力保留可重复输入、输出与失败条件，下一台直接继承能力而不重复研究同一件事。
