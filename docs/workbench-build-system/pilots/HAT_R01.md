## 对方法的七项补充

**P1：老师分层，视觉门槛不得被易获取性替代。** 本轮选择可运行且许可可追溯的MakeHuman帽型作为源例，但缺少证明其达到用户顶尖目标的强视觉对照。下一次把“视觉标杆”“可执行源例”“补缺技术老师”分别登记；可执行不自动晋级视觉标杆。在首个源例出来后就检查最大差距，避免先扩很多款再发现老师上限不足。

**P2：先复刻不是只拷网格与图片。** 本轮遗漏原材料颜色倍率导致过白；后续读diffuseColor并恢复后明显改善。导入清单应覆盖控制笼/细分设置、UV、材料数值、启用开关、纹理角色、原灯光/色彩处理及当前无法移植部分。原渲染器未移植时名称应为“源数据复用/浏览器适配”，不能改名一比一完成。

**P3：包级许可与文件级许可都要读。** 同一官方归档中部分文件头与包标签存在冲突；本次排除冲突项，而不是自行选择对自己方便的解释。不再分发不明确项；局部隔离不停止其余合法工作。

**P4：数据取得成功与数据语义正确分开。** 头形接口曾成功返回，却因Z-up误读为Y-up得到不合理尺寸。新增轴、单位、头部实际几何范围、纯旋转距离保持和身份差异检查。人没有变小，但帽子仍可能不贴合；不能把坐标修好升级为接触认证。

**P5：静态配件适配不能只用全库同一原点。** 不同原作者人体/帽口参考不同，简单仿射可以作为第一轮观察，但要按来源建立可追溯参考系和帽口对应，再做几何接触检查。本轮空顶帽仍有相交，当前规则只是识别缺口，未完成接触求解或生产认证。

**P6：公开包装层也属于实际交付路径。** 首轮file://成功，公网虽能显示却因数据script被包装器执行而报错；本轮将静态数据改为非可执行容器并重新验证。不能忽略错误或拿本地通过替代公网；公开的不是裸HTML时需测试整个实际入口。

**P7：证据文件也受仓库规则影响。** 原QA图片被全局ignore，临时artifact有图不等于长期GitHub可查。本轮用独立QA目录例外持久化，绑定source/build与哈希，同时保留失败。产物/测试脚本/报告和实际观察各自记录，不以branch或测试数量算视觉进度。

## 对日常执行的修正

“参数由执行端管理”本轮只完成有限字段和单项证据，尚不是全部设计空间；继续按PARAMETERS.md检验关键交互并优先形成真正有意义的可复现设计，而不是以6色×11款乘法宣称66种独立合格产品。

对话中没有技术性澄清打扰用户，但状态消息较多；以后只在有实质变化、关键风险或确实需决定时报告，不把每个构建阶段都当审核请求。用户反馈记录只写真实发生的意见，不预填接受。

新框架规则应由观察支撑并带状态。本案例支持P2/P3/P4/P6/P7所述已发生故障与对应修正；P1顶尖筛选、P5接触与最终质量仍待新实验，不编成“已全面解决”。
