# 质量门槛、反例与真实交付

> V1.1顺序说明：本册作为随任务使用的工程/验证附件，不再要求先完成通用架构或全量结构谱才做网页复刻。制作顺序以总入口为准：先保住顶尖参考效果，再拆解、掌握参数、构造变量和固化；已验证保护规则保留。用户指定先静态时，不提前扩大物理任务。

返回 [总入口](../../WORKBENCH_BUILD_SYSTEM.md)。以下按任务适用，不强迫一个纯文档任务伪造三维测试。

## 1. 先定义“顶尖”的观察条件

锁定比较对象、视角/焦距、画面占比、灯光、曝光、色彩处理、分辨率、运动片段和设备。材料至少要有中性检验、掠射、反面/边缘和近中远距离；有动作的对象需要连续过程与接触状态，不只一帧。不能把离线老师的无限采样画面与实时工作台成本混为一谈。

自动图像差分用于找退化，不是天然的美感分数。同一物体换镜头、亮度或肤色也能大幅改变像素；先控制条件，再解释差异。Playwright官方也明确渲染会随OS、浏览器、硬件等环境变化，因此跨环境不能无条件沿用逐像素标准。来源见registry的EXT-VISUAL。

## 2. 七类证据独立记录

Contract：对象、授权、参考与保护内容正确。
Source：真实相关源码改动及可复现构建。
Structure：轮廓、尺寸、拓扑、厚度、边界、语义及静态约束。
Interaction：实际控件改变真实输出，恢复/导出/失效行为正确。
Dynamics：有因果的运动或求解、接触、稳定性及适用工况。
Public：固定HTTPS页面实际渲染、主要交互与公开字节对应。
Acceptance：独立复核和用户明确认可的范围。

它们不是一个可互相替换的PASS。代码通过不升级视觉，静态通过不升级动态，公网通过不升级实机，自己重复看一遍不叫独立验收。无法取得独立复核时显式标为待复核，不虚构另一位专家。

## 3. 必须让测试有能力发现错误

测试应包含至少一个应当失败的反例和一个正确控制。闭眼眼球可见像素为零时，要确认眼球没有被隐藏、睁眼能检测到；衣缝的针位重合还要检查整段边缘与厚度；尺寸检查量最终变形几何，不只读输入值；参数按钮变色不代表三维结果改变。

使用与实现不同的观察方式：源码不变量 + 独立几何测量 + 真实画面，而不是同一公式算结果又给自己评分。相同拟合目标上的小残差不提供外部真实性。

回归至少保留：原用户缺陷、被保护旧能力、参数边界、无效输入、保存恢复、过期结果、相机切换、实际首屏、资源失败和移动视口。可先用少量代表工况，明确覆盖分母，再逐步扩展；不把有限采样写成全局无碰撞证明。

## 4. 分领域的首要检查

人物/眼睑：固定绑定与身份；最终蒙皮；完整组织而不只是边缘；多程度闭合、侧仰视、重复恢复；真实睁眼资料不足时限制身份恢复主张。

材料/皮革/牛仔/毛发：真实尺度、厚度/截面、正反面、部件连续性、不同灯光的响应、中远景过滤、动态时材料坐标；外观参数与物理参数分离。

服装/鞋履：原人物版本、实际纸样和组件身份、量体失效规则、缝边与缝份、材质坐标、体表/自接触；静态上脚或展示模特不提供动态穿着、压力、舒适度或可生产认证。

动物/行为：物种与身体结构、关节来源、相位传播、接触、环境反馈；来源通道的工程限位不是生物学常数，孤立扑翼不是完整生命行为。

环境/建筑/地形：统一单位、坐标、时钟与权威输入；资料分辨率、岸线与拓扑；不将未知潮流/地貌自补为观测真值，不拿接口测试冒充场景集成。

## 5. 性能是实测约束

分别记录加载字节、首次可交互、主线程/求解/GPU耗时、帧时间分布、峰值内存、网格/绘制次数和长时间变化。没有GPU计时就不把CPU提交时间称帧率。实例化减少重复存储，不意味着几百万三角形没有成本。手机视口不等于手机温升、续航或显卡性能。

预算写入具体任务，不给所有工作台统一承诺60FPS或1MB。桌面/移动、近景/群体/高质量模式可有不同预算，降级与精度必须公开，不能悄悄删掉目标结构。性能优化要保留同源表述并重新比较视觉。

## 6. 发布核验

确认source/build/release身份；核对原基线与保护路径差异；在固定公开页面加载真实资源、检查正确版本与非空首屏；实际点击主要控件并检查输出；核对公开字节或关键资产哈希；分别记录桌面、手机视口和实机。必要的离线HTML另跑断网/file://测试。

HTTP 200、按钮存在、CI整体success、某个job被跳过、只打开本地拦截页面，都不是完整公网验收。必须查看关键步骤与实际报告。不覆盖旧网址，不用失败后的旧缓存假装最新版本。

对外状态：未完成、可审查候选、当前范围已接受。出现部署/权限/运行阻塞就写“交付未完成”及原因，并留下已完成内容，不用截图或压缩包替代承诺的网页。

## 7. 向下一轮积累

把一次重要用户纠错变成：失败输入、错误现象、对应部件、根因或未知、检测方法、受保护能力、允许改动及固定证据。两次同类失败后复审方法和数据，不放宽阈值来过门。

用户接受记录绑定明确版本和范围。原手掌接受不自动覆盖肩颈；某款静态接受不覆盖60款动态穿着。独立审核、用户接受及真实物理验证必须各自有证据，不用一个布尔值串通全系统。
