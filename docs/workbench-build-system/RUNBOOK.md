# 新执行者与自动搭建接手规则

返回 [总入口](../../WORKBENCH_BUILD_SYSTEM.md)。这不是定时任务，也不表示任何后台自动生产已经启用。

## 第一轮实际执行

读取用户最新要求、根AGENTS、总入口、registry和目标工作台的README/实际manifest；读取当前GitHub分支和相关源码。先确认是否已有母型、被接受范围或被拒绝父节点。继承正确能力，不继承被明确否定的可见替代物。

初始化或更新一个TASK，记录本轮首要缺陷、输入输出、保护路径、参考、预算、门槛和下一条命令。有明确任务时立即执行读取/测量/源码修改/实验，不只回复计划。缺字段先从可访问仓库和已给资料补齐，不重复问用户已经回答的问题。

只有研究范围/目标真正不可确定才保留阻塞。真实工具限制要写明已尝试什么、得到什么、哪些未做；不要用“已保存文档”“已开分支”代替三维工作。

## 工位职责

协调/研究工位负责找老师、解释差距、选择表示、拆解任务与管理共享协议；生产工位执行冻结后的局部变化；验证工位独立看合同、源码差分、反例、画面与证据；集成工位维护单一权威状态和真实用户入口。没有独立执行端时，不得冒称已与其他专家开会或已获独立批准。

每个工位一次一个首要问题，独立路径可并行。当前缺陷完成后按已有nextAction继续，不要求用户反复说“继续”；但不能自行扩展授权范围、改模型、放宽门槛或新增收费服务。

## 状态及转移

DRAFT/LOCKED → WORKING → CANDIDATE → VERIFIED → ACCEPTED_SCOPE。

报告文档、源码、网页、物理和视觉分别记状态。HOLD_LOCAL只阻塞依赖该缺陷的工位；ROOT_CAUSE_REVIEW触发重新检验参考/方法；BLOCKED记录真实工具或数据障碍；REJECTED不成为新生产父节点。用户未接受时不写ACCEPTED_SCOPE。

以上是信息模型，不是每个状态都要新增一个文件。一个当前TASK、一个当前回执、一个HANDOFF加按版本存的必要证据即可。不要制造几十个几乎重复的R版本说明。

## 可复制的执行任务条

> 按仓库 WORKBENCH_BUILD_SYSTEM.md 的固定版本执行。先读目标工作台实际README、manifest、source入口、最新用户要求与已接受范围，核对GitHub当前head。继承正确基线；只在allowedPaths处理当前primaryDefect。先补足本缺陷所需的一手参考并注明实际读取/运行程度，再通过最小实验把老师知识接入原内核/适配器。不要重建另一个替代对象。每轮真实修改后执行正负对照、受保护功能回归和同条件画面检查；连续两次失败复审根因。交付时绑定source/build/public/QA版本，提供真实可操作的固定HTTPS入口并说明未通过项。只有用户明确接受的范围才晋级。保持Draft，不合并、不强推、不重写历史。完整下一步写入HANDOFF，不让我重新讲历史。

将目标、路径和基线填入TASK后使用；不要把这段模板本身当成当前任务已锁定。

## Python工具的边界

`init`只生成研究/任务/交接记录，不生成占位HTML、不上传GitHub、不执行第三方代码；已存在目录拒绝覆盖。初始化合同为DRAFT，回执为NOT_DELIVERED。

`check`验证回执身份、输入时间、证据文件与哈希、必需检查、独立复核字段，以及公网/实机/用户接受主张之间的基本一致性。错误或缺证据返回非零。它不能证明报告内容真实、URL当前可达、图片好看或阈值合理；这些需要实际验证者。不得把通过本脚本称为工作台质量通过。

`lint`核对本方法论包的文件、JSON、相对链接和源索引。本方法论CI只运行它及单元测试，不运行或改动其他工作台。

## 其他仓库接入

固定本方法版本和commit，在目标仓库自己的AGENTS或START_HERE中加入指针，并让任务显式加载。保留该仓库更严格的领域规则；存在资产或交付策略冲突时先记录当前适用授权，不擅自以本通用手册覆盖。

本轮只建立本库入口与Draft变更，不等于所有Mother自动采用。不安装新代理、不创建定时器、不自动合并PR。后来升级方法论也要记录变更并回归，不能让旧任务执行期间规则静默漂移。
