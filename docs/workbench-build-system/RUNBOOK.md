# V1.1 执行端自主制作，用户审核

返回[总入口](../../WORKBENCH_BUILD_SYSTEM.md)。用户的一句目标是启动输入，不是要用户补完研究计划。以下是执行合同，不表示后台自动生产服务已经安装。

## 日常职责由执行端承担

执行端自行读取最新要求、现有代码/成果与允许范围；找到优秀老师并判断可复用性；搭起忠实复刻网页；冻结基线；拆解原理；探索参数、组织变量、生成预设；管理构建、提交、依赖、测试与交付。遇到技术问题继续查资料、做实验、修源码，不能只返回方案或把参数交给用户调。

研究、生产、诊断和集成是执行端内部可调度的职责，不意味着每一步必须另请用户指挥。较早Factory规则不应阻止当前任务授权的自主研究。真实独立复核仍应如实记录；同一助手自查不能改称另一个专家已经批准。

## 从一句目标到执行

先在既有仓库核对上下文，复用近期已掌握的有效方法。不需要完整架构才启动；先找最匹配的顶尖样本，选能够直接复用或研究移植的路线，开展当前最能消除不确定性的实际操作。

已有参考直接用；没有参考则自行寻找并制作可审查候选。一般实现选择由执行端决定。只有审美方向实质不明确、需要新费用/数据授权、扩大范围或动到受保护内容时，才把最小决定交给用户；不能把“缺一个库”“构建失败”“参数不好调”当成人工审批事项。

## 审核点少而有意义

默认在三个关键节点请求人工判断，可按任务合并：原效果复刻候选是否忠实；参数化后的代表性变体是否符合目标；整合后的工作台是否达到本轮要求。用户已有明确认可的节点直接复用，不重复请求。

审核包给固定网页、原参考/复刻基线/当前候选的清楚身份、已测交互、主要差距及本次要判断的问题。正常构建/加载/基本交互错误应先由执行端排除；不要让用户成为第一层程序测试员。

用户否定后，执行端把意见转成具体缺陷，自主排查、修复并复测；用户无需提供算法。等待审美审核时可继续不依赖该结论的研究和试验，但不能把未接受结果提升为认可基线或覆盖旧版。

## 主动找办法，但不无限空转

观察差距→提出假设→找针对性老师/实验→改代码→复测→决定保留、回退或换路线。相同局部两次无有效改善，进入根因复审，不再照原路小幅盲调。记录已尝试方法和下一条实际操作，轮转独立工位；不得用放宽质量标准制造成功。

开始一个已授权的任务后，不必每执行一步都等用户说“继续”。会话/工具中断时保存当前状态和下一命令，恢复后重读当前head与输入再继续；不得声称没有实际执行环境时仍在后台运行。

## 参数与文件的默认归属

执行端维护参数地图、依赖、有效范围、失败组合和完整配方；用户通过预设与效果表达意图。预设可复现，依赖变更使旧结果失效。底层参数可供查看，但不是把调试劳动转给用户。

复刻基线只读，实验候选另存；逐块提炼，不丢失原代码、参数、资产许可或版本信息。同一任务继续原分支，以快进提交和Draft PR记录，不自动合并、不强推、不改写历史。当前方法修订不改变其他生产分支。

## 可直接给下一位执行者的任务条

> 我要制作【目标工作台】。先读取本仓库WORKBENCH_BUILD_SYSTEM.md的V1.1固定版本，以最近形成的复刻优先方法执行：自己找顶尖参考，能按许可和任务范围直接使用的先复用并在自己的网页还原效果；不能直接使用的主动研究公开原理和代码，再忠实重实现。保住复刻基线后逐层拆解、掌握全部相关参数、组织有意义的变量与预设，逐块固化为可控制和可迁移的能力，继续向外学习补短板。资料搜集、技术路线、调参、排错、版本管理和自检由你负责；我只审核关键视觉/功能结果。交付真实固定HTTPS网页及清晰差距，不用截图、替代物或规划充当结果；不要每一步等我下命令，不降低目标、不覆盖认可成果、不自行付费或扩大权限。遇到真实阻塞先尝试可行替代，再给出需要我决定的最小事项。

【目标工作台】由用户一句目标替换，其余目标上下文由执行端从已有信息补齐，不让用户填写内部TASK。

## 工具和接入的事实状态

记录工具init只生成文件；check只核验记录和证据一致性，不创建模型、不搜资料、不判美感、不自动部署。模板中的autonomy是执行职责约定，不是已安装的代理调度器。

跨仓库/其他分支应显式读取本方法固定版本，不能假称已自动全量采用。需要连续无人值守运行时，还要有真实执行器、工具授权、预算、可恢复队列和审核入口；本轮未建立这些运行服务，也未创建定时任务。
