# 面部结构身份与共享标志点 R2

## 目的

R1 已将人物长期长相与临时表情分开，但长期长相仍主要由若干局部控制点位移组成。R2 在不替换现有程序化脸部曲面、不修改 Core Rig 的前提下，增加一层可解释的中性脸结构参数，并把它编译到现有有界面部形变场。

本阶段解决的是数据与控制关系，不宣称已经形成统计人脸模型、扫描人脸或完整颅颌解剖模型。

## 数据结构

面部配置升级为：

```json
{
  "schema": "jarvis/face_profile@3",
  "identity": {
    "schema": "jarvis/face_identity@2",
    "shape": {
      "schema": "jarvis/face_identity_shape@1",
      "jawWidth": 0.3,
      "noseProjection": 0.2
    },
    "neutralOffsetsMm": {}
  },
  "expression": {
    "schema": "jarvis/face_expression@1",
    "weights": {}
  }
}
```

实际导出的 `identity.shape` 为紧凑键值对象，不保存值为 0 的参数；schema 由身份对象和运行时共同声明。

## 十三项结构参数

当前结构参数统一限制在 `-1..1`：

1. 颞额宽度；
2. 面部纵向长度；
3. 颧部宽度；
4. 面颊前突；
5. 下颌宽度；
6. 下脸饱满度；
7. 下巴长度；
8. 下巴前突；
9. 鼻翼宽度；
10. 鼻部纵向长度；
11. 鼻梁鼻尖前突；
12. 口裂宽度；
13. 唇部厚度。

这些参数先编译为毫米级结构位移，再与 `neutralOffsetsMm` 中的人工残差相加，最后叠加临时表情。所有结果继续经过每个控制点 6 mm 的有界限制。

## 共享标志点

新增 `jarvis/face_landmarks@1`，记录额部、双侧颞部、眉头、眉尾、颧颊、下颌、鼻梁、鼻尖、鼻翼、人中、口角、上下唇和颏前点。标志点由同一结构身份参数派生，供面部近景、后续眼鼻口结构重建、照片拟合和诊断使用。

当前标志点是 R2 中性参考脸上的作者标定点，不是医学测量真值。它们已经与结构参数共用一套坐标和位移编译器，但眼球中心、牙列、下颌关节和耳部标志点还未进入这一层。

## 兼容迁移

继续接受：

- `jarvis/face_pose@1`；
- `jarvis/face_profile@2`；
- `jarvis/face_identity@1`；
- 无 schema 的旧 `weights` / `offsetsMm` 对象。

迁移规则：

- 旧 `offsetsMm` 进入 `identity.neutralOffsetsMm`；
- 旧人物默认获得空的 `identity.shape`；
- 表情权重继续进入 `expression.weights`；
- 旧脸型不会被自动解释成新的十三项结构参数，因为旧数据不足以唯一反推参数。

## 运行顺序

```text
结构脸型参数
→ 编译结构位移
→ 人工中性残差
→ 临时表情通道
→ 每点有界限制
→ GPU 面部曲面与法线变换
```

该顺序保证表情结束后回到该人物自己的中性脸，也允许后续照片拟合先调低频结构，再用局部残差收尾。

## 页面检查

打开 `index.html?review=face`，进入“面部微控与表情”。面板新增：

- 五种中性脸结构起点；
- 十三项结构脸型滑杆；
- 当前共享标志点摘要；
- 独立的局部残差微调；
- 原有临时表情区。

建议选择“棱角清晰”或“圆润饱满”，再切换微笑、惊讶和中性。结构参数、共享标志点和局部残差应保持不变。

## 已验证与边界

自动检查覆盖 schema 迁移、结构参数范围、结构与残差合成、共享标志点、身份与表情分离、NPC uniform、源码装配和浏览器面板操作。

尚未完成：

- 结构参数直接重建鼻梁、眼眶、下颌角等基础曲面的拓扑与截面；
- 眼球和眼睑标志点随眼距及眼眶形态共同派生；
- 真实下颌关节、牙列、舌头与口腔；
- 照片或扫描数据拟合；
- 用户视觉验收。
