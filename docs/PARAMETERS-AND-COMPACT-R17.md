# 身体参数与无损加载 R17

用户本轮优先级：方便统一操作、减少数据及加载开销，保留身体效果和调整能力；人体母体用函数、个体差异用变量、表面用噪波。只处理身体，不动头部板块。全身、半身和正常肩头距离是视觉检查标准；当前不针对单套灯光重调肤色或粗糙度。

## 参数盘点

完整人物目录1916项，身体页965项，其他951项继续存档保留。目录没有完全重复的键或状态路径。“名称相近”不能证明相同响应，也不能因为中性状态下暂时无效就删除。

| 身体组 | 数量 | 本次处理 |
| --- | ---: | --- |
| 总体形态 | 11 | 常用8项放在主入口；其余基础混合轴保留 |
| 局部形态 | 127 | 其中34对左右参数增加对称操作，仍保留单侧自由度 |
| A驱动旋转 | 294 | 统一接口；只在A驱动编辑，保留动作与局部控制 |
| A驱动位移 | 294 | 放入详细操作；与旋转不等价，不随意删除 |
| B驱动体型 | 45 | 保留，它与总体形态共同影响身体，不是假定重复 |
| B驱动姿态 | 193 | 统一接口；只在B驱动编辑 |
| B驱动修正开关 | 1 | 明确布尔类型，不把它当普通滑杆 |

三项基础混合轴在原求值中按总和归一：同时按同一正数缩放时，比例不变，因此数学上存在一个公共尺度冗余。但零和时有特定回退规则，原档案还保存原始值。本轮不直接改变这三项的存档意义，后续可用两个比例变量与兼容转换代替。

未启用骨架的姿态属于暂不作用的状态，切换骨架后仍需恢复，不能当作无用数据。头部目录则是交给头部模块，而不是从人物文件删掉。

详细参数按当前驱动过滤：A显示771项，B显示377项，两者共享183项。全部965项仍在后台目录/状态中，不将两套骨架的无效动作混放到当前列表；切换后恢复相应的可编辑项。

## 一个操作入口

`window.bodyControlR17.apply(operation)` 接受一次具名变量修改与可选驱动选择，先整体校验，再提交一次身体求解。`preview`只检查和列出变化。`describe`返回完整映射与34个对称操作。常用界面为8个身体变量与一个“应用身体调整”按钮，详细控制折叠保留。

```js
bodyControlR17.apply({
  set: {'shape.weight': .63, 'shape.muscle': .71},
  label: '身体体量调整'
});
bodyControlR17.apply({
  set: {'symmetric.upperarm-fat-incr': .17},
  label: '双侧上臂脂肪调整'
});
bodyControlR17.apply({rig: 'B', set: {'pose.B.45': .2}});
```

旧参数键继续兼容。混合提交发生越界、非数、别名冲突、头部参数或不适用的骨架动作时，整批拒绝，不留下部分修改。值相同不求解。对称操作是显式的同时设置，不偷偷抹掉已有的不对称，也不删除单侧参数。

完整旧存档保留。主入口成功求得表面后，记录修改前后变量、驱动、标签、完成时间、函数版本和基础数值包哈希；只保存增量，不为每次迭代重复整份系数。来源校准与项目迭代是不同记录，增量迭代不会把原数据改记成独立来源。

## 真正缩减的数据

原始包内2256个逻辑数组有734个字节完全相同的副本；压缩版保留全部2256个引用描述，实际存储1522个唯一数组。完整目录、状态、权重、浮点位模式与元数据树不变。运行时共用只读系数，求值函数使用独立输出和临时变量，不修改共享输入。

数据包从117,384,869字节降至59,934,938字节；解压包从165,409,561降至90,490,457字节。缩减的是重复存储，未裁减系数、骨架、绑定影响或身体形体。新的独立页面仍包含两套驱动，不能把文件减半说成完全消除了冷启动成本。

证据分别为`qa/parameter-data-audit-r17.json`、`qa/compact-program-r17.json`、`qa/body-controls-r17.json`和实际浏览器`qa/compact-r17/report.json`。映射/校验通过不代表965项在所有组合下均已视觉验证。

## 仍然开放

身体母体、绑定和校准数据的独立替换没有由这次压缩完成。R15的腕部亮带、过强局部褶皱、整体材料层次有限等问题仍然存在。R17目标是无损整理与统一操作，视觉质量是否提高必须另立实际画面对照，不能由文件变小推断。
