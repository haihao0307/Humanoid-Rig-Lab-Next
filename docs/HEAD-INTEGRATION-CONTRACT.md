# 给后续头部整合的身体边界

R22 已将原 contour/fairing/harmonic 算子接入身体数值流程，17 状态离线阶段回放逐 Float32 位一致；尚未接通头部板块的任意连续状态提供方。原头部项目保持只读。以下 R21 的“尚未迁移”描述仅作历史记录，当前能力以本节及 DELIVERY.json 为准。

当前身体接收入口为 `bodyNeckR22.connect(async(state,requirements)=>packet)`，随后 `bodyNeckR22.refresh()`。`requirements()` 给出 1398 个来源头侧输入身份、来源哈希、米/Z-up 坐标及输入阶段。包 schema 为 `body-neck-head-boundary/1`，必须携带完整且精确匹配的 `sourceState`、当前头侧位置、共同静止矩阵、**原 contour 阶段实际使用的 neckSkinMatrix** 和头部尺度；不能用身体 attachment 的近似矩阵代替。TypedArray 输入会无损转为可保存数组。

过期状态、错误阶段、来源/单位不符、非有限值或不完整包在修改前拒绝。提供方错误回退完整旧人物；不提供对应边界时会明确标记原颈部阶段未执行，禁止复用过期输入。九个固定原状态的匹配输入只作来源对照。此接口是原算子的过渡适配，既不是自主头身接口完成，也不证明新连续表面复刻通过。


R21 历史记录：单独的共同静止矩阵和身体颈口曲线不足以证明复刻完成。离线原版还执行颈部 contour、fairing 和 harmonic surface 阶段，涉及头侧当前位置及共同邻域。当前固定状态对照保留这些阶段的实际结果；完整参数工作页尚未迁移它们。后续必须依据原阶段与头部板块提供的原接口恢复，不能以固定偏移、猜测封口、平滑并集或单条替代曲线冒充原连接。这里的 fairing 是需忠实保留的原版流程，不授权新增平滑。

本板块只处理身体，未修改共享R15、原眼睛、五官、表情或头发系统。新独立身体页没有显示头部；旧人物档案中的头部变量完整保留，供头部板块接入。

## 数值接口

`createBodyDriverR01(program).evaluate(state,{gnmRootRestMatrix})`保留原身体计算合同。`state`沿用原完整人物参数结构。可选`gnmRootRestMatrix`是由头部模块提供的共同静止空间变换，身体模块不猜测或重写头部的内部计算。

结果包含身体采样、完整权重、静止与动作矩阵以及`attachment.neck02`、`attachment.head`。这些是动画绑定接口，不是实际解剖骨骼扫描。矩阵是作用于列向量的行优先4×4矩阵，原生单位米、Z向上。

独立隐式显示使用Y向上空间：`(x,y,z) -> (x,z,-y)`。共享函数或矩阵前应明确转换，不能混用两个坐标约定。`program.bodyNeckCurve`是身体接入口的一条采样曲线，属于参数关系，不是三角面；头部应以共同边界或隐式接合处理连续性。

## 不应假设

- 不应从独立演示页没有头部推导为删掉了原人物头部；其状态仍在人物存档中。
- 独立演示页尚未提供完整双向头部实时连接。最终平台需要显式传入头部共同静止空间变换，并共同检查颈口、姿态、材质坐标和遮挡。
- 隐式场是近似场，不是全局精确SDF。不能直接假设随意进行平滑并集就会保住颈部比例、所有曲率和折射效果。
- 参数、命名与权重已保留，仍不代表外部源数据已消除，也不代表所有动作组合没有自交。

## R17 统一身体操作层

页面暴露`bodyControlR17.apply({set,rig,label})`，`rig`使用A/B公开名称，原人物状态仍保留原兼容键。完整目录1916项，身体操作层965项；只编辑身体路径，不改头部状态。`describe()`返回变量身份、原兼容映射、单位、范围及34个左右联动操作。多变量提交只求解一次，相同值不求解。

头部模块接入不应把公共名称当成新的头部坐标或自动骨骼映射。`person.bodyFunctionSystem.iterations`记录身体成功修改的增量与函数版本，旧头部档案字段保留。原数值包与R17共享数组包是同一套校准内容，包哈希改变不表示解剖数据已独立产生。
