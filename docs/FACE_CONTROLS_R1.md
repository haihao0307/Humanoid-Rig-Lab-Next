# 面部微控与表情 R1

后续已完成实际曲面校准、六组预设运行与截图复查，当前位移上限为 6 mm。见 [面部表情 R2 实拍复查](FACE_VISUAL_REVIEW_R2.md)；下文保留 R1 阶段的历史范围。

2026-09-12。当前为 Candidate，已实现控制程序与参数配方；本轮只验证文件内容，没有打开网页、运行人物生成、采样实际曲面、编译 GPU 着色器或操作鼠标。实际视觉效果、闭合情况、穿插和性能尚未验收。

## 使用顺序

工作台左下方 **面部微控与表情**，或 **人物设置 → 面部微控与表情**。

1. 点击 **面部近景**。在“局部采样”中选择眉头、眉尾、上下眼睑、面颊、鼻翼、嘴角、上下唇或颏部。左右按人物自身区分。
2. 勾选“显示所选点影响范围”，检查该点的着色范围。读数包含覆盖顶点数、峰值权重、到中性曲面最近顶点的距离及当前精度档。弱覆盖会提示复查，程序不会自动把控制中心移动到别处。
3. 用三轴滑条微调，每轴步进 0.1 mm。左右联动会反转 X 位移，保留 Y/Z 位移。X 正向为人物左，Y 正向为上，Z 正向为前。这是重建源坐标，在渲染时才做 X 反射，与 HumanDNA 的人体绑定坐标区分。
4. “上一采样 / 下一采样”使用默认 0.5 mm 的单点、单轴、正负位移，共 17 × 3 × 2 = **102 步**。可以设为 0.1–1 mm。开始时保存当前表情；每一步从中性开始隔离一个方向；结束采样会还原之前的表情。采样步骤始终单侧隔离，不应用左右联动选项。
5. 关闭影响范围显示，选择 **微笑、皱眉、惊讶、委屈、单侧挑眉笑、鼓颊抿嘴**，调节示例强度；也可展开 20 项通道分别组合。每次选择示例会清除之前的微调并应用完整配方。
6. “依次演示”按每种约 3 秒依次渐入、保持、渐出，一轮结束或点击“停止并还原”后恢复之前的表情。页面隐藏时不推进；切换角色会取消旧角色的临时演示与采样。
7. “恢复中性”清除全部表情和微调；“显示形变”用于暂时查看中性参考。“清零所选点微调”仅清除该点手工偏移，不清除表情通道。

## 程序结构与采样含义

- `body/FaceControlRecipe.json` 保存 17 个控制中心、椭球半径、20 个通道的位移参数、六个示例及来源。51 个轴向控制量不代表 51 根面部肌肉。
- `body/FaceControls.js` 验证配方、合成位移、管理 UI/演示和生成采样步骤。每个点的合成位移向量最多 4 mm，超过时按向量长度缩放并报告受限控制点。参数始终保留原值，实际渲染值单独限幅，反复操作不累计顶点误差。
- 当前曲面上传前，在已有的中性显示顶点上计算控制点覆盖。只保存每点数量、峰值和最近距离等汇总；不额外缓存整个人体顶点。切换显示精度成功后刷新读数，上传失败时仍保留旧曲面的读数。计数包含分块边界重复顶点，不能当作唯一拓扑点数量。
- 覆盖阈值为核权重 `w > 0.05`，峰值低于 0.2 提示覆盖偏弱。这是生成曲面的覆盖诊断，不是从真人采集的表情、解剖标定或对视觉效果的观测。读数只在用户实际运行工作台、人物生成完成后产生。本轮没有生成任何实际读数。
- 源位置 `p` 的位移为 `Σ w_i(p) d_i`，`r = length((p-c_i)/radius_i)`，`r<1` 时 `w=(1-r)^4(4r+1)`，否则为零。核函数的边界连续，使用同一场驱动皮肤、眉毛和唇部；眼球、虹膜、耳和毛发不参加面部形变。
- `CompactWorkbench.js` 在源坐标反射和原有双四元数蒙皮之前应用面部位移。法线由解析 Jacobian 的逆转置更新，颜色通道和阴影通道共用顶点着色器；材质坐标 `R` 保留中性坐标，避免皮肤细节随表情漂移。不新建绘制通道或顶点缓冲。
- 同一位置在皮肤分块和曲面连接带得到相同面部偏移。原有骨架权重、曲面精度与拓扑缺陷仍沿用原系统。

## 配方与接口

面部配方为 `jarvis/face_pose@1`，版本 `r1-local-fields`，字段为 `weights`（0–1）、`offsetsMm`（每轴 −4 至 +4）。只接受已定义通道和节点，拒绝非有限值、错误版本、未知字段和超过 64 KiB 的面部导入文件。

保存在角色的 `appearance.face`，复用现有 `character_preset@4`；没有该字段的旧角色默认中性，旧 `@3` 仍按原有兼容路径读取。随角色/NPC 导出保存，也可以单独导入导出。HumanDNA 增加面部生成配方、当前参数和采样状态，依然不保存生成网格，也不升级验收状态。

以下接口位于人体 iframe 的 `HumanLab.face`，仅供用户自行运行时调用；本轮没有执行这些示例。

```js
HumanLab.face.preset('smile', 1);
HumanLab.face.setWeight('browOuterUpLeft', 0.4);
HumanLab.face.setOffset('mouthLeft', [0.5, 0.5, 0], true);
HumanLab.face.sampleStep(1, 0.5);
HumanLab.face.endSample();
HumanLab.face.samples();     // 只读取当前曲面的汇总读数
HumanLab.face.samplePlan();  // 只生成参数步骤，不改变当前表情
HumanLab.face.play();
HumanLab.face.stop();
HumanLab.face.export();
HumanLab.face.report();
```

## 调研与取舍

先查询了 [Three.js BufferGeometry](https://threejs.org/docs/pages/BufferGeometry.html)、[Khronos morph target 教程](https://github.khronos.org/glTF-Tutorials/gltfTutorial/gltfTutorial_018_MorphTargets.html) 和 [Apple 面部通道定义](https://developer.apple.com/documentation/arkit/arfaceanchor/blendshapelocation)。Khronos 用多个位移目标的加权组合表达形变；Apple 将表情分为眉、眼、颊、嘴等局部权重，并按人物自身定义左右。

本项目实际使用自定义 WebGL 渲染器，也禁止保存烘焙顶点数组，因此采用从程序参数求值的局部位移场，再组合为表情。局部划分参考上述语义，不声称兼容完整 ARKit 52 通道，也没有面部追踪或摄像头输入。

已读取现有 `features.chf.gz` 的 JSON 头部曲面投影范围：眉毛约 Y 1.53423–1.54597 m，嘴唇约 Y 1.44851–1.46526 m；眼部沿用 `COMPACT_EYES`。中心和半径是在这些范围基础上编写的控制参数，不是经过实际曲面采样拟合的解剖标记。

## 当前边界与文件验证

眼睑收窄还不是完整闭眼；唇部拉开还不是张嘴系统。当前没有口腔内壁、牙齿、舌、下颌关节绑定、接触约束、面部肌肉体积保持或表情皱纹几何。4 mm 限幅限制单点幅度，不能证明任意组合没有局部翻折或穿插。现有曲面精度可能削弱微小形变；视觉合理性要在之后实际运行时检查。

新增 `tools/check-face-controls.mjs`，并接入 `tools/check-pure.mjs`。140 项文件断言检查控制点/镜像、半径与头面范围、位移单位、示例组合预算、配方验证、坐标处理顺序、法线公式、主渲染/阴影共用路径、角色保存与采样/演示恢复。它不运行面部模块，也不编译着色器，不能验证 GPU 兼容性或实际表情效果。

本轮 `node tools/check-face-controls.mjs` 的 140 项检查通过，`node tools/build-pure.mjs` 已重新装配入口并通过 JavaScript 语法检查。全项目 `tools/audit-files.py` 曾在 `check-r2-rig-motion.mjs` 的 `bounded weights with exact quantized normalization` 断言处终止：同目录正在修改的绑定实现已增加 `ownership` 参数，旧断言仍查找三参数调用。因此本轮不声明整项目检查通过，也未用面部专项结果覆盖全局审计文件。
