原始 AMC 的锁骨通道本身接近零，三份记录的最大绝对通道值约为 1.97e-13、1.62e-13、5.70e-14。没有证据表明导入器清空了有效的锁骨动作。没有为它补造录制轨道。

问题发生在 `body/ReferenceMotion.js` 的站立手势适配：保持 NPC 骨盆和脚不动，却继续使用表演者的绝对脊柱、颈部与手臂姿态。原始根节点旋转被去掉后，颈部仍带着原姿态补偿。在复现的 0.9 秒处，原录制头坐标系的向上轴偏离竖直约 33.9°，旧目标约 45.4°；按旧算法计算录制首帧的静态偏置约 45.94°。这里测的是头坐标系轴，并非头骨关节连线。

新增 `r2StandingCaptureMotion`：将捕捉各段世界旋转相对首帧的变化应用到 NPC 当前已提交姿势，再还原为脊柱局部旋转。上臂、前臂和手掌同步使用各自的旋转变化，消除静止手掌向上的偏置。保持既有骨盆和脚部约束。只有 wave/greet 使用该适配；源录制、坐卧转换、敬礼标准和搬运接触 IK 没有改写。

## 当前皮肤绑定：未通过

在当前生成表面上，将骨架重置到同源参考姿势，分别保持垂臂、抬臂 45°、抬臂 90°；不播放动作库。肩腋折叠依然出现。仅关闭肌肉补形、仅改变 LBS/DQS 混合比例，都没有消除问题。额外增加锁骨旋转也没有改善，因此这些试验没有进入生产代码。

区域原统计包含 111,037 个三角形；过滤后 80,655 个。T90 关闭全部软组织和腋窝位移的 CPU 隔离结果仍有 2,784 条原区域折叠边，最大边长拉伸 6.16。该隔离结果没有另算狭长面过滤项。大量细面会放大法线折叠统计，不能将原计数直接解释为同等数量的大型可见破洞；过滤后依然失败。

这已经把问题定位到当前肩胸连续表面、绑定权重场与抬臂补形的组合，而不是单纯动作文件或灯光。现有腋窝生成补形、共享根权重连续性和局部肩帽 Jacobian 检查，并未保证组合后的离散网格不折叠。计数不是全身非相邻三角形自交统计，也未在本轮重新建立 GPU 位置逐点一致性证明。本轮不修改绑定参数，不把已知失败的角色封装为不可变生产 NPC。
