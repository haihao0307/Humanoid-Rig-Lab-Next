# 动作截图复查与地面高度适配

用户明确要求自行截图检查，包括之前未查看的人物结果。本轮使用独立无头 Chrome 和真实 WebGL 工作台，未操作桌面鼠标。源码基于统一 main 的动作工作分支；不修改人物外貌、面部、选择或任务调度。

## 实际查看范围

`tools/capture-motion-visual-review.mjs` 通过现有人口分发与动作接口执行，修改前、修改后各保存 56 张截图和 `review.json`。图片保存在仓库外 QA 目录，没有提交图片或预制人体资产。

- 6 人：R2 参考人物、紧凑壮实复制体、林川、岳石、禾安、乔柏。每人查看正面与侧面的站立、挥手中段、动作结束站稳，共 36 张。
- R2 参考人物：坐下中段、坐稳、起身准备、起身中段、站稳、起步、行走中段、停止、转身中段、转完，共 20 张正侧面截图。
- 已通过五组联系表逐项查看以上全部采样，另放大查看坐下、坐稳、准备、起身侧面。它们是离散时点的视觉检查，不是连续播放的自然度验收。
- 为避免其他人物遮挡侧面，在单次截图时仅渲染目标人物和原场景地面；没有移动人物、改姿态或更换人体模型。未裁掉手脚。初始站姿截图中部分头发仍在异步生成，外貌检查以挥手结束的完整人物为补充；本轮不宣称面部/头发已独立验收。

## 发现与验收结论

| 项目 | 本轮观测 | 结论 |
| --- | --- | --- |
| 站立、挥手回落 | 六人保持完整身体，手臂回落后回到站姿 | 所查看静态姿态可辨认；不代表待机动作已有自然变化 |
| 起步、走停、转身 | 可见换脚与摆臂，任务能衔接 | 需要更密的接触时序与躯干角速度检查；未给连续自然度通过结论 |
| 坐下/坐稳 | 从侧面看，臀部悬起、脚部支撑不明确，仍显得不自然 | **未通过自然度验收** |
| 起身准备 | 一侧手臂大幅横展；起身中段有明显头躯干侧倾 | **未通过自然度验收**；需按臀、足、手支撑顺序处理，不能只加全身平滑 |
| 躺卧及坐起 | 完整链路截图中，人物支撑感仍弱，躺卧人物与邻近站立人物的脚部在画面上重叠 | 需要进一步核对世界空间占用与接触；本轮未验证群体坐躺避碰 |
| 群体自然行为 | 六人同场挥手完成，动作样式和时点高度一致 | 不等于真实群体行为，也没有大量 NPC 实时性能结论 |

最初从截图怀疑整个坐姿离地，进一步读实际支撑采样后修正了这个判断：坐稳时最低皮肤采样已经约为 0.5 mm，但限制点是右脚趾。整体最低点贴地不能证明臀部、膝部、脚掌形成了合理支撑。修改后的坐稳截图基本未变，不能写成“悬空坐姿已修好”。当前场景视觉地面也略低于动作的零高度面，本轮未修改共享场景展示逻辑。

## 本轮生产改动

给四个非腾空地面动作 `standToSit / sitToLie / lieToSit / sitToStand` 增加显式 `groundSupport: continuous-floor`。候选骨架提交前，依据已有实际骨骼/皮肤支撑查询，允许沿 Y 向下或向上适配到 0.5 mm 净空。原实现只向上防穿地，在原始录制体高与当前人体不一致时，会保留没有任何采样点接地的帧。

该适配不改关节旋转、水平根运动、骨长或原始采集数据。已由 IK 控制双脚、显式双手约束、世界接触目标拥有高度决定权，不应用整体向下适配。未标记的动作维持原有净空行为。诊断中的最大高度修正改为绝对值，避免漏报向下修正。该改动只消除“无采样点接地”的一类高度误差，不解决合理接触分配、臀部承重或全身动力学。

调研参考 [Unity Root Motion](https://docs.unity3d.com/cn/2018.3/Manual/RootMotion.html) 中按最低脚位适配根高度的说明，以及 [Three.js Quaternion](https://threejs.org/docs/pages/Quaternion.html) 的旋转插值接口。本项目沿用自身接触采样和四元数实现，没有引入 Unity/Three.js 动画依赖。

## 共享接口

- 输入：任务仍提供目标、路线和交通约束。新增字段仅由动作描述器生成；任务系统无须填充。
- 输出：现有 `groundCorrectionM` 现在在上述四类动作中可为负数；其含义为世界 Y 位移。`BasicController.maxFloorCorrection` 是位移绝对值峰值。其他接触、完成、失败和排队接口不变。
- 兼容性：没有人物队列、调度或交通逻辑变更；支撑脚接管和原有拒绝/回滚路径保留。新增脚本是显式授权后才运行的浏览器 QA，不加入默认文件检查。
- 配合事项：若其他板块展示有符号地面修正，应使用符号表示方向、绝对值表示幅度；不得将最低点贴地当作“平衡自然”或动力学验收。

## 验证记录

文件检查：重新构建 `index.html`，通过 `check-pure.mjs` 和 `audit-files.py`。没有直接编辑生成入口。

CPU 运行：准备阶段原有 87 帧脚锚/足部后代检查保持通过；新增四个地面片段共 244 个采样，其中 20 个进入向下适配分支。此测试使用明确标注的仿射表面探针验证高度策略，不冒充真实皮肤碰撞。另通过站姿接管、录制关节范围、站立手势重定向、执行回滚、2,078 组接触预检一致性及蒙皮连接回归。

浏览器截图运行：修改后的 56 个采样均无动作错误，六人挥手与回落完成；坐下中段、坐稳、起身中段实际最低皮肤采样约为 0.5 mm。起身中段的根高度比修改前低约 8.36 mm。此比较不等于坐姿自然度改善证明。

`tools/test-motion-runtime-browser.mjs` 冷启动后执行坐下、躺下、坐下（从躺姿坐起）、起身、向前走 1 米、左转 90 度、挥手，七项均完成并恢复可接续状态。实际 1,324 个地面动作提交采样中，80 个发生向下修正，最大 0.023619 m；与目标 0.5 mm 净空的最大采样差为 3.89e-16 m。这是采样模型输出，不代表物理测量精度。起身接管仍有 140 个样本，最大方向差 7.31e-8 rad，累计脚位误差约 1.17e-15 m。已另查看躺稳、坐起、再次站稳的真实场景截图；上述自然度与邻人占用问题仍保留。

同一次冷启动中，六人随后同场分发挥手、各完成一次并恢复就绪，pageErrors 为零；没有测量实时帧率或动作重叠峰值。交付前 `git fetch origin main` 成功，远端仍为 `3c3e9a4b7b250f4c8db20c15e2e5fab4ca9ce568`，也是当前分支与 main 的共同祖先，无新增基线冲突。

## 下一阶段顺序

1. 明确坐地与起身的接触顺序：臀/膝/足/手各自的接触区间、世界位置和承重代理；先纠正悬臀、脚趾支撑及不合理展臂，再优化时间曲线。不能靠整体下降破坏已承诺的足部接触。
2. 对停走、连续转向补充密集采样与连续回放，验证重心转移、支撑滑移和手臂相位；现有静态截图只作为定位证据。
3. 先测 4/8 人动作 CPU、整帧分位耗时和模拟掉时，再设计远近精度与共享预算，随后评估 16/32 人。当前不提高人口上限、不声称支持大量 NPC 自然协作。
