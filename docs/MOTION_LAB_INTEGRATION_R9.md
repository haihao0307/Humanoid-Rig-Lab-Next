# Motion-Lab R2.2 接入主项目 R9

日期：2026-09-11。用户要求以独立动作实验室取代旧动作系统，再接回以前的动作行为，保留长任务及不同形式的行为逻辑。本轮只检查文件内容，未执行应用或人物动作。

## 核心替换

`motion/vendor/` 固定以下八个实验室核心文件：`math.mjs`、`world.mjs`、`rig.mjs`、`clock.mjs`、`walk-data.mjs`、`full-body.mjs`、`controller.mjs`、`camp-routines.mjs`。来源为相邻 `Human-Motion-Lab/core/`，逐文件 SHA-256 及公共骨架哈希记录在 `motion/source-lock.json`。独立实验室保持原样。

`tools/bundle-motion-lab.mjs` 只进行文本装配和哈希核对，将每个模块保留在各自作用域中。它不导入或执行动作代码。主项目依赖的姿态混合和手掌方向辅助函数由装配器显式导出，源文件本身不变。

`body/NaturalLocomotion.js` 现在是路线到实验室指令的适配器。原有步态求解和全身关节限幅求解器已移出运行源码。初始站姿直接来自实验室控制器和完整骨架生成器；足底高度增加左右来源脚踝高度差所需的微小适配量。

| 核心规则 | 接入方式 |
| --- | --- |
| 身体时间 | 实验室 `FixedClock`：1/120 秒，每帧最多 24 步；丢弃的积压时间单独报告，暂停不消耗身体时间 |
| 根部移动 | `MotionController.update`；主任务执行器不直接平移步行根部 |
| 速度与转向 | 核心步速上限 0.48 m/s、加速 0.7 m/s²、减速 0.9 m/s²、转速 1.1 rad/s |
| 搬运与推动 | 对核心时间步降速，结合原有能力估算；相同核心参数和足部调度继续生效 |
| 脚部接触 | 独立世界坐标锚点；换脚时显式解除单脚支撑，保留支撑脚扭转上限 |
| 路线与碰撞 | 原路线规划接实验室连续移动查询；箱体采用扫掠圆与有向箱体，其他物体采用圆形包络 |
| 动作交接 | 到达并收脚后交接；整圈相对转向分成不超过 90° 的核心指令，防止最短转角消去整圈动作 |

这些数值描述实现参数，不代表人体实测能力。

## 统一表皮姿态适配

所有行为都经过 `Human.pose → MotionLabPose.apply`。适配器读取实验室完整节点位置及动作来源旋转，生成 128 个世界坐标关节变换，再转换回主项目父子层级。

正常步态保留实验室手掌朝向校正和独立脚朝向。接触动作使用固定骨长双骨 IK；来源坐卧姿态保留髋膝、肩臂、手足的完整来源四元数。手指、脚趾、中足、后足与髌骨跟随相应完整层级，未新增独立的实测细节关节曲线。

提交前检查节点数量、有限单位四元数、固定骨长、来源或适配范围内的肘膝弯曲，以及手脚目标残差。骨长误差上限为 0.1 mm，手脚 IK 目标残差上限为 12 mm。来源动作的关节范围从对应记录导出，避免被旧求解器再次裁剪。

表皮继续使用既有同源绑定与双四元数变形，变换为当前骨架相对于来源绑定的差值。没有引入另一份模型或蒙皮骨架。坐卧的采样地面净空修正在同一姿态适配器内作为整体竖直平移完成，它不改变骨长，也不等于接触力或全表面碰撞求解。

坐卧动作结束后锁定已提交的完整关节帧，避免每个保持帧重新重定向带来的变化。起身参考区间完成后，用 0.4 秒过渡回实验室初始站姿。

## 动作扩展及证据类型

| 动作 | 来源或方法 | 边界 |
| --- | --- | --- |
| 站立、步行、换脚转向 | 实验室核心；步行上身相位来自 CMU `08_01` | 起停和转向调度为工程适配 |
| 坐、躺、起身 | CMU `113_08` 四段区间 | 其他受试者采集，重定向到 R2 固定骨长 |
| 挥手、问候 | CMU `113_27` | 按骨架参考跟随误差判断完成，不要求搬运的手掌接触目标 |
| 敬礼 | 公开队列规范、同源头面标记和手部接触目标 | 时序与 IK 适配；未采集专属敬礼动作 |
| 搬运、推动 | 实验室步态、来源下蹲参数、双手接触 IK 与物体约束 | 未采集负重动作或接触力；不声称独立测得手指闭合、肌肉与皮肤形变 |

`body/MotionLabActions.js` 显式记录这些区别。接触姿态由来源下蹲区间选取，预推演和执行器共用双手可达性与头肩净空规则。搬运抬起、放下过程额外检查 17 个参数插值点；运行时每个候选姿态仍检查手脚残差。此检查不能证明所有表面、手指和障碍之间都无碰撞。

敬礼根据右手指尖、手掌和脚部误差判定。挥手根据来源骨架跟随误差判定。任意逐关节角度命令仍明确不支持；关节面板和遥测读取姿态，不另写关节或覆盖时间步。

## 长任务与 NPC 日常

保留既有整串预推演、语义步骤树、条件分支、等待与观察、追加和替换队列、执行票据、暂停与继续，以及步骤结果核对。等待继续使用身体时间。基础按钮经同一文本理解、预推演和执行队列进入身体，嵌入面板避免重复派发。

保留三种身份及原有八项持续日常：士兵巡视、器材借还、食堂周转，军官检查、文书交接，以及村民取水、分拣、市集周转。重新连接搬运后，相关动作不再被旧来源缺失开关禁用。另把实验室岗哨观察、集合报到配方接到营区语义地点上；这些日程沿用主项目的等待、休息、工具归位和回岗逻辑，不并行启动第二个日程执行器。

当前共十项日常、七个工具归位区。原职业长任务示例和不同身份的任务形式继续保留。日常采用单个活动人物，尚未形成多人群体模拟。旧 R2 人物定义的身份、能力和行为配置可迁移至新动作版本；人物定义没有保存动画进度，不把旧动画状态当作新内核恢复点。

## 失败、停止与回退

每个固定身体步开始前保存已接受状态。候选失败时共同恢复姿态、核心根部与脚锚、当前任务阶段、物体位置及持有标记、双手抓握关系、力量状态和完成证据，再暂停并报告错误。物体接触和任务完成计数不能单独越过失败帧。

普通停止取消后续步骤，由实验室减速收脚；地面支撑转换完成后再停。持物停止保留抓握、截断后续步骤并暂停，继续时重试当前放置。失败仍可能因场景、可达性或能力限制再次发生，会保留错误结果。无持物时可使用原有复位入口恢复实验室站姿。

## 文件检查与交付范围

运行 `node tools/build-pure.mjs` 装配当前 `index.html`，再运行 `python tools/audit-files.py`。文件审计包括：

- 源码装配一致性、HTML/JavaScript/Python 语法。
- 八个实验室模块及公共骨架的来源哈希；相邻实验室存在时核对其文件。
- JavaScript 词法作用域内的名称解析，包含装配后的各个核心模块。
- 初始姿态、时钟、回退、动作入口、接触预检及长任务/NPC 配方的源码关系。
- 公开动作参数、固定来源分区、系数容器和交付文件清单。

结果保存在 `FILE_AUDIT.json` 与 `SHA256SUMS.txt`。文件解析不运行应用、姿态函数、导航模拟、浏览器或 GPU，不构成视觉验收。当前 `runtimeVerified=false`、`visualAcceptance=false`、`productionReady=false`。本轮不恢复 GitHub 上传和其他旧项目目录清理。
