# 动作基础修正 R5

2026-09-13，按“开始计划、修改”执行。目标与顺序见 `MOTION_FOUNDATION_REPAIR_PLAN_R5.md`。本轮保留已有腕部、站立脚锚及 DQS 性能修复，进一步修正骨架连接和静止肩腋形体。所有浏览器检查在后台运行，未操作桌面鼠标。

## 已落实的修正

### 骨盆和脊柱的旋转必须与实际关节位置一致

原行走内核给出了髋点与腿部位置，适配器却给骨盆皮肤使用包含另一组摆动的录制旋转。同一个候选中的骨盆蒙皮端点与髋点最多相差 17.73 mm。现在保留内核髋点和脚锚，将骨盆旋转对齐其实际髋轴，并保留绕该轴的旋转。内核状态、路线、腿位置和来源骨长不变。

脊柱位置采用区域四元数的归一化线性插值，适配器旋转却采用球面插值。这会使位置、蒙皮各用不同的脊柱轴，原样本最大连接偏差 1.875 mm。现在二者采用相同的区域分配。

`MotionLabPose.validate` 除骨长、手脚目标之外，还检查整个父子链：父节点的蒙皮变换必须把来源绑定子点映到当前子点。阈值保持 0.1 mm，错误候选在提交前拒绝。它仍不证明皮肤无自交。

### 把一直作用的腋窝抬升改为随姿态变化

同一套冻结源码、同一相机对照表明，原 90 mm 参考形体抬升会在垂臂时造成深凹；直接去除它又扩大抬臂时胸壁到上臂的连皮。仅关闭肌腹、肩部 LBS，或换成几何法线，都不能同时解决两者。

本轮保留原采样、拓扑及抬升参考空间的绑定。生成 worker 只计算一次静态抬升的逆映射，并将中立端点和抬升端点映射到同一个个人体型场。运行时从中立表面出发，按上臂相对胸廓的抬举量逐渐使用抬升量；来源垂臂姿态权重为 0，90° 时为 1。左右独立，整体身体转向不会改变激活量。

CPU 支撑点使用同一位移和顺序。支撑候选保留两个端点各自的方向极值并集。GPU 使用一个属性 15，保留全部 Float32 位移和 oct16 法线位，不与眼睑属性 8–14 冲突；每个皮肤顶点增加 16 bytes 静态缓冲，没有每帧顶点上传或逆映射求解。来源外观坐标保持不变。生成几何、截图和调试脚本均不存入项目。

- 后台 Edge 对实际顶点着色器做 transform feedback。参考体型垂臂及 30/45/60/90°，每姿 50,616 个受影响顶点；另对两种体型实际挥手比较 CPU 与 GPU。最大位置差 6.71e-7 m，法线均有限且接近单位长度。此项只证明管线位置一致，不证明动作自然或法线为精确曲面导数。
- `build-pure`、`check-pure` 全量检查通过；动作过渡、持续任务和记录器回归通过。

## 尚未通过的内容

1. 当前实拍中，垂臂深凹消除，45° 抬臂硬折痕减轻。90° 隔离姿态仍有明显肩顶 V 缺口和肩腋连皮，不能宣称肩部修复完成。
2. 六类已安装动作的左右 `ClavicleQ` 全为恒等旋转，挥手数据并不覆盖完整带肩带的 T 姿。来源派生脚本没有显式清零；本轮尚未定位更上游原因。骨架有 SC→AC 链但无独立肩胛控制节点，也没有抬臂时自动生成的肩带耦合。临时 20° 肩带抬升对照仍不自然，没有把这个试验角度写入正式动作。
3. 中间权重采用归一化端点法线插值，是近似方法。独立解析参数样本可与部分抬升的真实法线相差约 24°；实拍已覆盖约 25/50/75% 激活，但这不能取代法线误差控制。不能把“法线有限”写成“正确法线”。
4. 全身皮肤自交、颈部大转角的曲面表现、全部坐卧与搬运过程均未完成完整验收。搬运回程的放置稳定性失败仍保留，不通过放宽物理阈值掩盖。

下一步应先追溯肩带来源数据，再对肩顶 AC→上臂权重交接和中间姿态法线分别做对照。基础肩部尚未合格，长任务数量和任务完成计数不作为通过依据。
