# NPC 母体与多人控制 R1

2026-09-12。原先多份角色配方只能替换同一个人物。本轮将配方与运行实例分开，新增 NPCPopulation，在同一场景和同一画布中生成、推进、选择和释放多个 NPC。保留当前人体来源、Motion-Lab 动作核心和已有外观控制。

这是本地源码实现，验证范围仅为文件装配、语法、引用、来源哈希和源码契约。没有运行网页、人物动作、Worker 或 GPU；多人效果、帧率、内存和交互结果尚未实测。8 人是保守的编辑上限，并非已测性能容量。

## 使用

沿用根目录 `启动人物项目.cmd`。页面中的 **NPC 生成与多人控制** 面板提供：

1. 选择角色定义，每次增加 1–4 人，总量最多 8 人。默认保留一人，新增人物依次生成，出生位置避开当前物体和其他 NPC。
2. 勾选一人或几人，在“选中人物”和“全体人物”之间选择指令目标。“设为当前”只改变人物设置、镜头和原任务面板的目标；勾选控制集合与当前人物分别保存。
3. 输入动作，例如 `向前走1米，然后向左转90度，然后挥手`。每个人有自己的等待队列、朝向、动作时钟和完成状态。同一指令中的“前方”“左方”按各自朝向计算。
4. 对选中人物或全体暂停、继续、停止。停止会清空后续队列并关闭循环；持物时保留抓握，须继续完成安全放置。暂停一人的身体不会暂停其他人的身体时钟。
5. 将动作设为独立循环并设置间隔，可让不同 NPC 分别运行不同动作串。间隔使用该 NPC 的模拟时间，失败关闭该人的循环并显示原因。
6. 在人物空闲且没有排队任务、循环或外观更新时，切换到当前人物并编辑皮肤、毛发、面部、身高。空闲人物可移除，至少保留一人。

生成多个外貌不同的 NPC，可选择不同内置身份或身高配方，再分别设为当前人物调整外观。不同实例可以引用同一个定义，实例 ID 仍各不相同。职业与显示姓名独立于角色模板 ID。

群控按每个人分别返回“接收/未接收及原因”，允许部分人物忙碌时其余人物接收指令。指令执行前使用各自当前位置、姿态和场景重新预检；后续执行受阻会记录到该人的状态。

## 数据与运行边界

| 层 | 职责 |
| --- | --- |
| `body/NPCDefinitions.js` | 可重用角色定义，保存外观、体型、能力及身份配方；与实例数量分离 |
| `control/NPCPopulation.js` | 实例注册、生成、选择、群控、每人队列和循环记忆、出生占位、资源释放 |
| 稳定 actor context | 持有本人的 Human、Agent、ReconstructionState、曲面、骨架纹理、毛发、身份和日志 |
| `control/TaskAgent.js` | 该人的姿态、动作、任务和接触状态；拥有稳定 npcId |
| 共享 World / PhysicsWorld | 场景物品、碰撞与物理世界；每个 population 固定步只推进一次 |
| Renderer | 同一场景绘制一次，遍历所有人物曲面；每次绘制重新绑定本人的骨架纹理 |
| 现有 HumanLab | 指向当前人物的兼容接口，不作为所有人物运行状态的唯一所有者 |
| 父层任务与日常 | 身份、历史、观察和日常记忆按 instanceId 保存；请求/响应绑定实例，拒绝过期投递 |

重建请求通过一个页面内串行队列处理，新增身体或毛发不再取消其他 NPC 的计算。实例只在身体生成成功且再次通过出生占位检查后注册；失败清理暂存显示资源。更换身高使用原来的完整人物事务，提交时更新该 actor 的身体引用。

NPC 根部及步行动作加入其他人的简化圆形碰撞约束；这不是全身软组织碰撞或人群路径规划。两人相向时可能停住，需要重新下达避让指令。共享物体具有 NPC 占用归属，单人失败只恢复自身对象和约束；共享物理步本身失败才回滚这一共同物理事务。

## 当前限制

- 身体沿用现有 R2 参数族及 0.94–1.06 等比例身高。独立胖瘦、腿身比、新骨架家族、服装资产和完整脸型生成没有在本轮实现。
- 现有高级对话、分支长任务和职业日常仍使用一个前台任务执行器。其任务在途时禁止切换当前人物，避免异步结果投错人；多人面板的本地动作串和循环可同时控制其他 NPC。未来可将高级执行器也实例化。
- 搬运和推物仍采用保守的单人占用通道，其他人的身体动作可继续。持物 NPC 暂停或失败时，共享物理物品暂时冻结以保留接触，其他 NPC 的身体时钟继续推进；这是待扩展的物理暂停边界。
- 替换整个场景、重新随机化场景或重置默认站位前，需要只保留一人。普通场景实体编辑会检查所有人的空闲状态与站位。
- 曲面、骨架纹理及显示资源按人持有，未加入人群 LOD、GPU 蒙皮批处理或外观相同人物的几何共享。并行计算和高人数性能不是本轮交付范围。

## 配方与扩展入口

`HumanLab.population` 是运行母体；`HumanLab.npc` 保留角色定义功能，新增 `spawn` 和 `instances` 转接。

```js
const population = HumanLab.population;
const first = population.activeId;
const second = await population.spawn('base-r2');
population.select([first, second]);
population.dispatch('挥手', { targets: 'selected', mode: 'append' });
population.dispatch('向左转90度', { targets: [second] });
population.control('pause', [first]);
population.setBehavior(second, {
  type: 'repeat', command: '挥手', intervalS: 8
});
population.activate(second);
```

实例的队列、行为记忆与身份已分开。新增行为系统应通过每人 Agent/队列提交动作，并显式处理已有任务、暂停和占用；不得直接写全局 human、agent 或覆盖其他人的姿态。新增人体参数仍走 CharacterPreset 验证与完整人物替换事务。

`exportScene()` 输出 `jarvis/npc_population_recipe@1`：角色定义、身份、出生位置、朝向与行为配方。它不保存显示网格、骨架缓冲、抓握恢复或动画进度。`importScene()` 添加新实例；与现有人物重叠的保存位置重新寻找空位，保持保存朝向，行为配置导入为关闭状态。全组身体暂存成功后才注册；失败不移除原有 NPC。若保存位置与当前场景物体冲突，导入会返回原因。

## 调研与验证

修改前查阅 Three.js 官方文档：

- [AnimationMixer](https://threejs.org/docs/pages/AnimationMixer.html)：独立动画对象可以使用各自的动画控制器。本项目延续同样的状态隔离原则，实际运行仍使用现有自定义 WebGL Renderer 和 Motion-Lab。
- [SkeletonUtils](https://threejs.org/docs/pages/module-SkeletonUtils.html)：骨架克隆需要保留每个实例的正确骨骼关联；本项目使用每人重新建立的源骨架及独立骨架纹理。
- [AnimationObjectGroup](https://threejs.org/docs/pages/AnimationObjectGroup.html)：共享动画状态有属性兼容与控制归属限制，因此群控采用指令分发，每人继续拥有自己的运行状态。
- [InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html)：适用于共享几何和材质的重复绘制；本轮不将需要独立外观和动作的人物直接换成静态实例网格。

`tools/check-npc-population.mjs` 对实例归属、并发 ID、生成事务、队列、单次世界推进、纹理绑定、占用释放和面板接线进行文件契约检查，并纳入 `tools/check-pure.mjs`。父层控制检查另覆盖实例消息路由与日常记忆隔离。检查通过仅证明这些文件契约，不能替代实际多人运行验收。
