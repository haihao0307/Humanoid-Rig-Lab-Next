# 无把手箱体搬运与接触协调（2026-09-18）

本轮只修改动作、接触与力量反馈。保留已有亚麻裙，服装问题由其他分支处理；不修改面部、人物选择、任务队列或交通预约逻辑。此适配仍是 Candidate，不是人体全关节动力学或大规模 NPC 验收。

## 现实依据与实现

- [CCOHS Compact Loads](https://www.ccohs.ca/oshanswers/ergonomics/mmh/compactloads.html)：无把手紧凑箱体可采用对角扣边，一手稳定上角、另一手承托相对下角；放下时保持倾斜，给抽手留空间。
- [CCOHS Handholds I](https://www.ccohs.ca/oshanswers/ergonomics/mmh/handholds1.html)：区分把手、勾握、扣边与指尖捏持。当前普通训练箱没有把手，不能把侧面双掌接触视为可靠底托。
- [HSE Good handling technique](https://www.hse.gov.uk/msd/manual-handling/good-handling-technique.htm)：负载靠近腰部、平稳起放、髋膝与背部协调，转向通过移动脚步完成。
- [CDC Joint ROM Study](https://archive.cdc.gov/www_cdc_gov/ncbddd/jointrom/index.html) 与 [AMSSM wrist/hand examination](https://sportsmedref.amssm.org/physical-examination/wrist-hand/) 提供活动范围参考。人群测量均值不是所有人的硬上限。本次搬运采用工程包络：腕屈伸 70°、桡偏 20°、尺偏 40°，接触肘屈曲 155°、膝屈曲 150°；并不等于完整的肩、髋、踝、前臂旋转解剖限位模型。

BoxHandling.js 在实际箱体局部坐标构造接触：先抓住上侧边缘，以远侧底边支撑倾转约 20°；左手先离开箱面，再绕到底部，右手稳定上角；底托成立后协调起身。放置反向执行，抽手后把箱体放平，再撤手站起。角度和路径是依据上述原则编写的程序化适配，不是搬运捕捉数据，也不是所有箱体的通用最优手法。

抬放时，髋部上升略滞后于负载，以保持低位承托手可达；执行使用实际物体高度驱动身体进度。手腕方向需求分配到肘部的剩余旋转自由度，保持骨长和手掌目标。伸手、抬放、换手路径均检查中间帧与关节跳变。手指检查覆盖掌骨到指尖骨段，不能当成完整皮肤体积碰撞证明。

推动保留掌面受压接触，采用更高髋部及髋折叠，避免低蹲行进时小腿穿地。地面修正同时保留脚锚与手掌世界目标；原有地面起身收敛迭代增加，不放宽地面净空阈值。

## 共享接口与兼容性

- 输入：现有任务目标、选定落点与路线、物体形状/刚体变换、人体骨长及支撑脚。人物队列仍由任务系统负责。
- 输出：携物高度与前距、进入/底托接触姿态、箱底支撑枢轴、倾转/换手路径及检查结果。Agent 增加 boxPickup、boxPutdown 两个动作执行阶段。
- PlanForecast 只调整抓取接近方向、接触可行性和动作耗时/力量估计；箱体抓取沿箱面法向寻找站位，保留路径与障碍检查。语义预推演的无物理场景副本使用独立碰撞查询环境，不推进物理时间、不改动实时物体。
- PhysicsWorld.setManipulation 新增可选 supportPivotLocal。只有显式提供枢轴、箱体有真实地面支撑且枢轴接近地面时，才补偿重力与平移施力在支撑边造成的转矩；继续服从原有肌力转矩上限。省略字段时保持原行为，空中不补偿支撑边转矩。
- 换手时只有右手传递负载，力量评估保守地将完整负载计入右臂；持物阶段主要由底托左手承重。双掌一致性证据不把换手中的空闲左手计为接触。
- 任务板块如对 phase 枚举做统计，应把新增两阶段视作持物动作；不要释放物品预约或启动下一项任务。服装板块继续按最终身体姿态做碰撞适配，本轮未更改其接口。

## 边界

目前没有证明所有体型、箱体尺寸、重量和场景都可成功。抓取不满足范围、净空或连续性时会拒绝，运行受阻时保留最后安全姿态。预检仍偏慢，未证明大量 NPC 同时进行接触操作的吞吐或帧率。跑、跳、独立蹲及饮食等未接入的生活动作不在本轮完成范围。服装视觉问题按用户要求留给其他分支。
