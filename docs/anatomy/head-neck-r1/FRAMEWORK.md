# 头颈连接框架 R1

版本：JARVIS_PROCEDURAL_HUMAN V1.15.0。日期：2026-09-06。

## 1. 本轮依据与编辑边界

用户截图显示头部在颈根前方突出，后颈接近下颌高度时突然收窄，前颈又向前折返，形成不自然的侧面轮廓。这是对当前程序化人物的视觉判断，不是对真实人的医学判断。

本轮只处理头部支撑位置、颈部截面、下颌下方、后枕与颈根连接，以及对应蒙皮。面部轮廓函数、眼、耳、鼻、口的局部设计和头高未重做。已认可的手掌、手腕、前臂 V1.12.1 与肩臂 V1.13.0 继续保留。采用上一轮实际交付的 V1.14.0 自包含网页作为运行源码基线，不以较早 ZIP 的旧躯干源码覆盖它。

## 3. 从结构关系到生成规则

头颈分成三个相互连接、处理时间不同的方向：前侧在下颌下方连接，侧面保留下颌角附近的转折，后侧上延到后枕。禁止把下巴闭合的小截面同时用于整个颈周。

静态支撑位置属于绑定数据。姿态属于局部四元数。静态位置修正必须独立记录比例版本；普通转头、低头、抬头和侧倾不改变绑定长度，也不写骨骼缩放。

颈部使用连续截面，左右宽度、前侧深度和后侧深度分别控制。下颌下方保留浅斜面，颈后保留较宽的枕颈支撑。胸锁乳突肌只添加低幅度斜向起伏；本轮没有生成独立可收缩的完整肌肉器官。

颈根以五次平滑权重接入原胸肩表面。细分和平滑会在相邻的共享控制网格中产生很小的传播，因此肩颈连接圈不能宣称所有顶点逐字节未变。实际保留区域的对比见 FROZEN_COMPARISON.json。

面部和五官必须使用同一头部绑定。下脸逐渐获得头部权重，避免下颌表面继续由较低颈椎牵引、眼耳却由头骨驱动的不同步。

## 4. 本角色的设计数值

下列内容为作者对当前角色的设计值，不是医学正常范围，也不代表从用户照片测量得到的数据。

旧头部绑定前向坐标为 0.056 m，新值为 0.016 m，向后回收 0.040 m。头部高度、面部局部尺寸保持原值。颈椎静态中心线适度弯曲，C1 前向坐标为 0.008 m，头关节相对 C1 向前偏移为 0.008 m。

绑定版本从 1 升到 2。C6 至 C1 与 head 的局部绑定向量改变。C7、胸椎、腰椎、四肢父子关系及四肢绑定长度继续保留。不得把这次静态修正描述为“所有骨长均未改变”。

六个形体变量的默认值都是 1。neckWidth、frontDepth、backDepth 的范围为 0.88 到 1.12；scmDefinition 为 0 到 1.5；submentalFullness、napeFullness 为 0.6 到 1.4。所有输入检查未知字段、类型、非有限值及范围。应用参数从固定源重新生成，不累计上一轮位移。

检查姿态采用 7 个颈椎控制节点和 1 个头部节点的等份旋转。这是可复现的保守展示方案，与真实寰枕、寰枢及下颈椎的各自活动贡献存在差距。预设角度不作为医学活动范围。

## 5. 数据与复现

规范化源码：source/body.v1140.runtime.mjs。
局部模块：body/HeadNeckSurface.js、body/HeadNeckWorkbench.js、body/HeadNeckWorkbench.css。
构建：python tools/build-head-neck.py。
生成的完整可读程序：body_runtime.js。
完整人物与各局部工作台共享这一完整运行程序。build/source-map.json 保存构建来源和输出哈希。

头颈形体导出 schema 为 jarvis/head_neck_shape@1，引用 proportionRevision=2。不同绑定版本的形体文件会拒绝静默导入。旧版手部姿态文件也应核对其引用的比例版本，不能简单把版本号改掉后声称经过重定向。

## 6. 必须检查的视角与不变量

每次修改至少复看中立正、侧、背、斜侧，低头、抬头、左右转头及侧倾。侧面优先检查头部支撑位置、颏颈转折与枕颈凹陷，背面检查左右对称和颈根过渡。灰模检查几何，骨架显示检查绑定。原场景入口与局部工作台都必须启动。

功能回归包括参数应用、恢复默认、JSON 往返、错误输入拒绝、绑定长度稳定、权重归一化、网格连通性和原工作台导航。测试通过只支持其覆盖的条件，不能替代用户视觉验收。

## 7. 当前边界与后续记录

保留简化的面部、头骨和颈椎外观。当前没有逐个枕髁接触、完整舌骨与下颌功能机构、肌肉力学、皮肤滑动、头颈与胸部碰撞求解。较大角度时颏下仍能看到细密折线，颈根的压缩仍为蒙皮近似。
