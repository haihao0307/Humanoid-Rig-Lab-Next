# 长任务观察与性能记录 R3

打开“NPC 生成与多人控制”，点击“开始双人长期观察”。前两个人物分别执行营区巡逻和观察箱往返搬运，轮数不限，直到手动停止或出现错误。按钮会在军营空地加入一个 0.8 kg 的观察箱及两个落点，不重置现有场景；编号或位置冲突时提示原因。

巡逻包含集合场行走、左右转向、门岗招呼和办公室回访。短程搬运包含取箱、抬起、持物行走、放下、等待和搬回。可以使用“场景全景”查看路线，或将某人设为当前人物后点击“跟随当前人物”观察动作。

任务编辑器另外提供八个示例：营区巡逻、被装箱往返、食堂日用品往返、空箱回收归还、文书多站交接、青菜筐分拣归还、行走坐卧起身、原地值守。搬运配方包括归还步骤，方便循环。选中人物、填入示例后可调整等待时间、轮数或时长，再开始。多个持续任务竞争现有搬运通道时显示等待，不直接让第二个任务抢占。场景和人物的可达性检查仍会拒绝无法执行的动作。

开始持续任务会自动开启记录，也可以单独开始或结束记录。结束记录不停止动作；任务停止按钮控制动作。记录包含：

- 每秒采样：FPS、帧间隔平均值与 P95、超过 50 ms 的帧数、主循环 CPU 耗时、渲染 CPU 耗时、全场景 GPU 计时、JS 堆、几何缓冲、三角形与绘制次数。
- 每个人：主线程动作更新耗时（均值/峰值/每秒总量）、动作完成数、阶段、任务步骤/轮数、站位、持物、错误、几何大小与现有动作统计。
- 事件：任务开始、动作阶段/步骤变化、暂停状态和错误，带墙钟与模拟时间。导出包含起始场景与人物任务配方，用于复现。

CPU 指标是主线程代码执行耗时，不是操作系统 CPU 占用率；人物 CPU 不含共享物理和渲染。GPU 计时是整个场景的实际 GPU 查询，不能分摊声称为单人 GPU。JS 堆是浏览器级读数，几何大小是缓冲核算，不等于显存总占用。浏览器不支持的指标为 `null`，界面显示“—”。后台标签页状态也写入采样。

内存最多保留最近 1800 个秒级采样和 1200 个事件，超过后丢弃旧项并计数。每 10 秒及错误发生时，将最近 120 个采样和 240 个事件保存到本地；刷新后可“导出上次记录”。使用“导出记录”下载完整当前保留窗口。保存失败会显示原因，仍可手动导出。

回归检查：`node tools/test-npc-persistent.mjs`（32 项）、`node tools/test-npc-observation.mjs`（28 项）。前者覆盖等待搬运通道和等待超时后的队列清理，后者覆盖记录边界、空值、事件、容量限制、存储失败和观察设施添加的冲突/事务检查。

已知观察问题：原场景的地面补给箱、日用品箱、空箱、文书包和青菜筐，在两个人物上均被现有抓取可达性预推演拒绝。初版较厚的观察箱能够抓取和运输，但放下后触发大腿/箱体穿透检查。上述错误保留在项目外的测试记录中，未通过增大碰撞容差或关闭检测来绕过。

针对放下位置的修正：`planObjectTransfer` 计算落点前的人体站位时改用 `motionApproachDistance`，与从地面抓取保持相同膝部空间；运输时仍使用 `motionCarryForward` 靠近身体持物，下放时沿现有插值前移至落点，继续经过双手可达性与物理检查。观察箱采用 0.32 × 0.50 × 0.20 米的尺寸，首次取箱前等待 3 秒让新物体稳定落地。

松手起身时，手腕目标现在相对同一候选姿态的肩膀插值，避免肩膀上升而世界坐标中的手掌目标仍停留在地面附近。仍使用原来的双手 IK、骨长和误差校验。共享物理错误在发生当步写入记录，即使所有人物立即暂停也能保存；停止绘制后不沿用旧 FPS/GPU 读数。

2026-09-13 当前验收：八个示例均通过界面语法检查；实际双人场景完成 30 秒实时观察后，以固定步进继续验证到约 76 秒任务模拟时间。巡逻完成一轮、7 个动作并开始第二轮；观察箱完成第一趟搬运，返程下放后的稳定性仍失败。错误时物体有地面支撑、无抓握施力，但速度约 0.413 m/s，角速度约 0.140 rad/s，未达到稳定阈值，因而未计作第二趟完成。当前不能声称搬运已经可以不间断循环；该剩余问题和原地面物资抓取问题供后续动作/物理修复复现。

实时段排除前 5 秒后，26 个采样的均值为：59.95 FPS，主循环 CPU 7.04 ms/帧，GPU 2.36 ms/帧，JS 堆 40.51 MiB，几何缓冲 47.58 MiB；两个人物分别占 150.48 / 158.55 ms 主线程更新耗时每墙钟秒，不含共享物理和渲染。该数据来自后台 Edge 实际页面、双人、启动细节档、默认阴影，是短时观测，不是数小时稳定性验收。随后固定步进测试的帧率受到测试驱动影响，不混入上述实时平均值。

输出记录位于项目外的 Codex 可视化目录：`npc-long-performance.json` 为纯实时段；`npc-long-qa.json` 含后续动作验证、错误及物体物理状态。此次任务与记录回归合计 60 项通过。整包检查当前另有面部控制模块的独立断言未通过，未通过更改该断言来掩盖失败。
