# NPC 身份日常 R4

版本：2026-09-11。新增三个身份预设、八套可重复日常、少量环境状态及归位设施。沿用动作系统 R3.1 的整串预推演、逐步执行反馈和最终目标检查。全部环境几何由函数生成。

## 使用

打开工作台的「任务」面板，展开「NPC 持续日常」，选择林川（士兵）、陈远（军官）或周禾（附近村庄农民），然后选择「按环境需求轮换」或固定某项日常，点击「开始持续日常」。当前身份中已有的自定义姓名会保留；主动选择命名预设时会采用预设姓名。

也可在主对话输入「开始日常活动」「开始日常循环」或「按身份持续活动」。这些指令为职业身份开启持续调度；通用、接待等原有生活身份继续使用原来的活动入口。

- 「暂停 / 继续」保留本轮进度，等待时间也随身体暂停。
- 「本轮结束后停止」等待本轮作业、归位和回岗完成后结束。
- 「立即停止」沿用现有动作停止规则；仍在持物时保留抓握，不能把物品瞬移回原位。
- 「导出日常记录」保存身份、环境需求、完成计数和最近 48 条事件。完成计数在本机按三个预设分别保存。
- 提交并通过预推演的手动任务会接管控制，持续日常结束；该轮尚未验收的工作不增加完成次数。

页面当前运行一个人物实例。三个预设共享生成函数，各自有身份定义和完成记忆；本版本没有同时运行三个人的群体控制器。页面关闭后不会在后台运行，重新打开后需手动启动日常。

## 环境如何推动下一轮

军营和村庄保存八个 0–1 的需求值，例如器材检查需求、食堂周转需求和农田缺水程度。它们按身体实际推进的时间增长，饱和后不再增加；暂停时不增长。每个需求的增长周期在 420–720 秒之间，这是可调整的场景参数。

自动模式选择当前身份下需求较高且已过冷却时间的日常，需求至少达到 0.30 才开始。固定日常模式仍遵守 90–150 秒的任务冷却。没有合适工作时提交一次 30 秒的普通等待计划，再重新检查，不创建无限长动作队列。

每轮执行前，包含作业、归位、休息和回岗的全部步骤必须通过现有强制预推演。轮次成功还须满足：

1. 已完成步骤数与本轮预推演选中的步骤数一致。
2. 全部最终物品目标通过实际场景数据检查。
3. 每个工具的完整水平包围范围位于自己的归位区域。
4. 人物回到本职岗位附近，站立且空手，身体没有错误或待执行动作。

通过后，当前工作的需求降为 0，环境记录最近完成时刻，预设的完成计数增加一次。下一轮从现场重新推演，因此不依赖上一次的旧路线或旧物品位置。

## 恢复和中断

肌肉疲劳最大值达到 0.30 后先等待恢复，降到 0.16 以下再安排工作，避免在阈值附近反复切换。恢复使用已有身体计时和肌力模型，不直接修改疲劳数值。

预推演受阻时暂缓该项任务，重试间隔按 30、60、120、240、480、600 秒增加，随后保持最大间隔；其他可行任务仍可调度。环境修订改变时允许提前重新检查。

执行中断且已空手时，最多尝试一次「工具归位 → 休息 → 回岗」恢复计划；这段恢复不计为工作完成。失败时停止重复恢复并暂缓原任务。若仍抓着物体，则暂停并保留接触，等待处理身体错误和安全放置，不能保证这类故障能自动恢复。

修改身份、重建场景需要先结束日常。身体连接丢失或身份改变时调度取消；进入部位编辑或毛发展示会暂停，退出后再继续。自动玩家问候不会在轮次间隙接管日常。

## 数据与生成方式

- 只新增 `WATER_PT` 取水点和 `WATER_A` 水壶两个对象，均由少量长方体组合生成；无需模型、图片贴图、烘焙顶点或动作文件。
- 新增 Z19–Z25 七个方形归位区，半宽 0.65 米，中心取自道具初始位置。预设场景共 76 个对象、25 个区域，继续遵守 160 / 32 的场景上限。
- 旧场景启动日常时只补充缺少的设施和区域，不搬动已有物品。若缺失道具，或新增设施位置被占用，则相关任务暂缓，其他任务仍可执行。
- 场景 JSON 的 `routines` 字段保存需求、环境时间、完成次数和最近完成时刻；通过场景保存、导出、导入保留这些数据。加载时不自动恢复执行中的动作队列。
- 四个新增功能源文件合计小于 64 KiB。动作按轮次展开，最大 20 个语义步骤，不保存无限循环轨迹。
- 日常事件保留 48 条，完成去重回执保留 32 条。身体动作证据在任务结束后保留最近 128 条，坐躺记录保留 32 条，不在执行票据开放时裁剪。

| 文件 | 职责 |
| --- | --- |
| `control/NPCRoutineCatalog.js` | 三个身份、八套日常、归位关系和按需步骤构建 |
| `world/NPCRoutineWorld.js` | 函数生成设施、环境需求、导入导出、完成验收 |
| `language/NPCRoutineController.js` | 选择下一轮、恢复、冷却、暂停、接管和界面 |
| `ui/NPCRoutines.css` | 日常面板样式 |
| `body/NPCDefinitions.js` | NPC 定义中的 `jarvis/npc_behavior@1` 身份绑定 |
| `tools/check-npc-routines.mjs` | 读取字面量与语法树，核对数据和跨文件接线 |

NPC 母体定义包含行为身份，出生记录包含独立的日常记忆初值。日常由工作台任务面板和主对话控制，不作为身体原生动作文本直接执行。

## 文件检查与验收边界

运行 `node tools/build-pure.mjs` 装配入口，`node tools/check-pure.mjs` 进行文件检查。检查器只解析源代码和数据，不执行日常构建函数、路径搜索、动作推演、人物模拟或渲染。打包另外核对 Python 语法、ZIP 完整性及逐项哈希。

本次只做上述文件验证，没有打开网页或操作鼠标。文件接线通过不等于实际路线、持物稳定性或长时间重复执行通过；`applicationExecuted=false`、`repeatedExecutionVerified=false`、`visualAcceptance=false`。原有运动学接触、未校准肌力模型和完整刚体动力学未实现的边界保持不变。

## 先行调研

设计参考以下原始资料中的顺序任务、受条件约束的重复、失败清理和环境工作点思路，使用本项目自己的小型函数与数据实现，没有引入框架或资源包。

- [BehaviorTree.CPP：Sequence](https://www.behaviortree.dev/docs/nodes-library/SequenceNode/)：按顺序完成步骤并传播失败。
- [BehaviorTree.CPP：Decorator](https://www.behaviortree.dev/docs/nodes-library/DecoratorNode/)：区分成功后的重复与失败后的有限重试。
- [BehaviorTree.CPP：前后置条件](https://www.behaviortree.dev/docs/guides/pre_post_conditions/)：运行条件与终止清理。
- [Game AI Pro 3，Chapter 34：1000 NPCs at 60 FPS](https://www.gameaipro.com/GameAIPro3/GameAIPro3_Chapter34_1000_NPCs_at_60_FPS.pdf)：小型行为选择和角色工作记忆。
- [Game AI Pro 3，Chapter 35：Ambient Interactions](https://www.gameaipro.com/GameAIPro3/GameAIPro3_Chapter35_Ambient_Interactions_Improving_Believability_by_Leveraging_Rule-Based_AI.pdf)：让环境工作点提供可用的交互。
