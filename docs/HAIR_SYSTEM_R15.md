# R15 毛发配方、种子与渲染预算

当前头皮范围已更新为解剖分区，最新实现、预算和实拍见 `HAIR_SCALP_REGIONS_R16.md`。下文保留 R15 阶段背景；其中圆弧蒙版、旧发束数量与旧底层属性布局不再代表当前实现。

2026-09-12。范围：当前 R2 参考人物的头皮毛发。源码已接入种子配方、独立更新和屏幕尺寸 LOD。用户授权实际截图后，进一步采用薄的程序化底层覆盖与细发束组合，消除首次检查中耳上、后脑的大片缺口，并柔化发际线。日常默认改为节省档；三个开销档的总缓冲和三角形上限保持原预算。最新证据见 `HAIR_REFINEMENT_R15.md`；首次问题记录保留在 `HAIR_VISUAL_REVIEW_20260912.md`。

## 配方与人物关系

`reconstruction/hair-presets.json` 是唯一预设目录。包含自然后梳、清爽短寸、侧分短发、蓬松微卷、灰白后梳和无头发六个预设，固定种子分别是 `2026091102`、`104729`、`130363`、`155921`、`196613`、`0`。

角色将下列内容保存到 `character.appearance.hair`：

```json
{
  "schema": "human-hair-profile/v1",
  "preset": "side-part",
  "seed": 130363,
  "color": "#543728",
  "density": 1,
  "lengthScale": 1,
  "quality": "balanced"
}
```

- 种子为完整 uint32 范围，包括零；相同配方、目录版本和头皮参数可重复生成相同分布。采样不使用 `Math.random()` 或时钟。
- 旧角色没有毛发字段时会补全配方；非零人物种子可稳定选择默认造型和毛发种子。三个内置 NPC 明确采用不同造型。
- `seededCharacterPreset` 重新派生毛发种子，保留已有发型与用户参数。选发型或“恢复预设参数”使用目录给出的固定种子。
- 密度范围 `0.45–1.3`，长度比例 `0.65–1.35`。密度小于 1 减少显示数量，大于 1 增加覆盖宽度但不突破数量预算。这不是生物学密度参数。
- NPC 导出/导入、人物配方导出都保留毛发。旧附件 ID `builtin/r2-hair-v1` 继续作为兼容入口；具体造型由 `appearance.hair` 决定。
- 当前角色仍共用一套固定参考人体和头皮。根点从实际曲面 chart 求值并随共享头关节变化，没有增加另一套头模型。其他头型接入时必须同时提供对应的曲面、头皮区域和径向避让场；不能只缩放当前头发。

主界面在“人物设置 → 头发”中修改。面板可选择发型、种子、发色、密度、长度和开销，点击“应用毛发”保存；显示开关作为 NPC 附件状态保存，风动只是当前查看状态。

## 成本预算

每个发束段沿用 9 个 Float32：两端位置、两端半宽和色调标记，共 36 字节。每段两三角形。新增底层使用共享 Float32 位置和 Uint16 索引；四套 LOD 索引共用位置。先扣除底层的全部 GPU 字节与最近景三角形，再确定可生成的发束数量。可见毛发最多两次绘制：一次底层索引绘制、一次发束实例化绘制。

| 档位 | 扣除底层前的发束预算 | 每束分段 | 底层与发束总缓冲上限（十进制 MB） | 最近景总三角形上限 |
| --- | ---: | ---: | ---: | ---: |
| 节省 economy（默认） | 3,000 | 4 | 0.432 | 24,000 |
| 均衡 balanced | 6,000 | 6 | 1.296 | 72,000 |
| 精细 closeup | 12,000 | 8 | 3.456 | 192,000 |

另有 44 字节发束共享角点和索引。表内不包含驱动对象、着色器、头部函数解码、临时 JS 对象、身体或整个进程占用。换发型时旧 GPU 缓冲保留到新上传成功，因此短暂有新旧两份；发束、底层位置和底层索引均通过 transferable buffer 传递。当前默认种子的节省档实际为 2,744 束、总几何 423,996 字节、23,936 三角形；均衡档为 5,480 束、1,269,972 字节、71,808 三角形。

原文件记录的参考数量为 87,391 根、每根 16 段，对应段缓冲 `50,337,216` 字节；原上限 120,000 根对应 `69,120,000` 字节。当前默认档的 `432,000` 字节总几何上限相对两项分别减少约 **99.1%**、**99.4%**。这只是数据布局比较，不能代替 GPU、帧率或进程内存测量。本轮也保留了同一页面毛发开/关的实际性能面板采样。

屏幕中的头部直径按约 160、70、28 像素分档，发束数量分别为原生成数量的 1、1/2、1/4、1/8；加入 12% 阈值迟滞。保留稳定随机顺序的完整发束，宽度最多补偿到 4 倍。底层独立选择预建索引，限制单元角跨度不超过 0.3 弧度，并加入小幅径向余量。生成时再采样各有效底层 LOD 的三角形，把局部头皮起伏所需的补偿合并到共享顶点；不增加顶点或索引。透视和正交相机均计算屏幕尺寸；相机后方不提交头发。每帧仅选索引范围、数量和 uniform，不生成或上传几何。有限采样不构成连续碰撞证明，LOD 切换也不承诺完全无跳变。

## 生成、更新与资源寿命

1. 保留分阶段启动：身体可用后再启动独立毛发请求。更换毛发只读取头部函数所需参数，不执行身体三角化、法线场或蒙皮计算。无头发预设跳过头部系数解码。
2. 最多 96,000 个候选点，在所有符合头皮条件的 chart 间按近似表面积分配。对候选采用有界优先级堆，最多保留当前显示预算的根点。达到预算后仍覆盖后续 chart，避免按源文件顺序截断造成一侧缺发。
3. 按稳定优先级排序，再检查根点间距；每条曲线立即写入定长缓冲。没有继续保留数万条曲线闭包；曲面 chart 缓存上限为 6。候选循环和曲线写入都报告进度。
4. 保留原 R2 径向头皮避让与根点归属，增加发际线软边界、梳理方向退化保护和非有限/异常长段检查。径向避让不能证明连续碰撞安全或弧长准确。
5. 颜色单独改变时复用现有几何。形状和开销改变时使用现有串行 Worker 队列；新数据上传检查成功后才释放旧 GPU 资源。失败、角色在计算期间变化或动作已开始时，不提交新角色定义。
6. 底层用约 0.65 mm 的基本间距和按发型变化的小幅顶区起伏贴合头皮；发际线、耳周和后颈用蒙版软化。表面约 88% 为窄发束、12% 为细丝，边界发束变短、变细。程序化纤维频率按屏幕导数过滤，底层高光较弱，上层保留切线高光。两层均写深度；有多重采样时使用覆盖采样，否则裁切边缘。不加载纹理或新增模拟、阴影通道。
7. 默认关闭风动。启用后只有着色器中的微小尖端摆动，根部位移为零，时间有界；不是弹性杆模拟，也不承担头皮/发丝连续碰撞。毛发没有额外阴影通道。

## 维护与文件验收

主要实现：`reconstruction/hair-profile.mjs`、`reconstruction/hair-rules-r2.mjs`、`reconstruction/hair.mjs`、`body/CompactHairRenderer.js`、`body/CompactHairControls.js`。主页面和 Worker 共用相同配方验证源码；装配器将该模块内容加入页面，避免两份验证规则漂移。

扩展预设应修改目录中的造型参数和种子，保留单位与短发范围。更换当前头皮参数时同时更新域、径向场、来源锁和配方适用范围。`appearance.json` 保留原 R2 来源参数，记录派生规则的旧 SHA-256 与当前文件哈希，历史截图数量不充当本轮结果。

维护命令为 `node tools/build-pure.mjs` 和 `python tools/audit-files.py`。`tools/check-hair-system.mjs` 仅检查文件内容：目录预算、种子边界、装配一致性、Worker 参数传递、候选/几何上限、上传释放路径、LOD 和材料接口。没有导入执行生成器或运行网页，因而不能把检查通过升级为视觉、启动速度或性能验收。状态仍为 Candidate、`visualAcceptance=false`。
