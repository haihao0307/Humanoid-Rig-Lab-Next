# R16：启动异常的运行定位与修复

2026-09-12。用户明确授权独立后台浏览器验证。使用独立无界面 Chrome 152.0.7977.65，不接管现有窗口或鼠标；直接访问当前服务 `http://127.0.0.1:8768/index.html`。已核对服务返回的入口、拓扑及采样源码与工作目录一致，响应为 `Cache-Control: no-store`。

## 可复现的缺陷

初次后台运行停留在 `body_extension/293`（身体进度 288/607），累计 67,146,340 次求值时，三角形仍为 17,097；随后页面响应超时。这次没有取得浏览器原生 OOM 转储，因此不能把该观测等同于完整的崩溃堆分析。

单独提取该曲面的原始参数可复现边界补点异常：只有 60 个边界点和 58 个初始三角形，`conformTrimFaces` 在 200,001 次访问中出现 199,327 次重复三角形访问。几乎共线的输入坐标包含 `1.42` 和 `1.4200000000000002`。补点时可能选择三角形自己的对顶点，产生重复顶点及退化子三角形；大量临时面在最终网格数量保护之前就已生成。它也不受自适应曲面细分预算控制。

共享目录中的皮肤任务同时修入了退化三角形与对顶点判断；本次独立复现确认了相同问题，并补充按输入规模限制补点访问次数的保护。保留所有源函数与边界点，不通过删除整块曲面绕开异常。

继续启动又捕获到第二个错误：`Builder.finish()` 释放索引数组之后，最终进度报告仍读取其 `length`。报告现在优先使用完成时已记录的三角形数量。

## 运行结果

- 原始问题曲面回归：保留全部 60 个源边界点，输出 58 个有效三角形，面积差约 `1.73e-18` 平方米；单次补点约 3.4 ms。回归脚本为 `node tools/test-trim-conformity.mjs`，仅在得到运行授权时执行，与文件审查分离。
- 修复后的第一次独立启动：约 6 秒身体就绪，随后毛发成功，持续渲染至 22 秒并取得完整页面截图。
- 在实际 8768 服务复测：身体启动约 5.94 秒，身体与毛发均就绪约 6.83 秒；页面版本为 `trim-runtime-repair-r16-20260912`。
- 依次切换活动档、近看档、启动档均完成，WebGL 错误码为 0，上下文未丢失。身体三角形分别为 269,148、320,107、222,853；几何缓冲约 11.67、13.30、10.20 MB，返回启动档后回到原缓冲量。切换耗时约 8.0、9.0、7.3 秒（含 1.5 秒稳定采样等待）。
- 各档位采样约 60 FPS；这只是本机、当前视角、无阴影场景的运行观测，不能推导复杂动作或其他机器的性能。
- 在独立浏览器中拦截毛发配方请求并返回 503：身体保持就绪、可见且持续渲染；取消拦截并点击重试后毛发恢复。首次测试的拦截规则漏掉 URL 查询参数，未成功注入故障；修正测试规则后确认拦截次数为 1，应用未因此修改。
- 同一浏览器同时打开两个工作台标签页：两次身体及两次毛发 Worker 的生命周期均结束，四个区间没有重叠，两个页面均就绪。
- 文件装配、162 个文件的内容审查以及 7 个 Python 文件的语法检查通过；这些检查仍不执行网页，并与以上运行测试分别报告。

启动档和更高档位仍报告 `precisionLimited`。当前画面可见表面局部棱面，运行修复不等于人体形态、皮肤或毛发画质验收。图形缓冲、JS 堆、进程私有内存、进程工作集是不同统计；此次阶段采样不能作为整个启动过程的内存峰值证书，也没有通过增大 JS 堆上限掩盖问题。

截图和逐阶段运行日志保存在本次独立验证的输出目录，没有把临时显示网格作为模型来源提交。文件审查结果继续单独记录在 `FILE_AUDIT.json`。
