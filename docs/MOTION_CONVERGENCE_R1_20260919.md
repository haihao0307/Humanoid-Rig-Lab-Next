动作候选中已经存在、准备按文件边界迁入：

- Human-Motion-Lab R2.2 固定步长步态；
- 完整骨架姿态提交、固定骨长、脚锚和脚掌方向接管；

仍未通过：

- 无把手箱体抬起、搬运、放下和释放闭环；

- 密集多人实时容量；
- 公网固定工作台的当前提交验收。

特别保留当前真实阻断：箱体换到底托后进入抬起约 0.125 秒，左腕屈伸约 -72.7°，动作保护触发并回滚。不得通过简单放宽腕部上限掩盖真实物体姿态与预检路径不一致的问题。

## 3. 本轮不变量

1. 动作不得修改绑定父子层级、固定骨长或人物比例。
2. 非根骨骼不得使用缩放轨道解决动作问题。
3. Motion-Lab `motion/vendor/` 八个锁定模块保持字节身份不变。
4. 任务系统只提供动作意图和世界约束，不直接写骨架。
5. 人物表皮、碰撞体和服装只能读取最终提交姿态。
6. 文件检查、CPU 回归、浏览器执行和视觉验收必须分开记录。
7. 数值通过不得升级为自然度、生产就绪或完整动力学通过。
8. 每次修改必须保留确定性回滚和旧基线可复现性。

## 4. 第一阶段执行顺序

### R1.0 基线、筛选和门禁

- 从 `main@3c3e9a4` 建立独立动作分支；
- 新增 `motion-convergence-gate.yml`；
- 按文件边界迁入 PR #7 的纯动作实现和测试；
- 明确排除 `clothing/`、面部、外观和无关体型改动；
- 构建生成入口并核对 source assembly、文件审计和 SHA256；
- 视觉 QA 单独执行，不由 CPU 门禁代替。

### R1.1 显式动作运行状态

完成干净迁移后，第一轮生产源码修改建立并接线：

- `MotionIntent`：目标速度、目标朝向、动作类型、交互目标；
- `MotionRuntimeState`：动作相位、连续速度、支撑与回滚状态；
- `SupportState`：左右脚、手掌、骨盆和物体支撑；
- `ContactState`：世界接触目标、位置/方向误差和释放状态；
- `MotionTelemetry`：实际速度、脚锚漂移、接触误差和阻断原因。

固定求解顺序为：

`MotionIntent → DesiredPose → Contact/IK → Joint Limits → Balance/Load → FinalPose → Skin/Clothing/Collision`

第一轮只迁移状态所有权和诊断，不改变现有动作外观，不修改 vendor。

### R1.2 走、转、停收敛

在显式状态接线通过后，依次处理：

1. 起步前脚步释放与骨盆前移顺序；
2. 经过路点与最终停止点区分；
3. 连续转向角速度、角加速度和落脚预看；
4. 减速、最后一步、双支撑和上肢回落；
5. 脚跟、全脚掌和脚尖滚动状态；
6. 支撑脚位置/方向漂移及停步残余动作。

### R1.3 肩肘手与坐起

走转停通过后，再处理锁骨、肩胛、肘平面、腕部和手指；随后重做臀部、手掌、脚掌和骨盆的坐起支撑切换。

### R1.4 物体交互与任务联调

最后修复真实箱体姿态进入抬起可达余量，完整跑通接近、抓边、倾转、换手、抬起、行走、转向、放下、抽手和释放；再与任务 PR #8 的导航、让行、暂停和恢复组合测试。

## 5. 当前验收口径

本分支当前只能称为“动作收敛工作基线”。只有同时满足以下条件才可申请合并：
