# 人物服装模块

默认服装已按用户选择切换为亚麻裙。每个人物持有独立 ClothingSystem，读取已提交人体姿态并输出服装形变；不写人体骨架、动作目标、路线、交通预约或任务调度。系统接入、动作执行、视觉验收是不同阶段，当前不能声明所有动作零穿模或大量 NPC 实时达标。

## 当前实现

- ProceduralLinenSkirt.js：沿用用户已提交的八片亚麻裙、内外表面、腰头、翻边、下摆及 3 倍布纹。来源为人物开发分支的 8b34db7993b27f8cdb40c801a40bf20931d8a416，组件 blob 记录在运行报告中。仅接入服装组件，没有合并该分支的其他人物或任务代码。
- LinenMaterial.js：原亚麻材质文件逐字节保留。厘米材料坐标、程序化经纬组织、像素覆盖过滤和材质着色不在本轮重新设计。
- GarmentSkinBinding.js：从本人物皮肤读取腰部附近权重，建立 96 列、4 行的窄带附着场，使用与皮肤相同的双四元数与肌肉形变。腰头完全跟随，向下在裙长 40% 范围内平滑退出。仅允许躯干、骨盆及大腿的皮肤来源，防止误绑附近静止手臂。它是附着修正，不是布料碰撞或压力模型。
- ClothingSystem.js：管理实例、更新、绘制、重置与释放。更新依赖服装声明的骨骼，同一时间腰椎发生变化也会刷新；阴影和颜色绘制使用同一结果，绘制不推进求解。

输入是本人物的 human/sourceBind/world、agent.time、身高比例和蒙皮调色板。输出为腰部附着纹理、显示资源和诊断。CompactSurfaceRenderer.clothing 是所有者，skirt 保留为兼容诊断引用。替换体型或曲面先构建新服装，全部上传成功后才释放旧服装；失败仅释放新资源。

亚麻裙仍使用继承的骨盆/大腿形变和大腿净空规则。setSimulation(false) 兼容旧检查调用；亚麻裙的 setSimulation(true) 明确报未通过动态布料验收，不能静默启用失败原型。

## 碰撞调研与失败试验

[Unreal Clothing Tool](https://dev.epicgames.com/documentation/unreal-engine/clothing-tool-in-unreal-engine)将固定、最大运动范围和动画驱动分开管理。[PhysX Cloth](https://nvidiagameworks.github.io/PhysX/3.3/PhysXGuide/Manual/Cloth.html)以距离约束、牵系约束、运动限制及逐子步插值的碰撞代理共同处理布料。虚拟三角形采样能补足顶点接触，但不等同于完整连续碰撞或自碰撞。[Unity Cloth](https://docs.unity.com/en-us/engine/6000.7/manual/physics-section/physics-overview/class-cloth)也要求显式配置衣物使用的碰撞体。

本轮测试了沿裙面外侧投影，以及带牵系长度限制的连续布面。前者出现硬片拉伸；后者坐起时出现严重局部拉伸，均已从亚麻裙生产实现中撤除。不要再次仅增大碰撞半径或求解次数来宣称修好。旧草裙及 GarmentClothSolver.js 保留为上一阶段关闭的试验源码，未实例化为默认服装。

当前大腿代理不是精确皮肤，腰部附着也不解决膝、小腿、手臂或衣物自碰撞。下一步先按实际变形皮肤拟合分段、渐变半径的碰撞包络，检查固定腰点与代理是否相容；再增加连续接触、拉伸与翻转门限。对外开放动态布料前，必须通过站立、步行、转身、坐起、躺卧和连续切换的多体型截图及数值检查。

## 检查与预算

test-garment-skin-binding.mjs 检查附着变换、统一平移、坐标解码及来源筛选；test-clothing-system.mjs 检查独立实例、同帧失效和生命周期。capture-clothing-review.mjs 在后台真实 WebGL 中读取草裙或亚麻裙的顶点着色器输出，检查顶点及三角形中心相对工程代理的间隙并采集截图。CLOTHING_QA_REQUIRE_CLEAR=1 会对不合格代理间隙报错；默认诊断完成不能写成无穿模通过。

多人尚未测出服装耗时、总帧时间和内存预算。后续以测量决定更新频率与休眠，不直接扩大人数上限。本轮证据见 docs/MOTION_LINEN_ATTACHMENT_20260918.md。
