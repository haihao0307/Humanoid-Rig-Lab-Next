# KAOPU 数字皮匠 R08 — 闭合厚皮、连续针路、工艺和抓取

原 R01–R07、anchors、R02 完整工艺台、R04 接触计算与 R05 连续针路来源全部只读。本轮新增只在 R08 和对应工作流内。最终网址、源提交、构建 SHA、浏览器结果以 DELIVERY_RECEIPT.json 为准。未有通过报告时不能把本文件当作完成证明，视觉仍待用户。

## 用户缺陷及实际修复

2026-10-10 用户的曲面皮包截图显示栏杆状切边、皮面与侧壁断开、针路没有贴合结构。原实现给表皮细分，却另用较粗轮廓做侧壁；顶点不共享。数值有限、无浏览器报错、能命中几个针孔，都不足以证明有连续厚度。

closed-shell.js 采用完整纸面的约束三角剖分。正面、背面、针孔内壁和外切边共享同一套实际细分边界，周期别名也统一；没有用双面材质或阴影掩盖缺口。pattern-physics.js 使用真实纸面与大开口生成力学参考网格，再用同一材料坐标驱动皮层、边壁、线和五金。微小针孔在物理网格中仍被均匀化，不声称逐孔损伤求解。

Poly2Tri 为固定提交的 BSD 依赖。完整许可在 vendor 和独立 HTML 中都有保留。

## 产品、原有工艺与可检查参数

七类对象为卡包、腰带、翻盖肩包、牛仔皮帽、三角海盗皮帽、立领皮夹克和皮样。帽冠、帽顶、帽檐、帽带，以及夹克身片、肩片、领、袖、袖口、口袋均为有两侧表皮和闭合切边的实际三维构造。夹克为本项目原创构造候选，没有搬入预制成衣模型，也没有冒称已经完成实物打样。

穿线继续使用 R05 的连续正反面针路和局部接触场。外露线体为沿同一穿孔路线生成的扁蜡线，不是悬放的短圆管。针孔、线体、局部压陷及侧向牵动共用材料位置；提供松线、正常收线、较紧和按住关闭牵动的同视角对照。

原八种材质、扫描粒面及已有涂饰共十三个三维缩略入口保留。接回新产品的控制包括：粒面颜色、尺度及隆起强度、粗糙度、涂饰；绗缝隆起与间距；连续平针、马鞍缝、双排、锯齿和交叉针路；针距、线径、线色；原切边、封边、实际折叠皮条包边；圆孔、长圆孔、分区穿孔及孔径/间距；交错编织尺寸。工艺受到对象边界及部件功能约束，不把不适用的工艺强塞进帽带或腰带。

“原版全部工艺”内嵌完整 R02 原字节与控制，作为旧能力存档；这不能代替在新产品上接入实际工艺。R05 原针路入口和 R04 承重接触演示也保留，不修改原文件。

新旧状态有位置相关的边角磨亮、露胎、褪色及细划痕。它们是作者控制的近似外观，不是有实测依据的服役年限或化学风化预测。绗缝隆起、编织几何不代表填充气腔、纱线摩擦或逐根纤维已被求解。

“厚度剖检”对实际正面、背面、切边着检验色；读数是生成几何的正背面距离。“切边”用当前材料位置及朝向取景，不盖静态示意图。厚薄和硬度分别修改几何尺度、面积质量、膜参数和 t³ 弯曲刚度，不只改变颜色。受力后“全貌”和“细节”使用当前变形场，不再取景旧参考位置。

## 抓手、性能和制作边界

点抓手后，按住当前物理三角形的重心位置拖动，目标来自鼠标射线与观察平面。重力、惯性、膜内弹性、弯曲、接缝及粒子接触产生节点位移；皮层、孔壁、缝线和五金跟随同一节点场。松开保留速度，只有“归位”显式重置。

ProductShell 在独立 Worker 中计算。界面显示实际模拟时间和计算速度，不用预设摇摆掩盖耗时，也不为追帧率扩大子步。复杂夹克可能慢于现实时间，抓取目标追随速度受稳定性限制。标量铰链及 Gram 形式的膜约束优化与原更新分别作逐项数值一致性测试，不能以优化名义偷换力学。

材料仍是未实测标定的近似壳体：R04 NL 零应变切线、客观 Green 应变的 XPBD 表达及原带符号弯曲角导数，并非原 R04 完整非线性隐式积分器。自接触为粒子级，不是完整三角面连续碰撞；猛烈折叠、部件穿插和细五金接触不能保证。完整缝线摩擦与张力传播、孔口损伤、断裂、永久折痕和真实鞣制差异未完成。

卡包与腰带仅有试作 SVG；帽子、肩包、夹克没有通过实物验证的生产纸样。现实制作仍需要皮料试验、削薄、缝合余量、五金配合和实物打样，不是看起来有厚度即可直接投产。

## 可复核门禁

verify-r08.cjs 检查主产品高精度网格的边关联、开放边、非流形和反向边、真实厚度以及各类工艺的闭合性。test-motion.cjs 重建实际顶点着色器随动位置，验证抓取后切边和皮面原重合点仍相接、正背皮层仍有正厚度。test-membrane.cjs 比较优化更新与原显式梯度更新，不是实物标定。

qa-release.py 使用实际 Chrome 检查七类产品、曲面切边、背面、材质和工艺控制、绗缝隆起、薄厚、真实鼠标抓起与释放、Worker 主线程响应、七类摇动、原 R02/R05 字节与运行、R04 承重恢复、SVG/JSON 导出和手机视口。成对像素检查只取三维视窗，不把文字计数变化充作材质变化。公网实际运行也要通过；只有成功报告才进入最终交付。
