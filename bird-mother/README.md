# Bird Mother｜鸟类生产工作台 V0.1

Bird Mother 是 Humanoid-Rig-Lab-Next 内的鸟类生产平台入口。它不另造一套孤立动画体系，而是复用人物系统已经验证的动作数据原则，并建立鸟类自己的骨骼语义、飞行状态和群体运行时。

## 本轮已建立

- `bird-rig-v1`：统一鸟类骨架契约，覆盖躯干、二段颈、头喙、左右三段翼、尾、左右腿足。
- `local quaternion motion`：局部四元数姿态、相位驱动动作、平滑状态切换。
- 动作：观察/呼吸、振翅、滑翔、悬停、起飞、着陆、行走、啄食。
- 飞行：单鸟路径飞行，以及含 Separation / Alignment / Cohesion / Wind 的三维群体求解。
- 鸟种参数：红嘴鸥型、麻雀型、苍鹭型、斑鸠型；鸟种改变结构参数，但不更换骨架接口。
- HTML 工作台：骨骼审查、动作切换、群体数量、风场、飞行参数、镜头、截图、状态保存、BirdDNA 配方导入导出。

## 与人物/动物系统的复用边界

可复用：

- `src/modules/animation/motion-runtime-v4.js` 的运行时分层思想。
- `motion-retarget-v4.js` 的语义映射方式。
- `phase-locomotion-v4.js` 的相位时钟。
- `human-core-v5/motion-execution-v1/behavior-plan-v1.js` 的行为计划接口。
- 局部四元数、动作片段、状态机、运行时参数和 QA 数据契约。

不能直接复用：

- 人形骨名和人体关节极限。
- 人体双足接触逻辑。
- 把人的手臂动画直接改名成翅膀动画。

鸟翼的肩带、肘/腕折叠、初级与次级飞羽、尾羽控制以及趾足接触必须使用 BirdRig 自己的语义层。

## 已识别的硬约束

1. **权威 R57 文档与几何资产不是一回事。** 当前分支能读取 R57 的决策、状态与参考锁定文档，但文档所指向的 OBJ/MTL 没有出现在可读取目录。未恢复资产前，不能声称已经完成 R57 表面蒙皮绑定。
2. **直接双击 HTML 与自动读取本地 OBJ/贴图存在浏览器安全冲突。** 本工作台本身可直接打开；本地模型资产需要拖入、嵌入，或从 HTTP/GitHub Pages 环境读取。
3. **单只 3A 英雄鸟与几十只同等细节群鸟不能在手机上无代价并存。** 正确路线是共享统一骨架/行为契约，同时让群体代理使用低绘制开销的表面表达；这不是按距离切换的传统 LOD，而是不同生产角色的固定实体规格。
4. 当前 V0.1 是可运行的系统母体，不是已通过真实鸟种 visual acceptance 的最终表面。后续必须把真实骨骼比例、羽区、翼膜/飞羽层、足趾和权威表面逐种接入。

## 打开

直接打开 `bird-mother/index.html`。工作台通过固定 CDN 载入 Three.js；联网的普通浏览器可直接运行，不要求构建工具。
