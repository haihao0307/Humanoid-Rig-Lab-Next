# 给Codex的逐项接入说明

## 当前授权

用户要的是专项方法储备，不是立即重构或一键启用整套系统。当前现有对象先完成其正在进行的优化；用户发出下一步接入指令后才实施。这个资料分支不创建或替换Palau工作台，不以旧鸟工作台作为当前项目。

## 第一件事：读取真实目标

读取当前`Palau-Bird-Workbench`所在仓库、远端分支、HEAD、对象登记和正在优化的状态；比较未提交改动。截图中的`tools/fit_fields.py`、`src/procedural-*.js`等只提供导航线索，并非已验证的完整接口。没有源代码不能声称已接入。

从资料分支只取`knowledge/bird-specialists/r01/`目录即可，不必合并它的整条main历史。可以在目标工作区干净且已备份后执行以下显式取目录操作；它不自动修改生产入口：

```sh
git fetch origin research/bird-specialists-r01-20261003
git restore --source=origin/research/bird-specialists-r01-20261003 -- knowledge/bird-specialists/r01
```

执行前确认本地同名目录没有未保存资料；存在则先比较，不能覆盖。读取固定提交比长期依赖可移动分支更便于复现，交接时记录实际资料提交SHA。

## 选择一个专项而不是全装

例如群体拥挤先评估FL01/FL04；需要互惠速度求解再考虑FL03。扑翼僵硬先查MO01/MO02，不必同步更换蒙皮。体型局部不准可单独测SH03，而不用先训练AVES。对应关系只是选题建议，不是强制开发顺序。

从 [examples/adoption-task.template.json](examples/adoption-task.template.json) 复制任务。填当前对象ID、准确科学名（待核实则null）、当前源码SHA、唯一主缺陷、一个方法ID、目标属性、测量依据、受保护锚点、修改文件、比较方式和回滚点。默认`enabled=false`。

## 每项最小接入闭环

1. 先冻结当前被接受的结果，记录相同镜头、光照、姿态和种子。形态、动作、导航、材质分别留不变量。
2. 阅读对应来源的实际核查级别；摘要入口不能当作全文算法。选作者代码时先锁提交和授权，数据/模型另查。
3. 实现局部适配器或单一功能开关，只读当前对象已有字段。不要为方便写入新骨长、换对象、重建整个解析器。
4. 先跑该方法的数学测试，再跑目标对象的专属形态/运动/接触回归；两者不能互相代替。
5. 在当前工作台比较关闭/开启两组。报告实际误差变化、CPU/GPU时间、内存、绘制次数与失败场景。阈值由项目证据/用户验收定义，不从测试夹具借用。
6. 只有该专项通过，才保存参数与来源和接入提交。没通过则关闭功能、保留失败记录并回滚；不要把失败状态推成新母本。

## 调度与冲突边界

每个模块声明读取/写入字段、坐标空间、时间基准和更新顺序。导航模块写期望速度/加速度，飞行控制写动作目标，约束写最终姿态，表面只读取最终姿态；这是避免同一属性被多个模块同时覆盖的建议，不强制改写当前成熟架构。

普通姿态不修改绑定骨长/父子层级。参考资料不等于模型事实；不能把2D羽片外观近似当成显微几何，不默认启用按距离换几何。曲面重构后生成的可见网格仍是几何，声称“无老师模型运行”不等于“零网格/零数据”。
