# 完整灰模动作研究预览

访问 `http://127.0.0.1:19057/`。页面是隔离的研究预览：左侧动作图谱，右侧统一灰模，右上角是同一时刻的来源示范。人物只在原地做动作；路线、正式 NPC 行为逻辑和动作包导入导出没有由此页面完成。它不修改正式工作台、人物函数母体或引擎。

先启动原动作资料服务 `http://127.0.0.1:9018/`，再在本目录运行：

```powershell
python research/gray-workbench/server.py --port 19057 --externalized-reference-research
```

此入口依赖 `.runtime/gray-externalized-reference-research-20261115.html`、`gray-reference-assets` 和相应清单。需要重建时，依次运行 `tools/build-gray-without-skin-graph-research.py`、`tools/build-gray-externalized-reference.py`。构建仅生成研究数据，保留每份依赖的内容身份；切换人物或源版本后必须重新构建和复核。灰模入口不装入原皮肤图谱，但保留原眼睑几何处理，不能用于皮肤材质或睫毛视图。

动作首次选择时一次性读取并校验该动作的完整身体轨道、头颈和来源提供的手指轨道；播放中不再按 32 帧请求片段。最近使用的动作在页面内有限常驻。时间轴和来源示范使用动作文件的实际帧时间；计算跟不上时跳过已经过时的画面，以尽可能保持动作时长，并显示真实完成帧率。来源帧率未知时仅开放逐帧查看，不虚构播放速度。来源没有独立手指轨道时不虚构手指动作。

## 计算路径与限制

默认将原显示细分、法线和部分平滑计算交给 WebGL2，并让静态显示数据常驻显卡；无法使用显卡计算或上下文丢失时自动切回灰模参考计算。可用 `/?reference=cpu` 主动打开参考计算。灰模模式省略了与本画面无关的皮肤表面字段同步、颜色和材质字段传播、睫毛显示查询和旧渲染器包围体刷新；相应皮肤和睫毛视图不能从本页恢复。默认零值的嘴部性能参数使用经过对照的空运算跳过，参数非零时仍执行原计算。

这还不是完整的显卡常驻动作系统。现阶段原头面修正仍有 CPU 运算，多层计算之间仍反复从显卡读回数据，不能声称达到实时播放或完成全部绑定。最近一次无窗口 Chrome 实测使用 NVIDIA GeForce RTX 4070 Ti SUPER，四种动作连续完成帧约 3.1–3.4 帧/秒；同机另一轮约 4.4–4.6 帧/秒，负载变化影响明显。最近一次冷启动约 27 秒，普通动作首次切换约 0.35 秒，较长样本约 0.94 秒。帧率按画面完成后的连续间隔计算，不是仅提交绘制命令的速度。

显卡和 CPU 的浮点计算不逐位相同。`review/gray-gpu-hybrid-cumulative-source-diagnostic-20261115.json` 对不同行为的姿态对照了完整表面；`review/gray-gpu-motion-sample-source-check-20261115.json` 另检查了三个动作在多个时刻的采样，当前样本最大位置差小于 0.001 毫米、最大法线夹角约 0.22 度。它们不是全部动作、全部视角或手脚接触验收。不得据此将研究版标记为已验收。

`review/gray-gpu-workbench-end-to-end-20261115.json` 记录实际播放、分段边界、长动作、未知来源帧率和显卡上下文丢失回退；`review/gray-complete-body-track-check-20261115.json` 对照了原分段轨道。`review/gray-externalized-reference-fresh-comparison-20261115.json` 记录了灰模源数据按需读取前后的几何、法线、索引和画面对照。表面数据文件按内容校验，首页 HTML 变小不等于所有人物资源只占首页的大小。

快速连续选择动作时，正在准备的新来源示范会先隐藏上一动作，准备完成后显示与人物同一时刻的画面。`review/gray-rapid-action-switch-20261115.json` 检查了请求乱序和示范画面的恢复。后续消除表面阶段间往返的具体工作见 `GPU-RESIDENCY-NEXT.md`。
