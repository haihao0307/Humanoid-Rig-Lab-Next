# ET09-S2：眼角与眼睑截面

继承已修复闭眼U形的固定S1.1：`c4cad2026f10b656a4bc00568be11dcf7429c44f`。本轮仍是灰模，未进入第三阶段材质坐标、第四阶段组织动力学、第五阶段皮肤和眼球光学。

## 实际代码

`SectionField.js` 重建上睑自由缘至睑板前区、浅褶皱、眉下过渡的几何截面。截面横坐标采用实际投影距离而非统一眼裂上下缩放；皮肤基底不再把角膜曲率的变化挤成纵向条纹。下睑采用短睑板前隆起和较平顺的主体，并加入鼻侧斜向泪沟变化，避免三条等宽平行凸带。内外眼角周围受固定边界约束的局部平顺处理减少原来的放射状夹痕。

`CanthalTissue.js` 为每只眼构建一个连接的内眼角曲面，低矮隆起、弯曲皱襞和凹入泪湖在该曲面内生成；不是独立小球或粉色塞子。上下附件直接读取现有后侧睑缘的实际顶点。贴近眼球一侧使用曲线边界和数值接触保护。外眼角有短的上下睑联合曲面。跨不同mesh的附件共享位置，不冒称整个眼周已经焊成单一拓扑。0.085mm是数值间隙，不是真人泪膜厚度。

`SectionEyes.js` 继承原绑定与闭眼修复，只在第二阶段开关启用时叠加本轮结构。中性眼裂的XY曲线、眼角端点、眼球中心/深度/半径、虹膜比例均保留。为了清理原闭眼扫描在开眼内眼角处的深度跳变，只对靠近内外眼角的小段开眼睑缘Z曲线作平顺处理；典型中性最大位移约0.80mm右眼、0.29mm左眼，闭眼终点该修正为0。不能称整条三维轮廓完全未变。

完全闭眼时，第二阶段的外表面及睑缘截面改变量为0，回到已验证的S1.1闭眼目标。新眼角曲面收拢，眼球对象不隐藏，也没有黑色盖片。该规则是几何混合，不是体积/弧长守恒的组织物理。

`SectionReview.js` 在原工作台同一画布内增加同光同相机的按住修改前对照、分级闭眼、左右眼与内眼角近景、深仰视、实际网格截面线。所有旧控制保存在可展开区，旧固定预览保持不变。没有增加第二个渲染器或第二条动画循环。

## 检验与迭代

`build.cjs` 从指定S1.1源文件取源码并核对SHA-256，定点接入新模块，使用原来的固定资产，生成语法检查过的单文件公网预览。原有Stage1文件和头部/皮肤资产不被修改。

`verify.cjs` 运行真实Chromium/WebGL，检查实际顶点和三角面、闭眼目标、共享边缘、原头与标定保持、同姿态对照、参数保存恢复、真实闭眼眼球像素遮挡，并生成桌面1440×1040和390×844手机视口截图。

`extra.cjs` 另外检查外侧眼皮、新内眼角、新外眼角的三角形质心和边中点、8个闭眼程度、真实上睑截面褶皱幅度、诊断函数只读。发布后在真实不可变htmlpreview地址重跑，核对公网HTML与构建清单哈希。

第一候选虽然主测试通过，但实际截图暴露深褶皱、皮肤纵条与眼角片状形体，因此被继续修正。第二候选的附加测试发现诊断查询会污染闭眼状态下的统计值，已修成只读统计，未通过放宽阈值掩盖。最终结果请看对应发布提交的Actions实际artifact，不能把较早测试当作最新结果。

## 边界与后续

灰模材质不使用毛孔、扫描修复、湿润、睫毛或虹膜光学掩盖结构。当前只是约束拟合，不是这个人物真实睁眼状态的重建；缺少同一人的睁眼、多视角和多方向注视观测。内眼角组织和上睑褶皱仍需视觉验收；眼周残留扫描痕迹、上方体积过渡、真实动态折叠属于尚需继续改进的内容。

有限采样通过不证明所有连续姿态都无碰撞。手机视口不等于手机实机。CPU拟合与浏览器灰模运行不等于影视级品质认证。保持Draft，不合并、不强推，不修改历史。
