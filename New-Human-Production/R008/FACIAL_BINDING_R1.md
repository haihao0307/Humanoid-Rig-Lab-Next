从资料得到的设计是“中性身份 → 动作驱动 → 重叠影响场 → 结构/组合修正 → 表皮表现”。实际肌肉分布无法从一张静态皮肤表面唯一反推，因此本次生成的是**肌肉启发的表面控制权重候选**，不是对真人肌肉体积、纤维或力学性质的扫描采样。

## 当前人物的证据与边界

参数包内头部是 material/part 2 `tripo_part_3` 的 19 个曲面参数域。脸、眼表与头发处于同一个部件，骨架仅有 `neck_01` 和 `head`，没有眼、颌或面部骨骼，也没有来源表情形态。

使用实际后台浏览器的生成表面射线采样校准眉、眼、鼻、口角、上下唇与颏点；主体坐标为米、Y 向上、脸朝 +Z、人物左侧为 +X。典型当前人物锚点：眼表 x≈±0.034、y≈1.656、z≈0.102；口角 x≈±0.026、y≈1.586、z≈0.103。源脸有不对称，本轮没有强制改变其形状。少量双侧锚点目前镜像展开；所有中心和半径是此人物的控制拟合参数，**不是医学测量或适用于所有人物的统计值**。

## 46 个区域

22 类双侧区域由一份参数镜像展开，另加中央鼻根与下颌场：

| 分层 | 区域类别 | 当前能力 |
|---|---|---|
| 眉额 | 额肌内侧、额肌外侧、皱眉、中央鼻根 | 独立权重与局部牵拉验证 |
| 眼周 | 上睑、下睑、眶周、眼表保护、内眼角、外眼角 | 眶周可验证；眼球、睑缘与眼角保留独立约束字段 |
| 鼻颊 | 鼻翼、鼻唇提肌、上唇提肌、颧小肌、颧大肌、笑肌、颊肌 | 独立权重与局部牵拉验证 |
| 口颏 | 上唇、下唇、口角、降口角、降下唇、颏肌 | 独立权重与局部牵拉验证 |
| 下颌 | 中央下颌支撑 | 权重与接口预留，暂不张嘴 |

其中 35 个皮肤控制区可验证，11 个眼睑、眼表、眼角或下颌区域为结构预留。名称描述控制作用区域；不宣称 46 块真实肌肉。AU 关系是多对多，例如口角既涉及提拉也涉及压低，单区的牵拉方向不能替代对应完整动作。

## 函数、数据与所有者

- `FacialBinding.mjs`：唯一的区域参数、C2 紧支撑椭球权重、前脸/高度窗、眼表保护、动作关系和小幅位移所有者。连续场依赖中性米制坐标，不依赖某个 UV 岛或顶点编号。
- `SubjectRuntime.mjs`：从当前生成表面重新求值权重、保留原有 8 影响身体蒙皮；附加检查属性由 GPU 使用。脸的局部位移先作用于中性表面，再由原头部骨骼跟随。
- `FacialWorkbench.mjs`：选择区域、权重显示、正面/两侧观察与恢复。权重颜色在光照之后叠加；关闭时 alpha 全部归零，原表皮材质仍在。
- `app.mjs`：检查模式暂停世界行为，保存并恢复角色朝向、游戏暂停状态及骨架/身体权重显示，释放键盘输入；不使用鼠标锁定。

只持久保存 22 份双侧参数、2 份中央参数、关系和函数。生成表面上的稀疏 CSR 权重、位置/法线参考和 GPU 检查属性均为临时缓存，不写入参数包或顶点资产。默认 4,551 个面部候选点产生 8,868 个非零权重，最多 9 个重叠区；CSR 和局部参考缓存共 189,976 字节，不包含全身 GPU 检查属性。模块源码约 9.82 KB，界面源码约 4.76 KB；不声称理论最小编码。

皮肤影响场允许重叠，**不把所有 AU 权重强制归一化为和 1**。角色骨骼蒙皮权重继续归一化。全区颜色仅显示最大影响区，单选模式才显示该区的完整衰减场；颜色边界不是切开的几何或真实肌肉边界。

## 未来调用契约

```js
const face = HumanGame.subject.face;
face.sample([x, y, z], part); // 中性 canonical 米制坐标 → 46 个 [0,1] 权重
face.resolveAction('mouthSmile', 'Left'); // 独立侧别 → 多个候选控制区
face.resolveAction('eyeBlink', 'Right'); // 返回 structure-required
face.deform('mouthCornerLeft', 0.5); // 局部牵拉验证，不是完整微笑
face.reset();
```

`resolveAction` 只解析关系，不自动播放完整表情。注视需要独立水平/垂直眼球自由度，眼睑需要睑缘闭合与随眼球转动关系，下颌需要铰链、唇接触、口腔和组合修正。眼区、睑区、眼角及下颌的牵拉被禁用，避免拉伸贴在皮肤上的眼睛或把闭合嘴部扯成孔洞。后续具体表情应使用按动作设定的位移方向/增益及组合修正，而非叠加本次检查用的小幅方向向量。

## 实际检查、失败与修正

`tools/validate-face.cjs` 在隐藏的真实 Chrome / NVIDIA RTX 4070 Ti SUPER / D3D11 上执行，未操作桌面鼠标。证据为 `qa/face-browser-report.json`、`qa/face-numeric-report.json` 和当前正面、侧面、热图、牵拉截图；截图只作 QA，不替代工作台。

- 46/46 区在默认及轻量密度都有有效采样；轻量 3,779 个面部点。
- 111 对共享生成位置的权重差异为 0；全部权重有限且在 [0,1]。
- 测试的后脑、头发、颈部和眼表保护点无皮肤区影响。只证明指定探针及当前区域窗，不声称已识别所有毛发/眼表像素。
- 35 个皮肤区逐一满幅测试；身体顶点改动为 0，恢复后位置和法线逐元素差异为 0。
- **失败记录**：最初统一 1.5 mm 拉力使眼周窄带的局部 Jacobian 降至 0.458。修正为按每个区域的实际梯度自动限制位移增益，当前生成点的最小 Jacobian 为 0.82，最大位移约 1.50 mm。此检查不等于无限采样或极端复合表情的全局防穿插保证。
- 真正点击区域、切换原表皮、拖动滑条、恢复、切换镜头、查看锚点、退出、WASD 行走和空格跳跃、轻量密度重建并重新进入检查均通过。浏览器错误和运行时来源模型/图片请求为 0。
- 参数包 SHA256 仍为 `0f801bc60163a968aef8a647b2a9b472279236dc63d5b81d5c320654141333e2`，原有表皮系数未变。

当前验证源码指纹保存在 `qa/face-verified-source.json`，包含生产入口、面部模块、运行时和原参数包 SHA256；两个新增模块合并 gzip 为 6,074 字节（比较用的编码预算，正式服务仍传输 JS 源码）。
