# 步态、闲置与跳跃选型 R2

历史记录：本页的四种跳跃后来被用户否定，已从游戏选择器移除。当前三种实采曲线方案和连续性修正见 [跳跃替换 R3](JUMP_REPLACEMENT_R3.md)。本页的肩部诊断、行走与闲置说明仍适用。

2026-10-01。交互入口 <http://127.0.0.1:8877/?version=R008-behavior-3>。本轮处理肩部内扣、行走力量感、静止后的闲置动作，以及跳跃姿态选型。人物曲面、材质、绑定权重参数保持原包；新增内容为关节函数和少量动作参数。

## 肩部原因与步态调整

原游戏步态直接使用上一人物的动画参考姿势，而当前认可站姿从逆绑定矩阵恢复。两者的胸部、锁骨和上臂参考不同。实际后台浏览器测量：站姿两肩关节间距约 0.386719 m，旧步态六个采样约 0.355–0.358 m，较站立收窄约 8%。这是关节位置的测量，不是对肌肉表面的解剖定量评价。

`SubjectRuntime.mjs` 在混合前为游戏用的临时曲线修正胸部、锁骨与上臂参考；上臂保留沿前后摆臂轴的分量，去掉继承动作中的横向卷曲偏差。原四段曲线仍供独立检查，站立没有重复叠加修正。修正后的六个行走采样肩距约 0.389–0.391 m，仍保留锁骨变化和摆臂。

根据用户对力量感的反馈，行走摆臂分量放大至 1.3 倍，并限制在 ±0.52 rad。`GameAnimator.mjs` 的行走层减少胸部侧摆、加入受限前倾、保持约 16–23 度的动态屈肘，并将手腕大幅偏转向中性对齐。手臂略收近身体，肩关节位置保持展开。该层按行走混合权重进入、离开，起跳时退去；奔跑、站姿和环顾不叠加该层。腿部曲线、步速校准和世界位移不变。

胸部重定向后，原动作中的补偿性抬下巴不再合适，因此走跑时将头部世界朝向部分恢复至中性参考；保留少量原头部运动和转向领先，闲置与跳跃不应用该水平注视层。

## 闲置与跳跃选项

落地、无输入、速度低于 0.08 m/s 且处于待机时开始计时。2.8 秒后平滑混入现有 `look_around`。移动、转向输入或跳跃会清零计时并快速退出；再次静止会从环顾开头重新播放。淡出使用阈值判定，避免权重趋近零却无法重置片段。

`JumpProfiles.mjs` 提供四种少量参数生成的动作：

| 选择 | 姿态特点 |
| --- | --- |
| A 原版对照 | 保留本轮调整前的 R008 游戏跳跃形态供比较，并非播放原热身跳曲线 |
| B 自然前跳 | 先伸展起跳，空中适度屈腿，手臂前摆后回收 |
| C 跑动跨步跳 | 根据起跳时前脚分配前后腿，采用分腿与对侧摆臂 |
| D 收腿上台 | 更明显地收起双腿，为矮墙和台面留出足部空间 |

关节关键姿态采用连续 Hermite 插值，腾空阶段取自实际竖直速度，提前伸腿准备落地取自支撑高度与预计接触时间；落地缓冲随实际接触速度变化。蓄力和落地保留两段腿部 IK。四个选项共用原有物理轨迹，不能通过换姿态提高跳跃高度。空中锁定本次选择，页面保存下一次跳跃风格。

左侧下拉框选择后可按“试跳所选动作”，也可在游戏内按空格；WASD 与 Shift 保持可操作。这三种新候选是本项目编写的参数化姿态，不是已下载的外部动捕片段。

## 参考与证据

参考 [Epic IK Rig Retargeting](https://dev.epicgames.com/documentation/en-us/unreal-engine/ik-rig-animation-retargeting-in-unreal-engine) 的参考姿势校准、[Epic 分层动画](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-layered-animations-in-unreal-engine) 的分骨骼加权原则。实现为本项目的 Three.js 关节修正函数，没有接入 Unreal 运行时。

动作来源检索查看了 [Adobe Mixamo 工作流](https://helpx.adobe.com/creative-cloud/help/animate-characters-mixamo.html)，以及 [CMU Subject 16](https://mocap.cs.cmu.edu/search.php?subjectnumber=16)、[Subject 118](https://mocap.cs.cmu.edu/search.php?subjectnumber=118) 的跳跃分类索引。CMU 页面读取超时，未观看或下载其片段，也未导入 Mixamo 动作；它们不构成本轮候选姿态的动捕来源。

`tools/behavior-preview.cjs` 使用后台真实 Chrome 检查肩距、完整行走周期、手腕稳定与摆臂变化，检查闲置延时、输入中断、重复进入，检查四种动作在同一 0.65 m 矮墙落地、落地踝关节误差小于 3 mm、选择保存和试跳按钮。证据为 `qa/behavior-browser-report.json`，当前实际截图为 `qa/behavior-walk.png`、`qa/behavior-walk-side.png`、`qa/behavior-idle.png` 与 `qa/jump-choice-*.png`。这些截图来自真实运行时，不操作桌面鼠标。

最后一次力量姿态复查的 24 个采样中，左右手前后行程约 0.275 / 0.279 m，手腕相对中性姿态最大偏角约 0.164 rad（9.4 度）。闲置权重在触发后约 0.968，输入后约 0.00269；重新静止时片段从头开始。四种跳跃均在矮墙顶部落地，试跳按钮与刷新后保存选择均通过；浏览器错误为 0。

之前的控制器 12 项检查与完整 WASD 场景浏览器检查见 [角色控制记录](GAMEPLAY.md)；它们不等同于用户对动作风格的主观验收。普通走跑仍没有完整接触脚锁定，参数盒体以外的复杂障碍遍历不在此次实现范围。
