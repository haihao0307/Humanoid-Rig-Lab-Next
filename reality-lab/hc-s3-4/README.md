## 为什么要有两次运行

最小观察基线只读初始化/步入口/原门前/回滚后等边界，详细观察额外在原生批处理后读数。两者运行同一D03与原物理逻辑。它们不是无诊断与诊断的硬件性能比较，最小观察基线也带有边界记录。

对比四组实际TypedArray原始字节，包括位置、速度、old、WASM边与弯曲参数、人体数组及相关锚定状态。base64只转运复制的诊断字节，不转移原生缓冲所有权，不把JSON数字相等冒充精确浮点字节相等。时间开销不用于物理积分步长。

原生失败文字与最终未提交衣服数保持。回滚与步入口的受检字段也比较；发现不一致必须保存为问题，不能仅为了门禁通过而删字段。这里不覆盖全部GPU驱动状态和所有设备。

## 定位粒度

每个采样点保存上下装各自的最大比值、约束边ID、超限数量，区分：接缝焊接/约束构造后的初始状态、WASM初始化、人体插值/腰锚、距离、弯曲、伸缩限制、人体接触、衣物间接触、子步和原保护门。

“首次跨线”指相邻观测边界间首次发现超限，不是WASM函数内部某一个投影点的严格时间先后。若初始构造已经超限，就不能将之后第一个操作称为原因。原保护门用some按求解器顺序短路，因此门前全局最大边和原门首先拒绝的求解器需分开记录。

通过相同panels/triangles/焊接map顺序把实际s.edges映回原裁片ID、局部顶点、UV、焊接粒子及接缝成员。原模板sourceRest、分级targetRest、audit的rest及WASM实际packed rest独立保存，不混用几种参考长度。

## 成本和限制

逐阶段扫描全部边、保存多个边界数组会显著增加诊断成本。它用于一次有界离线复现，不逐帧装入生产，也不承诺实时帧率。原人体准备与材质初始化很重；本任务不借减画质、动作缓存或固定LOD换速度。

只覆盖固定D03、该源构建和软件Chromium回退路线，不能推导所有服装或真实设备均相同。数值状态一致支持本次观察没有改变受检求解结果，不构成全程序形式化证明。

最终以diagnosis.json、BUILD_MANIFEST、DELIVERY和同版本浏览器报告为准。README存在不代表试验已成功。缺少数据、断链、未能取得原失败或观察者影响数值时，应停止发布结论，保留失败证据。
