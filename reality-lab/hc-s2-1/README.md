# REALITY-HC-S2.1 · 人物与服装公共核心收束

S1 已证明人物/鞋履可以在不写回原台的情况下读取单位、坐标、相机与数字几何；S2 已证明裁片净样、缝份、裁切线与有向配缝可以在固定源上独立核验。本阶段不增加第四套孤立检查器，而是把两套既有结果放入一个公共协议、一个入口和一个缺陷回传格式。

范围仍严格限制为人物与服装。当前实际适配对象为 R07 人物、R12 鞋履和 S2 短裤裁片；布料/皮革与成衣只登记下一阶段，不显示假数据。建筑、飞机、地形、动物、植被和展示世界不接入。

## 交付形态

- `protocol.js`：共同状态、来源、对象、测量、缺陷和汇总协议。状态固定为 `PASS / FAIL / WARNING / UNKNOWN / NOT_APPLICABLE`，不再把警告与未知合并。
- `measurement-dictionary.json`：语义测量字典。明确区分可见包围范围、人体身高、鞋楦长度、裁片尺寸和未来布料厚度/纱线间距。
- `adapters.js`：同一只读接口适配固定 S1 和 S2。S1 人物/鞋履按需加载并执行新观察；S2 使用受保护固定快照。没有 `write` 方法。
- `app.js`：统一入口、实际原生工作台、语义测量、所有检查、缺陷派单和定义字典。
- `reality-object.schema.json`：构建生成的公共结构协议；关系、单位和无修复权限等额外规则由 `protocol.js` 执行。

统一入口不会复制或替代人物、鞋履与裁缝的生产职责。源工作台负责修复，Reality Foundation 负责观察、记录、派单和复验。所有派单强制 `repairAuthorized=false`、`verificationRequired=true`；本系统不允许自动改人物、鞋、纸样、材质、灯光或物理。

## 当前语义边界

人物的 X/Y/Z 可见包围范围仍是运行计算，不是肩宽、人体身高或胸厚。人体身高只有在头顶语义点、足底支撑面、人物比例版本和测量方法都明确时才可填写。

鞋履的 X/Y/Z 可见包围范围受成双、拆件、对比和显示状态影响，不是脚长、鞋楦长度或鞋码。鞋楦长度需要楦体身份、版本和制造测量方法。

裁片的九片、19条有向接缝、净样/材料顶点和三角形、缩减顶点、零偏移裁片及接缝残差可以进入共同协议。腰线、侧缝和内缝等成衣级语义长度尚未聚合，保留 UNKNOWN，不从包围框推测。

布料字典预先登记厚度、经纬纱间距，但 S2.1 没有读取任何布料值。Tex/Denier 是线密度，不能直接当几何直径；贴图倍率也不能冒充毫米尺度。

## 验证路线

公共仓库的测试验证协议、S1 人物、S1 鞋履、S2 无密钥锁定、两个登记对象和统一报告/缺陷导出。S2 私有裁片的完整共同适配由 Human-Clothing-Workbench 使用其现有私人访问文件，直接打开固定公网入口重新测试；密钥不进入公共证据。

完成门槛：

- 纯协议、测量字典、状态分离和无修复权限测试通过。
- 人物与鞋履形成共同对象，原受检数据保持不变。
- 裁片形成共同对象，九片/19缝及原警告数值不漂移。
- 公共网页字节固定，实际 HTTPS 浏览器通过。
- 缺陷导出包含来源提交、责任工作台、开放状态和复验要求。
- 原 S1、S2、人物、鞋、纸样、材质、灯光和物理文件零修改。
