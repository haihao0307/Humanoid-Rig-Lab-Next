# RF01 S3.6 · 渐进体型适配事务

日期2026-10-21。接续S3.5，只把原WASM适配循环做成来源/世代明确、能完成也能恢复的候选。不是材质迭代，不修碰撞，不启动RF02—RF07。

## 为什么需要这一步

S3.5的组合试验能完成48步，但它直接采用完整目标参考长度；同源GPU路径的原意是随fitFraction渐变。上一轮也没有证明取消时人体目标、参考长度和衣服状态能够作为一组恢复。因此不能把那两个实验赋值直接作为生产补丁。

本模块按min(step/32,1)从sourceRest到targetRest更新JS边描述与WASM数组，同时将actorPrevious推进到上一次已完成体型。每个物理步仍用原1/60时间步、原迭代、原WASM、原接触和原>1.45门；不增加门限或隐藏失败。48步全通过才提交一个本地运行revision。这个revision不是全项目或人物proportion_revision。

## 事务状态与恢复

runFittingTransaction先验证源commit、人物来源/目标身份token、调用世代和本地运行revision，再锁定该world。输入目标复制后使用，外部异步改值不会偷偷替换当前目标。同一个world不能并行执行两个适配。

事务保存声明的数组/标量：服装位置、速度、old、质量权重、输出/法线、接触缓存、JS/WASM边参考、弯曲缓存、人体起终点与位置、腰部锚点、BVH数据、时钟和版本等。原生单步失败回滚之后，新事务还恢复到整次48步过程的入口；不是留下前几个已经试算的步。

snapshotFittingState.differences逐字节核对每个声明数组，属性还原也包括原来不存在的属性。测试另用独立代码计算关键数组SHA256及边参考/帧/时间/版本，避免只根据事务自己的passed字段自证。

安全事件计数与原metrics.rollbacks作为单调诊断保留，不随数值状态被抹掉。范围不包含GPU、浏览器进程、WASM内隐诊断计数以及没有列入快照的可重算scratch（例如groupNormals）；不宣称全内存位元级恢复。参考源结构/纸样/身份不由此函数修改。若WASM内存被替换或扩大，拒绝以旧视图假恢复。

## 取消边界

候选worker接收带requestId与generation的cancel-fit，仅允许当前请求取消。每步末真正让出一个任务，处理匹配消息后在边界恢复；过期取消不会影响当前工作。取消延迟包含一个正在执行的同步物理步，不承诺瞬时打断。

Worker.terminate不会给内部代码完成恢复的机会，所以“强制终止进程”不等于本接口的协作取消。本轮没有修改生产UI，也没有宣称关闭浏览器仍能保存内存中的未提交事务。相关一手参考：

- https://developer.mozilla.org/en-US/docs/Web/API/AbortSignal/throwIfAborted
- https://developer.mozilla.org/en-US/docs/Web/API/Worker/terminate

## 当前未解决项与成本

S3.5的身体/衣物及上下装负距离采样仍作为历史失败保留，本轮未重新测完整运动接触，也未修ReducedCloth。初始化通过不授予无穿插、实物标定、制造、全部衣型或生产认证。
