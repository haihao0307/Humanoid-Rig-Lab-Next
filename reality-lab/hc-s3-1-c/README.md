## 不能混淆的厚度

1. thicknessScale是无量纲控制倍率。
2. 主片配方目标=产品主片名义毫米厚度×倍率；不同附属裁片可能有不同厚度。
3. 生成part.t是每片数字壳的参数，影响既有几何和物理。
4. 当前内外壳面配对距离由原变形公式、当前节点场和已呈现矩阵计算；它可受缝口压缩等影响，是有限采样，不能冒充每个位置的全局极值。
5. 实物皮料厚度需要具体试样、测厚压力与方法，本轮仍UNKNOWN。

实物面密度与Tex同样不由数字线径或求解器密度假设反推。请求针距、已生成SeamPath.pitch、变形后孔间空间距离也不是同一概念。

## 只读接口与保护

源worldShellMeasurements会调用root.updateMatrixWorld(true)，因此新接口不调用它，也不调用recipe、audit、frameAudit、getError、pose flush、render或solver step。使用已审阅的纯evaluateBoundVertex函数读取现有节点场和缓存矩阵；脏矩阵、尚未应用的姿势、待处理请求或缓存版本不匹配时等待稳定帧，而不是自行刷新源状态。

普通读取每片最多16对固定索引采样；深度校验额外扫描可用CPU几何和姿势数组。两者使用相同表面采样点。完整采样前后序列化读集比较一致后才返回，再把保护摘要压缩为FNV诊断指纹，避免导入清单携带重复shader文本。它不是数字签名或全部驱动状态证明。GPU缓存读回、所有表面点和Worker内部内存未被新观察器完整检查。

返回小型深层冻结原生清单，包含产品/材料身份、源commit/hash、捕获时间、root实例、源revision、姿势/缓存版本、求解步、每片厚度、有限采样和明确缺失。只观察既有物理，不新增或替换物理。

## 共用协议与运行方式

leather-bridge.js继续使用S2.1 object/bundle@0.2并调用既有针织、牛仔桥接。旧协议未登记秒单位，求解时间步保留原单位s于扩展并给出警告，不写成无量纲。当前六款原成品使用分别具名的对象ID，不与S3旧fabric-leather-r17快照混同。

同一入口按需解压并验证所选原生HTML摘要后启动，任意时刻只有一个活动原生iframe。gzip只是无损字节封装，解压后必须恢复相同原程序；不是新模型、降质或动作缓存。需要支持DecompressionStream和Web Crypto的浏览器；不支持时明确报错，不用假样片顶替。

取消加载、关闭、切换、导入有世代保护。导入文件始终imported_unverified，不成为本次实时证据；格式/版本/量纲不合规时原子拒绝。切到原皮革试样物理或旧基线模式时，本轮产品导出器明确不支持，不伪造产品实时结果。

## 验收设计

源码门检查唯一插入段可逆、原HTML摘要、旧协议/旧适配器身份、语法和路径范围。合成协议夹具明确标记synthetic，不冒充真实材料。

浏览器须真实启动原R17，操作厚度倍率、针距与产品选择，读取原物理解算后的姿势，检查普通/深度读取前后画布像素和步数。独立原版与候选在同缓冲尺寸下比较完整PNG，不通过改变分辨率、灯光、几何或容差求通过。另测文件导出/导入、缺失和unsupported单位、取消加载、毛衣和牛仔回归、单引擎与窄屏规范布局。

独立file与固定HTTPS分别验证，重复套件不累计成独立能力数。原native数据、工件摘要、失败和实际截图保留。软件Chromium不等于消费级GPU或实体手机认证；本轮不能承诺60FPS、制造合格或全显示网格无穿模。

## 成本与下一步

原皮革材质预生成、物理和绘制成本都保留；无损压缩减少传输体积，但解压需要内存和CPU，完整性扫描也有成本。按需启动与手动深度检查不能被描述为原物理已经提速。

皮革成品、毛衣、牛仔接通后，下一阶段应整理三类接口的统一安装包、兼容性与版本确认，再进入源工作台受控安装与成衣材料轴/人物比例关联。当前没有原生产安装、实物标定、完整试样物理页适配或成衣试穿。

范围仍是人物、服装、裁片、布料/皮革、鞋；建筑、飞机、地形、动物、植被和完整世界不接入。保持Draft，不合并、不强推、不改写历史。
