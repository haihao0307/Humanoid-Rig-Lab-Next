# KAOPU 世界基准 · 人物与服装 S1

本次授权严格限定人物、成衣、裁缝裁片、布料、鞋履。没有建筑、飞机、地形、动物、植被和展示世界接入；不改其他工作者区域。

## 本阶段的形态

独立版本化公共核心 `core.js` + 已知原台的只读观察器 `adapters.js` + 可交互几何校准/声明核验网页。暂存于人物仓库的独立目录，而非向所有工作台散落复制规则。核心无 Three.js 依赖、无服务器和全局状态中心，可在下一阶段单独打包迁移；本次没有声称已创建一个新仓库或全平台生产依赖。

原生工作台只有用户点击时才按固定公开提交读取。SHA-256 必须匹配才载入独立 iframe。整个原 HTML 不改写，不注入脚本、不 patch 原 API。观察器仅读取当前公开的原生数据；没有设置相机、缩放模型、改变材质、重绑骨架、触发物理或保存原档案的接口。关闭 iframe 退出实验。

## 实际实现

- `core.js`：m/cm/mm/in/ft 换算；量纲拒绝；正交轴转换；投影像素足迹；范围、单位、版本、尺寸、相机、颜色声明及证据检查。未知明确标记，不猜单位，不制造置信度。
- `adapters.js`：R07 人物与 R12 鞋履的同步只读观测；CPU 顶点乘已有世界矩阵得到可见几何包围范围；采集真实相机和 drawing buffer；逐字节保护读取前后的 position/normal/csRest/index，加上世界矩阵、相机和指定设置。
- `catalog.json`：五类对象的固定来源、接入状态和下一步。人物与鞋履有实时观察器；成衣、裁片和布料只有来源登记，不能视为已接入。
- `lab.html` + `lab.js`：真实 WebGL 1 米立方体/坐标轴/标尺、可操作视角和像素足迹计算器、原版按需显示、读数、错误单位测试、本地草稿、JSON 导入/导出。
- 固定 R12 设计配方支持导入，保留毫米；不自动把倍率当尺寸，不把设计外形当脚长或鞋码。
- `reality-observation.schema.json` 是构建出的结构协议。`core.js` 额外负责关系和证据语义；单独通过 JSON Schema 不代表全部检查通过。

`preview.html` 为唯一生成网页，不能手工修改。`BUILD_MANIFEST.json` 保存当前源码提交与源文件/网页摘要。浏览器证据与最终状态以 `DELIVERY.json`、`TASK_STATE.json`、`qa/public/BROWSER_REPORT.json` 为准。构建期 `publicVerified=false` 不会被伪改成成功。

## 重要纠正

1. 坐标系基准不是世界里每个对象的真实尺寸，二者必须区分。
2. 鞋台以毫米生成裁片，再用 0.001 进入米制场景；不能对已转为米的场景再除一次 1000。
3. 原始 `length`/`width` 设计参数是倍率，不能仅凭字段名字写成毫米。
4. 可见包围范围不等于身高、腰围、鞋长或鞋码；成双、拆件、选部件状态会改变范围。
5. 读取 CPU 位置与世界矩阵并不等于最终顶点着色器后的像素轮廓。此缺口保留，不伪称精确最终体表测量。
6. 相机距离本身不足以复现实验；记录垂直视场、zoom、aspect、世界矩阵、投影矩阵、near/far、实际画布像素。只读，不强改原生镜头。
7. Three.js 的 ACESFilmic tone mapping 不是完整 ACES/OCIO 标定。S1 记录原设置，不更换已认可的照明。
8. 不给缺证据的测量填一个看似精确的 0.82。置信度可为 null；实物测量必须补样本、测量方法与单位明确的不确定度。
9. PASS 只表示某条声明或读数关系通过。物性、审美、制造、用户批准及生产就绪不会由本系统自动授予。

## 性能和隐私

核心校验/标尺自包含，不启动时下载所有模型。原生人物和鞋台仍保留自己的网络、编译及图形开销；R12 原页约 13.7 MB。本次没有降低它们的质量或重新做加载优化。

原生读取是用户显式触发的一次性同步检查，不逐帧轮询顶点；保护快照有 96 MiB 上限。读取时间、保护数据字节数写入报告，仍需用户设备实测。

本页 JSON 上限 1 MiB，不接收照片或完整顶点档案，不向服务器上传数据。草稿使用独立键 `kaopu:reality-hc-s1:draft`。私有裁片/布料源码、访问密钥没有复制或公开。已公开的固定源运行页面仅按需读取。
