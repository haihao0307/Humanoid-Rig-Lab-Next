## 时长与四组条件

从真正加载的actor.clips.walk读取duration/frames/continuous；原native-motion在0.65秒进行起步过渡。每组计划时长为0.65秒加两个实际循环，按1/60秒向上取整；未知时长或超过600步拒绝，不随结果改短。

同一个CI作业内顺序运行：原版静止→候选静止→候选走路→原版走路。静止是人体保持不动，衣物仍受原重力和动力学，不称为静态平衡。四个新浏览器上下文独立初始化，初始状态必须精确相同。不是并行跑四个负载再比较耗时。

原生失败即停止该序列、记录尝试步及回滚后的原状态。执行/记录验证通过不等于物理成功，更不等于所有候选完成计划。每组的前3个初始化边界和12个物理步，与S3.7原版或S3.8候选的15个记录，受检状态SHA256、身体与上下装测量逐项相等，否则不能继承过去结论。

在原projectFine前后读取原位置数组，统计改动节点数、RMS/最大修正和节点191修正。用独立复制数组逐项核对fine阶段是否修改coarse delta/velocity。输出只记录数值，不把细修正写回粗状态、不新增残差项、不硬编码目标节点修复。

## 成本统计

使用同一Worker的performance.now单调时钟，原生已有pose/reference/dynamics/contact/reconstruction、lower fine/coarse/refit指标原样读取。完整ContactProbe和SHA256在world.step之后执行，不计入步骤时间。fine观察器自身的复制/比较时间另列；调整步骤值=步骤外部计时-该观察器计时，不隐藏原始外部计时。

比较只用两个条件共同完成的步数，排除前12步；分别报告中位数、95分位、最大值和样本数量。中位数定义为排序后floor((n-1)*0.5)位置，95分位为nearest-rank。诊断探针耗时单列。单次顺序实验存在顺序、缓存、调度和软件渲染环境影响，不等于消费级硬件独立重复基准，不直接换算成用户帧率。

一手计时依据：MDN performance.now https://developer.mozilla.org/en-US/docs/Web/API/Performance/now 与 High precision timing https://developer.mozilla.org/en-US/docs/Web/API/Performance_API/High_precision_timing 。运行库继续固定Playwright1.56.0；不因此升级生产依赖。
