# 动物基本数据与米制展示

仓库负责接收、保存、校验和展示数值，动物模块负责形体、年龄、生长和生命活动。平台不根据外观自动推断体重或物种。

## kaopu/basic@1

```json
{
  "schema": "kaopu/basic@1",
  "units": {"length": "m", "mass": "kg"},
  "measure": "reference-pose-maximum-span",
  "referenceSpanM": 1,
  "massKg": 8,
  "sourceSpan": 0.9764193296432495,
  "metersPerUnit": 1.0241501470125198,
  "basis": "planning-estimate",
  "stage": "成年参考个体（规划）"
}
```

换算使用完整数值 `referenceSpanM / sourceSpan`，验证器核对相对误差。`calibration` 可携带原模块 SHA、参数和默认姿态几何尺寸，`note` 可保存来源说明。新物种作者提交数值用 `user-declared`；不得把声明或规划值标作测量认证。

**固定换算**：默认姿态测一次源单位跨度，建立米/源单位。之后改变胖瘦、模型尺寸或动作，不重新按包围盒归一化。因此形体参数变大时，排练和导出的尺寸也会变大。体重由生产模块或用户独立声明，展示倍率不会改变体重；平台没有重量、生长或动力学估算模型。

工作台“基本数据”可修改基准跨度、个体体重，并测量当前形态 X/Y/Z 包围尺寸。新导入动物必须带有效基本数据，或在预览后补填这两个正数；缺失、非有限数、负值或尺度不一致会拒绝加入。旧导入对象可在工作台补齐后再移交。

## 保存与移交

基本数据独立于生成器参数保存，不作为原乐器的额外控制参数。

- 参数配方和乐谱：顶层 `basicData`。
- 动物包：`animal.basicData` 与 `score.basicData`。
- 烘焙对象：`source.basicData`；网格继续用源单位，接收网站乘 `metersPerUnit`。
- 单动物 HTML：运行器上下文与 `AnimalRuntime.describe().basicData`。
- 标准 GLB 输出：顶点真正转换到米；元数据保留基本数据，导回时换算重置为 1 米/源单位。
- 完整排练谱 / 独立 HTML：`units: "meters"`，资源保留基本数据，实例 `scale` 只是额外展示倍率。

目录 GLB 展示的内部归一化只用于相机呈现；源单位网格快照和活动绑定会移除这层归一化，防止目录往返改变真实尺寸。

旧排练谱保留 `display-units`（每只动物跨度 2），不会悄悄把旧坐标当成米。点击尺度按钮可显式切换，只有所有参演对象具备数据才允许切换到米制。旧内置烘焙可在源 ID 与原版本 SHA 均一致时补用工厂基准；无法确定尺度的旧未知对象，先导入目录补齐数据。

关系距离使用当前排练单位。接近/跟随/避让仍是人工编排，没有生态或碰撞物理推断。功能验收不代表生物科学准确性或生产就绪。
